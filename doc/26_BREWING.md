# 醸造・発酵システム設計 - Stella Garden

> **位置づけ**
>
> 本ドキュメントは、Stella Garden に**発酵・醸造を第3の生産軸**として追加するための正式な設計書である。
> `doc/22_REPUTATION_SYSTEM.md` のアンロックツリーを拡張し、既存の「食糧軸（じゃがいも・大豆）」「繊維軸（亜麻 → 糸 → 布）」に並ぶ
> 「発酵軸（塩 → 麹 → 味噌・醤油・酒・酢）」を定義する。
>
> **背景となる課題**
>
> 現状のアンロックツリー（`22_REPUTATION_SYSTEM.md`）はほぼ一本道で全6 Tier であり、数時間で全て開放できてしまう。
> ボリュームを「長さ（閾値引き上げ）」だけで足すと作業ゲー化するため、本書では
> **「新しい生産軸を足して、より上位の合流点（高級品）を作る」**方向で拡張する。
> 発酵軸は既存の大豆を再利用しつつ、塩・麦という新要素でツリーを横に広げ、
> 熟成の待ち時間がチル原則と噛み合うのが狙いである。
>
> **関連ドキュメントとの関係**
>
> - `22_REPUTATION_SYSTEM.md` — アンロック Tier・スコア設計。本書の Tier はこれを拡張する
> - `05_CULTIVATION.md` — 作物の栽培・連作・種子循環。麦の栽培仕様は本書 §2 と整合させる
> - `25_MISSION_SYSTEM.md` — ミッション進行。本書 §8 で M-18 以降を追加
> - `16_IRRIGATION.md` — 水タイルと灌漑。塩田の設置条件で参照
> - `18_FUEL.md` — 木材・木炭。蒸し器の燃料で参照
> - `15_RE_SYNOPSIS.md` — 格付けの大枠と入植船ゴール

## 1. 設計方針

### 1.1 基本コンセプト

発酵軸の中心にあるのは、以下の構造である。

1. **既存の大豆を再利用する** — 味噌・醤油の主原料は大豆。新作物だけに頼らず、既に育てている大豆ラインに新しい価値を足す
2. **塩と麦という2つの新要素で門を開く** — 塩は発酵軸全体の門番（味噌・醤油・酒・酢・将来の漬物等に必須）、麦は麹の基質
3. **熟成という新しい時間メカニクスを導入する** — 既存の加工機械（ボタン押下中に処理）とは異なり、「仕込んで放置 → 数日〜数十日後に完成」という受動・並列の工程。桶が静かに発酵していく様子がチルなエンドゲームの絵になる
4. **より上位の合流点を作る** — 味噌（大豆＋塩＋麹の三軸合流）、醤油（さらに麦を加えた四軸合流・最高級品）。袋詰め大豆の次の集大成として機能する

### 1.2 基本原則

- スキルツリーは採用しない（`15_RE_SYNOPSIS.md` のオープンクラフト方式に準拠）。制約はリソースと設備の有無のみ
- 格付け・アンロックは累積出荷量で進行し、一度上がったら下がらない（チル原則）
- 発酵・熟成は**急かさない**。仕込んで放置でよく、早回し UI（`25_MISSION_SYSTEM.md`）で待ち時間を調整できる
- 製塩は当面**塩田（天日干し）のみ**とし、燃料を使う製塩鍋は将来検討（§9）に回す

## 2. 新規作物・資源

### 2.1 麦（むぎ）

麹の基質となる新作物。既存の乾田作物（大豆・亜麻）と同じ操作系で栽培でき、実装コストを抑える。

| 項目 | 仕様 |
|---|---|
| フィールド | 乾田（既存と同じ。水田は不要） |
| 成長日数 | 4日（仮。大豆と同等の回転） |
| 散水 | 必要（全成長期間。水切れ3日で枯死、`05` の散水メカニクスに準拠） |
| 連作耐性 | 普通（fatigue 4 で枯死、`05_CULTIVATION.md` §5.6 に準拠） |
| 収穫 | 鎌で収穫 → **麦（粒）＋ 麦わら（茎）** |
| 麦わらの用途 | 堆肥原料 / 草木灰原料（茎×5 → 草木灰×1。亜麻と違い焼却可） |
| 種子循環 | 収穫した麦の一部を種に回す（`05` の種子循環方式） |

> **将来連結**: 麦は将来の「製粉・焼成軸」（小麦粉 → パン）の基質にもなる。本書では麹基質としてのみ扱うが、製粉軸を追加する際に共用できる。
> なお米（水田）は本軸では扱わず、後続の大型アップデートに回す（§9）。麹の基質はまず麦で立ち上げる。

### 2.2 塩（しお）

発酵軸全体の門番となる新資源。**海/川の区別は設けず、全ての水タイルに隣接する陸タイルに塩田を設置できる**。

> **海/川を区別しない理由**: 現状マップは自動生成で、見た目に海か川か判別できない場所がある。
> 「海岸タイル限定」とすると自動生成との整合が難しいため、本書では**全水タイル隣接で塩田可**と簡略化する。
> これは `22_REPUTATION_SYSTEM.md` §6.2 の「砂を海岸タイル限定資源にする」将来案とは別方針であり、
> 本軸では立地の地理的制約よりチルな手軽さを優先する。

塩田の仕様は §3.1 を参照。

## 3. 新規施設

施設は機能ごとに分けるが、**発酵タイマー（仕込む → 日数カウント → 完成）は共通コンポーネントとして実装**し、麹室・発酵桶で再利用する。これにより施設は別エンティティでもコードは重複しない。

### 3.1 塩田

| 項目 | 仕様 |
|---|---|
| 占有サイズ | **2×2**（堆肥場と統一。現実の塩田も広大なため見た目にも合う） |
| 設置条件 | **水タイルに隣接する陸タイル**（海/川の区別なし） |
| 動力/燃料 | 不要 |
| 動作 | 受動。設置後、一定のゲーム内日数ごとに塩が貯まる（仮: 2日で塩×n） |
| 回収 | プレイヤーがインタラクトして貯まった塩を取り出す |
| メカニクス | 「仕込んで放置」型。塩田が並ぶ海辺の景観がチル要素になる |

製塩鍋（海水を鍋に入れて煮詰める速いルート）は、海水を汲むパスが未実装のため**当面なし**（§9 将来検討）。

### 3.2 焚き火の拡張（蒸し・炒り）

蒸し器は新規導入せず、**既存の焚き火を拡張**して大豆・麦を加熱加工する。`20_FORGE.md` の簡略化方針（一度加熱した素材は時間経過で戻らない）を踏襲する。

| 項目 | 仕様 |
|---|---|
| スロット構成 | **燃料スロット（既存）＋ 素材スロット（新規）** の2系統 |
| 動作 | 焚き火が燃料を消費しつつ、**1日経過するごとに素材スロットの素材を n 個ずつ加熱加工**する |
| レシピ | 大豆 → 蒸し大豆 ／ 麦 → 蒸麦 ／ 麦 → 炒り麦（醤油用） |
| 簡略化 | 一度蒸した/炒った素材は、その後時間が経過しても**蒸されたまま**（劣化・常温戻りなし）。`20_FORGE.md` の赤熱隕鉄と同じ扱い |
| 燃料 | 木材（高温は不要なので木炭は要らない、`18_FUEL.md`） |

> 既存の焚き火は「木材/茎 → 草木灰」を担う（`05_CULTIVATION.md`）。本拡張で素材スロットが加わり、草木灰生成と蒸し・炒りを同じ焚き火が日次で処理する形になる。

### 3.3 麹室（こうじむろ）

蒸麦に麹（前回の仕込みから種として取り分けた一部）を加えて麹菌を繁殖させる、**好気性・短期（2〜3日）**の発酵設備。中間素材「麹」を量産し、多数の発酵桶に供給する。

| 項目 | 仕様 |
|---|---|
| 占有サイズ | **2×2** |
| 動力/燃料 | 不要 |
| 発酵の質 | 好気性（麹菌は酸素を要する）。棚に薄く広げるイメージ |
| 時間 | 短い（2〜3日。仮） |
| レシピ | **蒸麦（焚き火で加工）＋ 麹（種として一部）→ 麹** |
| 種（循環） | **種麹は独立アイテムを設けず、麹を種麹兼用とする**（種イモ方式）。初期は麹を持ち込み、完成した麹の一部を次の仕込みの種に取り分けて循環。在庫が尽きると次が仕込めない |
| メカニクス | 共通発酵タイマー（仕込む → 日数カウント → 完成）。回転が速く、生産設備として機能 |

> **種麹を独立アイテムにしない理由（簡略化）**: 現実には種麹（麹菌の胞子を集めた粉）と麹（穀物に菌が繁殖した状態）は別物で、麹を種麹に戻すには胞子を作らせて採取する追加工程が要る。だが本書はもともと「種イモ方式で循環」する設計（`05_CULTIVATION.md` の種子循環・大豆の豆＝種兼用と同思想）であり、麹を種麹兼用にすれば追加工程ゼロで同じ操作系に乗る。見た目（菌が付いた穀物）としても通るため、**種麹は専用アイテム・専用スプライトを設けず、麹で兼ねる**（`09_RESOURCE.md` 194 麹も種麹兼用として記載）。

### 3.4 発酵桶（はっこうおけ）

最終製品（味噌・醤油・酒・酢）を作る、**長期の熟成設備**。**見た目は全て同一（樽）の単一エンティティ**とし、中で何を熟成させているかは**カーソルホバーで現れるプロパティ表示**で判別する。内部は共通の発酵タイマー機構で、**複数を同時並列で寝かせられる**。

| 項目 | 仕様 |
|---|---|
| 占有サイズ | 1×1（仮。塩田・麹室の 2×2 とは別に小型でよい） |
| 見た目 | **全品目で同一の樽スプライト**。中身はホバー時のプロパティで表示（品目・熟成残り日数など） |
| 動力/燃料 | 不要 |
| 発酵の質 | 品目により嫌気（味噌・醤油もろみ・麦もろみ）／好気（酢）。実装上は同じ樽でレシピ違いとして吸収 |
| 時間 | 品目ごとに数日〜十数日で初出荷可能（§4.1）。品質目的でさらに長期熟成も可 |
| 樽熟成（兼用） | **蒸留した麦焼酎を樽に戻して寝かせる「樽熟成」にも発酵桶を兼用**する（ウィスキー/長期熟成焼酎に相当）。寝かせた日数で品質・単価が上がる（§4.1・§6.2） |
| メカニクス | 共通発酵タイマー。並列で多数稼働させ、静かに熟成する樽が並ぶ様子がチルなエンドゲームの絵になる |

#### 熟成カウンタとビット幅

- 熟成日数カウンタは **現状の 4bit（最大15日）から 6bit（最大63日）に拡張**する
- **初出荷は数日〜十数日で達成できる**設定にし、最初の出荷で待たせすぎない（チル原則）
- その上で、**品質目的の長期熟成（最大63日）**を可能にする。**現スコープでは麦焼酎の樽熟成**がこの主な使い道（寝かせるほど高品質・高単価。§4.1・§6.2）。将来の米アップデートでは精米グレードが「素材側の品質」として加わり、樽熟成（熟成側）と二軸になる

レシピは §4 を参照。

### 3.5 蒸留器（じょうりゅうき）

麦もろみ（麦を発酵させた仕込み）を蒸留して麦焼酎にする新エンティティ。前近代でも存在する単式蒸留器（ポットスチル）に相当し、世界観に馴染む。

| 項目 | 仕様 |
|---|---|
| 占有サイズ | 1×1 または 2×2（仮） |
| 燃料 | 要（`18_FUEL.md`。加熱して気化・凝縮させる） |
| スロット構成 | **燃料スロット＋素材スロット（麦もろみ）**（焚き火 §3.2 と同じ構成） |
| 処理 | **焚き火と同じ日次バッチ（DailyProcessing）型**。処理ボタン押下ではなく、**1日経過するごとに麦もろみを n 個消費して麦焼酎を 1 個産出**する（蒸留で量が凝縮するため n:1） |
| レシピ | **麦もろみ ×n → 麦焼酎（新酒）×1** |
| 後工程 | 蒸留した麦焼酎は、発酵桶（§3.4）に戻して**樽熟成**すると品質・単価が上がる |

> 蒸留器は焚き火（§3.2）と同じ「燃料スロット＋素材スロット＋日次処理」ロジックを共有する別エンティティとして実装する。
> 蒸留が1工程加わることで酒チェーンが伸び、高単価が「より多くの工程＝より高い価値」として正当化される（§6 設計原則）。

## 4. 加工チェーン（確定版）

```
海水（水タイル）─[塩田・天日・受動]→ 塩

麦 ─[焚き火]→ 蒸麦 ─[麹室・好気・2〜3日]→ 麹     （麹の一部を種として取り分けて循環＝種麹兼用）
大豆 ─[焚き火]→ 蒸し大豆
麦 ─[焚き火]→ 炒り麦（醤油用）

味噌 ＝ 蒸し大豆 ＋ 塩 ＋ 麹 ─[発酵桶・嫌気熟成]→ 味噌         ★三軸合流
醤油 ＝ 蒸し大豆 ＋ 炒り麦 ＋ 塩 ＋ 麹 ─[発酵桶・嫌気熟成]→ 醤油もろみ ─[搾油機で圧搾]→ 醤油 ＋ 醤油粕(肥料)   ★四軸合流・現スコープの価格ピナクル（最長チェーン）

【酒・酢ライン】
麦もろみ ＝ 麦麹 ＋ 蒸麦 ─[発酵桶・嫌気発酵]→ 麦もろみ（麦を発酵させた仕込み・酒の手前の中間体）
   ├─[蒸留器・要燃料]→ 麦焼酎（新酒）─[発酵桶で樽熟成]→ 熟成麦焼酎   高単価の嗜好品（醤油の少し下。寝かせるほど高品質）
   └─[発酵桶・好気＝酢酸発酵]→ 酢       （低アルの麦もろみから。空気に触れさせる。日常調味料）
```

> **甘酒を麦スコープから外した理由**: 甘酒は米＋米麹でデンプンを糖化した甘い飲み物で、米の文化。麦における「酒の手前の中間体」は甘酒ではなく**麦もろみ（麦を発酵させた仕込み）**になる。甘酒は米／水田アップデートで米の糖化中間体として復活させる（§9）。
> **「麦もろみ」という名前の理由**: 当初「どぶろく」としていたが、どぶろく（濁酒）は米から作る漉していない日本酒で米を連想させるため不適切。焼酎づくりで蒸留前の発酵中の仕込みは「もろみ（醪）」と呼ぶため、麦の場合は**麦もろみ**が正確。既存の「醤油もろみ」とも命名体系が揃う。
> **麦＋麹の酒＝麦焼酎**: 麹（東アジア式の糖化）で麦を発酵させ蒸留したものは**麦焼酎**にあたる。ウィスキーは麦芽（西洋式の糖化）を使う別系統だが「蒸留した麦の酒」という点では親戚。
> **酢は焼酎ではなく麦もろみから**: 酢（酢酸発酵）は低アルコールの醸造酒から作るのが現実的（米酢は清酒/濁酒から、ワインビネガーはワインから）。高濃度の蒸留酒からは作らないため、酢は麦もろみから分岐させる。

### 4.1 醸造・蒸留レシピと熟成日数（仮）

熟成カウンタは 6bit（最大63日）。下表の「初出荷日数」で最初の出荷が成立する。

| 品目 | 投入 | 設備 | 産出 | 初出荷日数（仮） | 備考 |
|---|---|---|---|---|---|
| 味噌 | 蒸し大豆 ＋ 塩 ＋ 麹 | 発酵桶（嫌気） | 味噌 | 10日 | 三軸合流 |
| 醤油 | 蒸し大豆 ＋ 炒り麦 ＋ 塩 ＋ 麹 | 発酵桶（嫌気）→ 搾油機 | 醤油もろみ → 搾る → 醤油 ＋ 醤油粕 | 12日 | **四軸合流・現スコープの価格ピナクル**。醤油粕は肥料 |
| 麦もろみ | 麦麹 ＋ 蒸麦 | 発酵桶（嫌気） | 麦もろみ（酒の手前の中間体） | 5日 | 焼酎・酢の共通の前段。甘酒の代替 |
| 麦焼酎（新酒） | 麦もろみ ×n | **蒸留器**（要燃料・日次処理） | 麦焼酎 ×1 | 1日（n個消費して1個産出） | 高単価の嗜好品。蒸留でチェーンが伸びる |
| 熟成麦焼酎 | 麦焼酎（新酒） | 発酵桶（樽熟成） | 熟成麦焼酎 | 樽熟成 7日〜（長いほど高品質・高単価） | **醤油の少し下〜迫る高単価**。現スコープの品質最適化要素 |
| 酢 | 麦もろみ | 発酵桶（好気） | 酢 | 5日 | **好気＝酢酸発酵**（空気に触れさせる）。日常調味料 |

> **醤油の搾り＝搾油機を流用**: 醤油もろみの圧搾は油の搾汁と同じ圧力搾汁。専用工程は設けず、搾油機（`17_AUTOMATION.md`）にレシピ（醤油もろみ → 醤油 ＋ 醤油粕）を追加する。
> **醤油粕**は油粕と同様、内部肥料として扱い、初期実装では出荷対象外（`22_REPUTATION_SYSTEM.md` §3.4 に準拠）。
> **酢酸発酵について**: アルコール発酵（酵母・嫌気）と異なり、酢酸発酵は酢酸菌が酸素を使ってアルコールを酸化する**好気性**反応。実装上は同じ樽でレシピ違いとして吸収し、フレーバーとして「酢は空気に触れさせる」と表現する。
> **麦焼酎の樽熟成**: 蒸留した新酒を発酵桶（＝樽）に戻して寝かせる。寝かせた日数で品質・単価が上がる（ウィスキー/長期熟成焼酎に相当）。6bit熟成カウンタの主な使い道。
> **「醤油もろみ」と「麦もろみ」**: どちらも発酵途中の半液体だが別物（醤油用 ＝ 搾って醤油、酒用 ＝ 蒸留して焼酎/酢酸発酵して酢）。名前を分けて区別する。

### 4.2 麦麹で味噌・醤油を作ることの現実的根拠

「米麹でなく麦麹で味噌・醤油を作って大丈夫か」という疑問に対する根拠メモ。**いずれも現実の伝統的・王道の製法であり、米麹でなくても十分に味噌・醤油らしくなる**。

#### 味噌：麦麹味噌（麦味噌）は伝統的分類のひとつ

味噌は麹の種類で大別される。

| 種類 | 麹 | 主な産地 | 特徴 |
|---|---|---|---|
| 米味噌 | 米麹 | 全国（生産量の約8割） | 最も一般的 |
| **麦味噌** | **麦麹（大麦/裸麦）** | 九州・山口・愛媛・北関東など | 田舎味噌とも。やや甘口で香ばしい |
| 豆味噌 | 豆麹（大豆のみ） | 愛知（八丁味噌） | 濃厚・長期熟成 |

本ゲームの味噌レシピ（蒸し大豆 ＋ 塩 ＋ 麦麹）は、そのまま**麦味噌**にあたる。米味噌よりやや甘く香ばしいが、間違いなく味噌。

#### 醤油：麦（小麦）はむしろ必須原料

標準的な濃口醤油は**大豆と小麦をほぼ半々**で使い、麹は「蒸した大豆 ＋ 炒った砕き小麦」を混ぜた上に麹菌を生やして作る（混合麹）。小麦由来の糖が香り・甘み・アルコールを生み、醤油らしい風味の要となる。小麦をほとんど使わない例外は「たまり醤油」（中部地方、大豆主体）。したがって本ゲームの醤油レシピ（蒸し大豆 ＋ 炒り麦 ＋ 塩 ＋ 麦麹）は現実の王道とよく合致する。

#### 米麹は将来の差別化に使える

米／水田アップデートで米麹を導入すれば、**米味噌・米麹醤油**という別バリエーションを追加できる。「麦麹＝香ばしい/甘い、米麹＝まろやか」といった**風味・品質差**を、麹の種類による分岐として将来の差別化要素にできる（§9 将来検討）。

> **実装上の小さな冗長性**: 現実の醤油は「大豆＋小麦を混ぜた上で麹を作る」ため、本ゲームの「麦麹（別工程）＋炒り麦＋蒸し大豆」は麦が二度登場してやや冗長。ただし麹を全製品で麦麹に統一する簡略化として自然なので、このままとする。

## 6. アンロック Tier（doc/22 拡張）

発酵軸は、`22_REPUTATION_SYSTEM.md` の Tier 2（大豆・生）以降に**分岐**として生やす。既存の繊維軸（油 → 糸 → 布 → 袋詰め大豆）と並行し、味噌・醤油を袋詰め大豆に並ぶ／その先の集大成として置く。

```
Tier 2: 大豆（生）
  ├→ (既存) 油 → 糸 → 布 → 袋詰め大豆            ★集大成1（包装の記号的達成）
  └→ (新規・発酵軸)
        塩 ──→ 麹 ──→ 味噌                        ★三軸合流
                  │       └──→ 醤油                ★四軸合流・現スコープの価格ピナクル（最長チェーン）
                  └──→ 麦もろみ ─[蒸留器]→ 麦焼酎 ─[樽熟成]→ 熟成麦焼酎   高単価の嗜好品（醤油の少し下）
                              └→ 酢               （日常調味料）
```

**設計原則「最深チェーン＝最高単価」**: Factorio ライクでは、最も長く重いチェーンが最も儲かるべきで、そうでないと継続生産のうまみがない。本軸では**四軸合流かつ最長チェーンの醤油を現スコープの価格ピナクル**に置く。酒はそれに次ぐ高単価の嗜好品とする。

> **酒を将来「真のピナクル」にする道筋**: 現実のプレミアム酒（吟醸・大吟醸）が高いのは酒税ではなく**精米歩合**による。米を磨くほど素材（米）を2〜4倍消費し、精米という追加工程も増えるため、「より多くの素材＋より多くの工程＝より高単価」が成立する。この**精米（磨き）グレード**は米／水田アップデートの目玉として導入し、その時点で酒を醤油を超える真のピナクルに引き上げる予定（§9 将来検討）。麦ベースの現スコープでは酒は醤油の少し下にとどめる。

### 6.1 発酵軸の Tier 詳細

| Tier | 品目 | アンロック条件（累積出荷） | 位置づけ |
|---|---|---|---|
| B-塩 | 塩 | 大豆（生）の累積出荷が閾値達成 | 発酵軸の入口。塩田の設置を促す |
| B-麹 | 麹 | 塩の累積出荷が閾値達成 | 麦栽培＋焚き火拡張＋麹室の導入を促す |
| B-味噌 | 味噌 | 麹の累積出荷が閾値達成 | ★三軸合流。発酵桶（熟成）の導入 |
| B-醤油 | 醤油 | 味噌の累積出荷が閾値達成 | ★四軸合流・現スコープのピナクル。炒り麦＋搾油機が加わる |
| B-酒酢 | 麦焼酎・酢 | 麹の累積出荷が閾値達成（味噌と並行アンロック） | 嗜好品の並行ライン。麦もろみ経由で蒸留→麦焼酎（樽熟成で高品質）／酢酸発酵→酢 |

### 6.2 相対スコア（じゃがいも = 1 として、仮の目安）

| 品目 | 相対スコア | 備考 |
|---|---|---|
| 塩 | 4 | 大豆（生）= 3 よりやや上 |
| 麹 | 6 | 大豆油 = 6 と同程度 |
| 麦もろみ | （出荷対象外） | 焼酎・酢の中間体。出荷せず内部消費が基本（任意で安価な飲み物として出荷解禁も可） |
| 酢 | 30 | 麦もろみから作るが**日常調味料ゆえ安い**（現実整合） |
| 味噌 | 40 | 三軸合流。布 = 20 を超える |
| 麦焼酎（新酒） | 65 | 高単価の嗜好品。袋詰め大豆 = 50 を超えるが、醤油の少し下 |
| 熟成麦焼酎 | 〜78（樽熟成日数による） | 寝かせるほど上がるが、現スコープでは醤油 80 を超えない範囲 |
| 醤油 | 80 | **四軸合流・最長チェーン。現スコープの価格ピナクル** |

> **設計メモ（最深チェーン＝最高単価）**: 醤油は本軸で最も工程が長い（大豆＋麦＋塩＋麹＋搾り）ため、現スコープの最高単価に置く。麦焼酎はそれに次ぐ高単価で、樽熟成で醤油に迫るが超えない。
> 現実では醤油は安いコモディティ（安い原料＝脱脂大豆＝油粕的＋大量生産）、プレミアム酒は精米・手間で高い、という逆転構造があるが、本ゲームでは「深いチェーンほど儲かる」というゲーム原則と継続生産の動機を優先する。麦焼酎を醤油超えの真のピナクルにするのは米アップデートの精米グレードで行う（§6.1 補足・§9 参照）。

### 6.3 アンロック閾値の考え方

`22_REPUTATION_SYSTEM.md` §4.3 と同じく「次のアンロックまで何分プレイすればいいか」で設計する。発酵軸の各段階は**30〜45分体感**を目安とし、この軸全体で 5〜8 時間のボリュームを上乗せする。具体数値はプレイテストで調整する。

## 7. 実装メモ

### 7.1 新規イベント（`_boundary/events.ts`）

発酵タイマーとミッション判定のため、以下の追加が見込まれる（具体設計は実装時に確定）。

| イベント | 用途 |
|---|---|
| `fermentation_started` | 麹室・発酵桶に仕込んだ時。ミッション判定・タイマー開始 |
| `fermentation_completed` | 熟成完了時。回収可能になった通知 |

塩・麹・味噌・醤油・酒・酢の出荷は、既存の `item_shipped` で吸収できる。

### 7.2 ボクセルデータ

- **麦**: 連作カウンタの `last_crop`（3bit、0〜7）に麦=5 として収まる（既存枠で対応可、`05` §5.6）
- **発酵施設の熟成カウンタ**: 麹室・発酵桶の経過日数を格納する。**現状の 4bit（最大15日）から 6bit（最大63日）に拡張**する。理由は、初出荷は数日〜十数日で達成しつつ、麦焼酎の樽熟成（最大63日）で品質・単価を伸ばす余地を残すため。作物育成カウンタ（bits 16-18）とは別領域に確保する（64bit に拡張済みのため余裕あり、`21` §8 参照）
- **塩田**: 設置は「水タイル隣接」を実行時判定。貯蔵カウンタ用ビットを持つ

### 7.3 共通発酵タイマー機構

麹室・発酵桶・塩田はいずれも「仕込む/設置 → ゲーム内日数をカウント → 完成/回収可能」という共通構造を持つ（麦焼酎の樽熟成も同じ機構を使う）。
`day_changed` イベント（`engine/GameTime.ts`）に乗せて経過日数を進める、共通の発酵進行ロジックとして実装するのが綺麗。
作物育成（`engine/CropSystem.ts` の `advanceDayAllCrops`）と同じパターンで、施設の熟成も日次で進める。**焚き火（蒸し・炒り）と蒸留器も同じ日次バッチ（DailyProcessing）型**で、1日経過ごとに素材を n 個消費して産物を出す（処理ボタン押下ではない）。

### 7.4 想定モジュール構成（案）

- `engine/` — 発酵進行ロジック（日次タイマー）、レシピ定義、塩田の生産ロジック、焚き火の蒸し・炒り処理、蒸留器の処理（PixiJS 非依存）
- `_registry/entities/` — 塩田・麹室・発酵桶・蒸留器のエンティティ定義、既存の焚き火エンティティの拡張（`doc/13` の Entity Registry パターン）
- `view/` — 各施設の UI（既存の DailyProcessingPanel 等のパターンを踏襲）、塩田/発酵桶/蒸留器の状態スプライト
- スプライトは未作図分を既存プレースホルダーで流用（spritesheet JSON は編集禁止）
