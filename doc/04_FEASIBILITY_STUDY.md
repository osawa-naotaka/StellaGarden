## 目的
実際にゲームが楽しいものになるのか確認したい。そのために、簡易実装でゲームを作成し、テストプレイで楽しさを確認したい。

### 農作物の育成

## 自動化システム設計：水・重力・歯車による原始的メカニズム

### 背景と動機

専門の機械（「耕作機」「脱穀機」など）を用意するだけでは楽しみに欠ける。プレイヤーが少数の汎用的な要素を自分で組み合わせ、発想力により様々な応用ができるようにしたい。Factorioが「ベルトコンベアとインサータ」を原始要素にしたように、Stella Gardenでは**「水・重力・回転力」**を原始要素とする。

惑星開拓で化学肥料が手に入らないのと同様に、電気も潤沢にはない。代わりに水力・重力という自然エネルギーと、歯車・滑車・カムといった古典的な機械要素でプレイヤーが仕組みを組み上げる。木製の歯車、亜麻のロープベルト、水道橋といった素材は、ゲーム内で自給可能なものに限定できる。

---

### 川の追加と灌漑

#### 川の役割（歴史的背景）

世界四大文明がすべて大河の流域で生まれたのは偶然ではない。

- **メソポタミア（チグリス・ユーフラテス川）**: 紀元前6000年頃から灌漑農業。川から運河を掘って農地に水を引くシステム。
- **エジプト（ナイル川）**: 年1回の洪水後にシルト（肥沃な泥）が堆積した土地に種を撒く。

川は単なる水源ではなく、**肥沃な土壌の運搬者**でもある。

#### ゲームへの適用

- **地形生成に川を追加**: 高地（山岳地帯）から低地（海岸）に向かって流れる川をシンプレックスノイズで生成
- **川沿いの土壌は肥沃**: 川に隣接するタイルは初期状態でも土壌品質が高い設定にできる
- **高台の水源問題の解決**: 川の上流が自然な高所水源になる

#### 天水農業と堰による灌漑

主要作物の水の必要性:

| 作物 | 水の必要性 | 備考 |
|------|-----------|------|
| ジャガイモ | 低〜中 | 雨水だけでそれなりに育つ。灌漑は収量向上の任意工程 |
| 大豆 | 低〜中 | 雨水農業で広く栽培されている。開花期に水があると良い程度 |
| 亜麻 | 低（育成中） | 育成中の水やりはさほど重要でない。むしろ収穫後のレッティング（浸漬）工程で大量の水を使う |

川沿いの農地では、**堰（ウィア）＋導水路**の組み合わせで揚水装置なしに灌漑が成立する。

##### 堰（ウィア）の構造

堰は川幅いっぱいに作る低い壁。上流側の水位が上がり「ミルポンド（水車池）」ができる。堰の脇に水門付きの取水口を設け、そこから狭い導水路（ミルレース）に水を引き込む。ミルレースは川本体より幅が狭いため、同じ水量でも流速が速くなる。

```
              川上（上流）
                 │
  ═══════════════╤══════════════  ← 堰（川幅いっぱいの低い壁）
  ～～～～～～～ │ ～～～～～～      堰で水位が上がる（ミルポンド）
               [水門]
                 │
            [導水路（ミルレース）]  ← 狭い水路。流速が速い
                 │
            [水車/農地への散水]
                 │
            [放水路（テイルレース）] → 下流で川に合流
```

ゲームでの簡略化（幅3タイルの川の場合）:

```
  ～ ～ ～     ← 川（上流）
  ═ ═ ■       ← 堰（═）+ 水門（■）
  ～ ～ │
        │
       [導水路] → [水車]
```

水門はON/OFFスイッチの最も基本的な形。手動で開閉（序盤）→ リンク棒やカムで自動開閉（中盤以降）。

乾燥地帯では、畝立てをした土地に用水路から水を少し流し込む**畝間灌漑（furrow irrigation）**で土を湿らせる方法もある。

### 動力源と動力伝達

#### 動力源

| 要素 | 原理 | ゲーム上の特徴 |
|------|------|---------------|
| **水車（下掛け）** | 川の水流で回転 | 川沿い限定。安定。序盤の主力 |
| **トレッドミル（踏み車）** | 人力/動物で回転 | 序盤の補助動力 |

#### 動力伝達要素

| 要素 | 機能 | 備考 |
|------|------|------|
| **シャフト（軸）** | 回転を直線的に伝える | 木製。ラインシャフトとして遠距離に |
| **歯車** | 方向変換・増速/減速 | 木製歯車は歴史的に一般的 |
| **プーリー+ベルト** | 離れた軸間で回転を伝える | 亜麻ロープ/ベルトで実現 |
| **ロープドライブ** | さらに遠距離の動力伝達 | V溝プーリーで滑り防止 |
| **クランク** | 回転⇔往復運動の変換 | 鋤を引く、ポンプを動かす等 |
| **カム** | 回転→任意タイミングの押し出し | ピンシリンダーの基本原理 |

#### 亜麻ロープによる動力伝達の歴史的根拠

18世紀〜19世紀の工場では、水車1台の動力を建物全体に伝達するためにロープドライブが広く使われていた（素材は麻・マニラ麻・綿ロープが主流。亜麻も同系統の繊維であり歴史的に妥当）。

ゲームで既に設計されている「亜麻栽培→紡績→糸」のラインが動力伝達と直接つながる:

```
亜麻栽培 → 収穫 → レッティング → 紡績 → 亜麻ロープ
                                          ├→ 袋（大豆出荷用）  ← 既存設計
                                          ├→ ベルト（動力伝達） ← 新用途
                                          └→ ロープ（滑車・巻き上げ）
```

産業革命期の工場の動力伝達（ラインシャフトシステム）:

```
[水車] → [主軸（ラインシャフト）] ━━━━━━━━━━━━━━━━━→ 工場の端まで
              │          │          │          │
           [プーリー]  [プーリー]  [プーリー]  [プーリー]
              │          │          │          │
           [ベルト]    [ベルト]    [ベルト]    [ベルト]
              │          │          │          │
           [製粉]     [紡績]     [コンベア]  [農具]
```

### 制御・プログラム要素

| 要素 | 機能 | 備考 |
|------|------|------|
| **ピンシリンダー** | 回転1周を「プログラム」として実行 | ピンの配置 = プログラムコード |
| **カムシャフト** | 複数のカムで複数動作を同期 | エンジンのカムシャフトと同原理 |
| **ラチェット** | 一方向にだけ回転を許可 | 逆回転防止。巻き上げ機構に必須 |
| **クラッチ** | 動力の接続/切断 | センサーと組み合わせてON/OFF |
| **トリップハンマー** | カムで持ち上げ→落下の反復 | 鍛冶、精米、亜麻の叩き（スカッチング）に |
| **感圧板** | アイテムの有無を検知 | ホッパーが満杯→水門閉じる等 |
| **成長センサー** | 作物の成長段階を検知 | 収穫タイミングの自動判定 |
| **リンク棒** | センサーの信号を機械的に伝達 | 電気ワイヤーではなく物理的な棒 |

**ピンシリンダー**は9世紀バグダッドのバヌー・ムーサー兄弟が水力オルガンに使用した「機械的にプログラムを再生する」最古の仕組みであり、1804年のジャカード織機（コンピュータの祖先）につながる。プレイヤーがピンを差し込んで「プログラム」を作る。

```
[ピンシリンダー]        回転方向 →
  ┌─────────────────┐
  │ ●   ●     ●     │  ← ピンの位置 = 「いつ」
  │   ●     ●   ●   │  ← ピンの列  = 「何を」
  │     ●       ●   │
  └─────────────────┘
         ↓ ピンが押す
  [レバーA][レバーB][レバーC]
     ↓        ↓        ↓
  [水門開] [鋤を下ろす] [刃を動かす]
```

これはフィージビリティスタディで言及した「ヴィジュアルプログラミングみたいなこと」の原始的な実現形態。

**制御系の進化経路:**

```
手動操作（序盤）
  → タイマー歯車による定期制御（中盤）
  → ピンシリンダーによるシーケンス制御（終盤）
```

### 停止・制御機構

水車のON/OFF制御には以下の2つを主に使う。

#### 方法1: 水門（スルースゲート）— 水を止める

最も一般的な方法。水車そのものではなく、**水車に到達する水を制御する**。水門を閉じると導水路への水が止まり、水位差がなくなって回転が止まる。

##### 堰からの接続

```
              川上
                 │
  ═══════════════╤══════════════  ← 堰（ミルポンド形成）
               [水門]             ← ここを開閉
                 │
            [導水路（ミルレース）]
                 │
            [水車/ノーリア]
                 │
            [放水路] → 下流
```

水門はプログラム制御の第一歩：手動開閉（序盤）→ リンク棒やカムで自動開閉（中盤以降）

#### 方法2: ドッグクラッチ — 回転を伝えない

水車は回り続けるが、**その回転を後段に伝えない**機構。

```
[水車] → [軸A] → [ドッグクラッチ] → [軸B] → [歯車列]
                       │
                  噛み合い/離脱
                  をスライドで切替
```

- スライドさせて歯を噛み合わせる → 動力が伝わる（ON）
- スライドさせて歯を外す → 動力が切れる（OFF）
- 水車を止めずに特定の機械だけON/OFFできる
- 木製でも十分に作れる構造

#### 比較

| 方法 | 何を止めるか | 特徴 | ゲーム用途 |
|------|------------|------|-----------|
| **水門** | 水の流れ | 水車自体が止まる。灌漑の制御にも兼用 | 水路システム全体のON/OFF。タイマーとの相性◎ |
| **ドッグクラッチ** | 回転の伝達 | 動力源は動き続け、末端だけ切断 | 個別機械のON/OFF。分岐制御 |

1台の水車から複数機械に動力を分配しつつ個別にON/OFFする例:

```
[川] → [水門] → [水車] → [ドッグクラッチA] → [製粉機]
                     │
                     └→ [ドッグクラッチB] → [紡績機]
                     │
                     └→ [ドッグクラッチC] → [コンベア]
```

### 農作業の機械化

#### 各農作業の機械的な仕組み

**1. 耕す（プラウ／犂）**

犂は3つの部品で構成される：コールター（土を縦に切る）、シェア（土を下から持ち上げる）、モールドボード（持ち上がった土を横に反転させる）。**牽引力のみで動作**し、回転動力は不要。

**2. 植え付け（シードドリル / ポテトプランター）**

通常のシードドリルは小粒種子向け。種いも（40〜60gの塊）には**ポテトプランター**という専用機械が必要（カップまたはベルトで1個ずつ拾い上げて落とす）。どちらも台車が進むことで車輪の回転からギアで繰り出し機構を駆動するため、牽引するだけで動作する。

**3. 土寄せ（リッジャー）**

V字型の翼が土をかき分けて畝の両側に盛る。**牽引力のみで動作**。

**4. 収穫前処理 — ハウムトッピング**

じゃがいもの茎（ハウム）は収穫前に除去する必要がある（茎が収穫機に絡まって詰まるため）。ハウムトッパー（フレイルモア）の回転刃が地上部の茎を粉砕する。**回転動力が必要**（牽引だけでは動かない）。

**5. 収穫（ポテトハーベスター）**

掘り取り刃で土ごとジャガイモを持ち上げ、振動篩（エレベーターチェーン）で土を落とす。牽引力＋回転動力（あると良い）。

#### 農作業ごとの動力要件まとめ

| 農作業 | 牽引力 | 回転動力 | ゲーム的な簡略化 |
|--------|--------|----------|-----------------|
| 耕す | 必要 | 不要 | ロープで引っ張るだけ |
| 植え付け（小粒種子） | 必要 | 車輪から取れる | 台車が進めば自動で種まき |
| 植え付け（種いも） | 必要 | 車輪から取れる | ポテトプランター |
| 土寄せ | 必要 | 不要 | ロープで引っ張るだけ |
| 水やり | 不要 | 不要（水路+重力） | 既に設計済み |
| 茎刈り（ハウムトッピング） | 必要 | **回転動力必要** | じゃがいも収穫前の必須工程 |
| 収穫 | 必要 | あると良い | 掘り取りのみなら牽引だけ |

**重要な発見**: ほとんどの農作業は「牽引力」だけで成立する。水車からロープで台車を引っ張る仕組みさえあれば、農具を付け替えるだけで多くの作業を自動化できる。

参考: https://www.ndl.go.jp/exposition/s2/9.html（耕うん機・刈り取り機・脱穀機・コンバイン等の説明）

#### じゃがいもの農作業フロー

```
1. [プラウ]            土を耕す（牽引のみ）
       ↓
2. [ポテトプランター]  種いもを植え付け（牽引＋車輪回転）
       ↓
3. [リッジャー]        土寄せ・畝立て（牽引のみ）
       ↓
   （成長期間：水路+重力で自動灌漑、または天水に任せる）
       ↓
4. [ハウムトッパー]    茎を粉砕（牽引＋回転動力）
       ↓
5. [ポテトハーベスター] 掘り取り＋振動篩で土を落とす（牽引＋回転動力）
       ↓
   傾斜面 → ホッパー → チェストへ
```

#### 農具アタッチメントの設計方針

「何を動かすか」は既製品（クラフトレシピで入手）、「どう動かすか」はプレイヤーの設計。Factorioの「組立機は既製品、ベルトとインサータの配置はプレイヤー設計」と同じ構造。

| **プラウ** | 木材＋鉄 | 耕起 |
| **シードドリル** | 木材＋鉄＋歯車 | 小粒種子の植え付け |
| **ポテトプランター** | 木材＋鉄＋歯車 | 種いもの植え付け |
| **リッジャー** | 木材＋鉄 | 土寄せ |
| **ハウムトッパー** | 木材＋鉄＋刃 | 茎刈り（要回転動力） |
| **ポテトハーベスター** | 木材＋鉄＋チェーン | 収穫 |

### ケーブル牽引システム（ループレール方式）

「固定動力源＋ケーブル＋軌道上の移動体」という原理は、フニクラ（ケーブルカー）・鉱山トロッコ・運河インクラインなど歴史的に広く使われてきた普遍的な技術。ゲームでは農具・運搬台車を引っ張る用途に限定して応用する。

```
ケーブルカー:  [山上の巻き上げ機] ═══ケーブル═══ [客車] ═══ [軌道]
ケーブル牽引:  [畑端のウィンチ]   ═══ケーブル═══ [台車] ═══ [畑/レール]
```

どちらも固定された動力源がケーブルを巻き取り、軌道上の移動体を牽引する。動力源が移動体に搭載されていない点が共通で、移動体側を軽量・単純に保てる。

#### 基本構造

```
        水車
         ‖
      主シャフト
       ╱    ╲
  ウィンチA   ウィンチB    ← ロープ/ベルトで水車から動力を伝達
      ‖         ‖
      ╚═══台車═══╝
          ‖
        農具（プラウ/プランター/リッジャー/トッパー/ハーベスター等）
```

台車への動力伝達は二系統：
- **牽引ロープ**: ウィンチからの巻き取りで台車を移動
- **動力ベルト**（オプション）: 回転動力が必要な農具（ハウムトッパー等）用。車輪からギアで取れる場合は不要

#### ループレール方式

蛇行する1本の連続レールを畑に敷き、台車がレール上を周回する。引っ張るだけで全面をカバー。**方向転換の制御が不要**。

```
  ┌──────────────────────┐
  │  ←←←←←←←←←←←←←←←←  │
  │                      │
  │  →→→→→→→→→→→→→→→→  │
  │                      │  ← 蛇行する1本の連続レール
  │  ←←←←←←←←←←←←←←←←  │
  │                      │
  │  →→→→→→→→→→→→→→→→  │
  └──────────────────────┘
      ↑ 始点 = 終点（ループ）
```

段階的な自動化:
- **初心者**: 手動でクラッチON → ループ1周で全面自動耕作 → 始点のトリップレバーで自動停止
- **中級者**: ピンシリンダーで毎朝自動でクラッチON → 定期実行
- **上級者**: 成長センサーで作物育成を検知 → 収穫台車を自動発進（条件トリガー）

| 観点 | ループレール方式 |
|------|----------------|
| 資材コスト | 多い（レール全面敷設が必要） |
| 制御の複雑さ | 低い（引っ張るだけ） |
| 面積の変更 | 困難（レール敷き直しが必要） |
| プレイヤースキル | 初心者でも可能 |

#### 端の検知 — トリップレバー方式

フロートが水位を検知するのと同じ「物理的な力 → レバー → 制御機構」のパターンで台車の位置を検知する。19世紀の自動織機・自動旋盤で使われていた仕組み。

```
  台車の進行方向 →→→

                        ┌─ トリップレバー（ピボットで固定）
                        │    ↑ 台車が押すと倒れる
  ══════════════════════╪═══════
                        │
                        └─→ リンク棒 → クラッチ切断 or ブレーキ作動
```

- 畑の端に**トリップレバー**（突起棒）を立てておく
- 台車が到達するとレバーを物理的に押し倒す
- リンク棒を介して**ドッグクラッチの切断**に繋がる → 台車が端で自動停止

### アタッチメント自動切り替え（転車台＋グリップ方式）

農作業の工程ごとに台車のアタッチメントを切り替えるため、**転車台（ターンテーブル）とグリップ機構**を組み合わせる。

#### 基本構造

```
          [メインループ（畑）]
           ↗ 出発          ↖ 帰還
          ╱                  ╲
    ─────●────────────────────●─────
         │    ケーブル（常時走行）    │
         │                          │
    ═════╪══════════════════════════╪═════
         │       [転車台]           │
         │      ╱   │   ╲          │
         │   [A]   [B]   [C]       │
         │  プラウ プランター リッジャー │
         │      [D]   [E]          │
         │    トッパー ハーベスター    │
```

- 転車台の上に複数の台車が放射状に配置（各台車にアタッチメントが固定）
- ケーブルは転車台の下を直線的に通過（常時走行）
- 全台車のグリップは普段**開放状態**（ケーブルが素通りする）

#### 動作手順

1. **転車台回転**: 歯車駆動で転車台を回転させ、目的の台車をケーブルの真上に位置決め
2. **グリップ係合**: リンク棒が台車のグリップを閉じる。台車がケーブルを掴む
3. **出発**: ケーブルが台車を引き出し、メインループを1周
4. **帰還**: 帰還口のトリップレバーがグリップを開放
5. **再回転**: グリップが開いたので転車台が再び回転可能。次の台車を位置決め

#### グリップ機構（サンフランシスコのケーブルカーと同原理・1873年〜）

```
    [台車]
      │
    [グリップレバー]
      │
    ╔═══╗
    ║   ║ ← 2枚の顎（ジョー）
    ║ ○ ║ ← ケーブル（常時走行中）
    ║   ║
    ╚═══╝

   レバーを引く → 顎が閉じる → ケーブルを掴む → 台車が動く
   レバーを戻す → 顎が開く → ケーブルが素通り → 台車が止まる
```

#### 歴史的根拠

| 要素 | 由来 | 時代 |
|------|------|------|
| 転車台 | 鉄道の扇形機関庫（ラウンドハウス） | 1830年代〜 |
| グリップ | サンフランシスコのケーブルカー | 1873年〜 |
| ケーブル牽引 | 鉱山トロッコ、ケーブル農業 | 19世紀〜 |

#### 転車台の回転制御

- **手動期（序盤）**: プレイヤーがレバーで転車台を回す
- **自動期（中盤〜）**: ピンシリンダーで「1日目→プラウ、2日目→プランター…」と制御。帰還時のトリップレバーがグリップ解放と同時に転車台の回転クラッチを接続し、次の台車位置まで回転→位置決めピンで停止

### 回転動力の方向転換

水車からの回転動力を「曲がり角」で伝える方法:

| 要素 | 機能 | 用途 |
|------|------|------|
| **角度付き滑車** | ロープ/ベルトの方向を変える | 直角含む任意の角度で方向転換（最もシンプル） |
| **ベベルギア（かさ歯車）** | シャフトの方向を90度変換 | 水車→主シャフト→横方向シャフトの中継 |
| **ユニバーサルジョイント（自在継手）** | 角度付きシャフト間で回転を伝達 | シャフトが直線でない場合の接続 |

ゲーム的には**滑車**が最もシンプル。プレイヤーが畑の角に滑車を置くだけでロープの方向が変わる。

### 機械式カウンタ

歯車の角度位置を数値として扱うバベッジ的発想。

#### カウンタ歯車

```
  入力（1回転で1カウント）
      │
    [爪車（ラチェットホイール）]  ← 10歯なら10カウントで1周
      │
      ├── カウント値 = 歯車の角度位置
      │
    [桁上げ機構]
      │
    [次の桁の爪車]  ← 10カウントで1つ進む = 10の位
```

爪車（ラチェットホイール）が1クリックずつ進む。1周すると**桁上げ**で次の桁の歯車を1クリック進める（時計の分針→時針と同じ）。

#### カウンタ＋カムによる「n回目に発動」

カウンタ歯車の特定の位置にカム突起をつけることで、プログラマブルタイマーとして機能する。ピンシリンダーが「1回転中の時間的パターン」を制御するのに対し、カウンタは「n回目のイベントで発動」を制御する。

```
  日数カウンタ（day_changed イベントで +1）
      │
    [10歯の爪車]
      │
      ├── 5番目の歯にカム突起
      │        ↓
      │     フォロワーが押される
      │        ↓
      │     クラッチ接続 → 水門を開ける、台車を動かす 等
      │
    5日ごとに1回だけ作動する仕組み
```

| カウンタの対象 | カム位置 | 発動する動作 |
|--------------|---------|-------------|
| 日数 | 5日目 | 水やり台車を発進 |
| 日数 | 7日目 | 収穫台車を発進 |
| 収穫回数 | 3回目 | 肥料散布を実行 |
| 水車の回転数 | 100回転目 | 貯水槽の水門を閉じる |

## 川と水のシステム設計

### 課題

川は動力源（水車）として重要だが、プレイヤーが土地を削ったり盛ったりできるため、以下の問題が発生する：

- 地形変更で川の水が流れ出す（水のシミュレーションが必要になる）
- 地形変更で川を消せてしまう（水源の概念が必要になる）

### 検討した案

#### 案A: 平坦な川（水平線の高さにのみ水を生成）

- 水のシミュレーション不要で最も実装が簡単
- しかし高低差のある地形が活かせず、景観の多様性が減る
- 堰・導水路・水車の設計（本ドキュメントの自動化システム設計）と矛盾する
- 高台への揚水手段が別途必要になる
- **不採用**

#### 案B: 水源＋フラッドフィル

- 「水源」タイルを導入し、水源から隣接する同高さ以下のタイルにBFS/フラッドフィルで水が広がる
- 地形変更時のみ再計算するため計算コストは低い
- 水源が通常の操作で破壊可能なため、うっかり水源を潰してゲームが詰むリスクがある
- **案Eに統合**

#### 案C: 層状水位（Dwarf Fortress簡易版）

- 水を0〜7のレベルで表現し、毎tickで拡散シミュレーション
- 堰で水を溜める・水門で調整するなどの操作が直感的
- しかし毎tickの拡散シミュレーションが重く、実装・デバッグコストも高い
- フィジビリティスタディの段階では過剰
- 将来的に水路での運搬を実装する場合は再検討の余地あり
- **不採用（現段階では）**

#### 案D: 川は固定＋人工水路のみ可変

- 自然の川は破壊不能の固定地形とし、プレイヤーは水路ブロックのみ設置可能
- 実装は簡単だが、他の土地は削れるのに川だけ固定だと、川が絶壁の上を流れるような不自然なシチュエーションが発生しうる
- **不採用**

#### 案E: 水源永続＋フラッドフィル ← **採用**

- 案Bのフラッドフィル方式をベースに、水源を破壊不能な特殊ブロックとして扱う
- 水源以外の水タイルは地形変更の影響を受け、自然に広がったり消えたりする
- 水源が永続なので、掘り直せば必ず水が復活する（チルなゲームとしての安全設計）

### 採用案（案E）の詳細設計

#### 水源タイル

- 地形生成時に川の上流部に配置される特殊ブロック
- プレイヤーの通常操作（シャベル等）では破壊できない
- 常に水を供給し続ける（地下水脈という設定）
- 上に土を盛ることもできない（破壊不能ブロック）

#### 水の広がりルール

1. 水源タイルから隣接する同高さまたはそれ以下のタイルにフラッドフィル（BFS）で水が広がる
2. 再計算は**地形変更イベント発生時のみ**（毎tick計算しない）
3. 水は「流量」を持たず、到達可能な低地はすべて水で満たされる

#### プレイヤーの操作

- **堤防**: 土を盛って水をせき止める
- **水路**: 土を掘って水を引く
- **堰**: 川幅に壁を作り水位を上げる（既存の自動化システム設計と整合）

#### 水車との連携

- 水タイルに隣接して設置
- 高低差がある水の隣に置くと効率UP（落差による動力増加）

#### 高台への揚水

- ノーリア（水車で水を汲み上げる装置）を将来実装して解決
- 水道橋（既存の流体制御設計に記載済み）も利用可能

#### 計算コストの見積もり

- 400×400マップでのフラッドフィルは、地形変更1回あたり数ミリ秒で完了する規模
- プレイヤーは1タイルずつ操作するため、局所的な再計算で十分
