農作物は、主人公が食べることで少しずつ減る。この減るスピードより作るスピードを上げるのが最初の目的となる。

## 農作業の自動化システム設計

### 基本方針

**ガジェット連携システム**を採用する。各ガジェットが「入力」と「出力」を持ち、それらを組み合わせることで自動化を実現する。モナド的な入出力モデルをベースに、副作用を含めた拡張可能な設計を目指す。

段階的な実装により、初期は物理シミュレーションなしで範囲型の自動化を実現し、将来的にパイプやケーブルなどの明示的な接続システムを追加可能にする。

### Phase 1: 範囲型自動化（暗黙的連携）

#### 概要
- ガジェット同士が**近接していれば自動的に連携**する仕組み
- 物理的な接続（パイプ、ケーブルなど）の描画は不要
- 各ガジェットは「入力範囲」と「出力範囲」を持つ
- 配置時に依存関係を計算し、動作可否を判定

#### ガジェットの入出力モデル

各ガジェットは以下の属性を持つ：

```
入力 (inputs):
  - リソースタイプ（water, power, cropsなど）
  - 入力受取範囲（マス数）
  - 必須/オプショナル

出力 (outputs):
  - リソースタイプ
  - 出力影響範囲（マス数）
  - 効果（Effect）
```

#### 初期実装ガジェット一覧

**1. 井戸（水源）**
- 入力: なし
- 出力: water（範囲3マス）
- 効果: 範囲内のガジェットに水を供給

**2. 発電機（太陽電池）**
- 入力: なし（日中のみ稼働）
- 出力: power（範囲5マス）
- 効果: 範囲内のガジェットに電力を供給

**3. スプリンクラー**
- 入力: water（範囲2マス、必須）、power（範囲3マス、オプション）
- 出力: watering（電力あり→5マス、なし→3マス）
- 効果: 範囲内の作物に「水やり済み」状態を付与
- 備考: 電力があると範囲が拡大

**4. 自動耕作機**
- 入力: power（範囲3マス、必須）、seeds（インベントリから消費、必須）
- 出力: planting（範囲4マス）
- 効果: 範囲内の耕された土地に種を植える

**5. ハーベスター（収穫機）**
- 入力: power（範囲3マス、必須）
- 出力: harvesting（範囲4マス）
- 効果: 範囲内の成長した作物を収穫し、インベントリに追加

#### 視覚的フィードバック

**配置前のプレビュー:**
- ガジェット選択中、マウス位置に半透明で表示
- 入力要件が満たされているか色で表示（緑=OK、赤=NG、黄=一部満たされていない）
- 出力範囲を円または四角で表示

**配置後の状態確認:**
- ガジェットをクリックすると入出力の状態を表示
  - 例：「水源: 井戸#3から供給中 ✓」
  - 例：「電力: 供給なし ✗（範囲内に発電機を配置してください）」
- 動作中のガジェットには視覚エフェクト（アニメーション、パーティクル）を表示

**範囲の可視化:**
- 複数ガジェットの範囲が重なる部分をハイライト
- プレイヤーが効率的な配置を考える楽しさを提供

### Phase 2以降: 明示的接続システム（将来実装）

Phase 1が完成し、基本的な自動化が楽しめるようになった後、以下の要素を追加検討：

**パイプとケーブル:**
- 水や電力を明示的に接続するビジュアル要素
- 距離制限を超えて資源を輸送可能
- Factorio的な配線の楽しさを提供

**コンベアベルト:**
- 収穫物を物理的に運搬
- 倉庫やガジェット間の接続

**ビジュアルプログラミング要素:**
- 条件分岐やループを含む高度な自動化
- ノードベースのエディタでフローを組み立て

### 技術的な設計方針

#### 依存グラフの計算
- ガジェット配置時に周囲をスキャンし、入力要件を満たせるか判定
- 依存関係をグラフ構造として記録
- 毎フレームの物理演算は不要（配置・削除時のみ再計算）

#### 拡張可能な型システム
- リソースタイプは文字列ベースで拡張可能
- 新しいガジェットを追加しやすい設計
- 将来的なモッド対応も視野に入れる

#### 段階的な複雑化
- Phase 1: 範囲型（実装コスト低、理解しやすい）
- Phase 2: 明示的接続（戦略性向上、視覚的に楽しい）
- Phase 3: プログラミング要素（上級者向け、深いやりこみ）
