# 肥料生産自動化システム設計

> **位置づけ**
>
> 本ドキュメントは、`doc/05_CULTIVATION.md` の肥料体系と `doc/17_AUTOMATION.md` の自動化設計を接続し、  
> **堆肥を中心とした肥料生産・物流・施肥の自動化**を具体化する正式設計書である。
>
> ただし、本書には **MVP で実装する範囲** と **将来拡張として残す範囲** が混在するため、以下のルールで読むこと。
>
> - **正式方針として採用済み**
>   - ホッパー的な瞬間移動物流は導入しない
>   - 物流は台車・ループ・ステーションで視覚的に表現する
>   - 動力源は水車を中心とする
>   - 肥料自動化の主対象はまず **堆肥ライン**
>   - **ローダー / アンローダーはステーション側に持たせる**（台車側には持たせない）
> - **MVP で実装対象**
>   - 堆肥ラインの半自動化
>   - 共有チェストによるループ間受け渡し
>   - ローダーステーション / アンローダーステーション / マニュア・スプレッダー
> - **将来拡張**
>   - カムやピンシリンダーによる高度制御
>   - 水流搬送
>   - ケーブルクロス
>   - アイテム種フィルタ
>
> したがって、本書は正式設計書ではあるが、**全記述が即MVP実装対象という意味ではない**。  
> MVP の境界は本文中の「スコープ」「将来実装」節を優先すること。

> 本ドキュメントは `doc/05_CULTIVATION.md`（堆肥体系）と `doc/17_AUTOMATION.md`（ケーブル牽引システム）の設計を踏まえ、肥料（特に堆肥）の生産を自動化するための具体的な設計をまとめたものである。

## 1. 設計方針

### 1.1 背景

- 現状の肥料体系（`doc/05`）では、堆肥は**有機物×10 → 堆肥×1、発酵3日**という高コストな生産レシピが設定されている
- 輪作のためにひまわりを育て、刈り取って作物残渣を得、堆肥場で発酵させ、完成した堆肥を畑に撒く、という工程が手作業では大きな負担
- 草木灰のルートは比較的軽量だが、樹木供給に制約がある（持続的な植林が必要）
- いずれにせよ肥料生産は**自動化の価値が高い**領域であり、中盤の主要な自動化ターゲットとなる
- 手作業でも回るが、面積が広がるにつれ破綻する → 自動化への動機

### 1.2 基本原則

- 動力源は**水車**のみ（`doc/17` と共通）
- 物流は**台車＋ケーブル**で行う。マイクラ的な「ホッパーで自動的にアイテムが移動する」抽象機構は導入しない
- **全ての物流は物理的に視認できる**（台車が走り、積み、降ろす姿が見える）
- 抽象的な分類機・フィルタ機能は最小限。**現実の農機具の類推で成立する範囲**でメカニクスを組む
- 点と点の搬送が必要な場合、**ループを交差させず、共有チェスト（ステーション）で乗り換える**

### 1.3 「ホッパーを導入しない」設計思想

マイクラのホッパーのような「タイル間で自動的にアイテムが瞬間移動する」機構は、StellaGarden では**意図的に採用しない**:

- 台車が物理的にアイテムを運ぶ様子が「眺める楽しさ」の核になる
- チルな雰囲気との整合性（急がない・機械的でない・のんびり）
- 世界観（水力時代・前近代技術）との一致
- 結果として、**物流はすべて台車の巡回として実装される**

### 1.4 スコープ

**MVP（本設計で実装するもの）:**
- 堆肥ライン（作物残渣 → 堆肥場 → 施肥）の半自動化
- 必要なアタッチメントとエンティティの追加
- 共有チェスト + ステーション（ローダー/アンローダー）による「ステーション乗り換え」方式
- 「容量ベースで自然に流れる」物流ルール
- プレイヤーのレイアウト責任によって混在を避ける設計

**MVP スコープ外（将来実装）:**
- 水流搬送（フルーム）— ノーリアによる揚水が前提のため後半実装
- 陸橋エンティティ（ケーブルのクロス）— 第二段階で追加
- カム・ピンシリンダーによる自動プログラミング
- アイテム種フィルタ機能（台車の特化）
- 草木灰ラインや油粕ラインの本格自動化
- 複数ループの高度な優先制御

### 1.5 ローダー/アンローダーをステーション側に持たせる設計判断

本設計では、ローダー/アンローダーを **台車に装着するアタッチメントではなく、線路脇に設置する独立エンティティ（ステーション）として実装する**。この方針は、当初検討した「台車側アタッチメント方式」から正式に変更されたものである。

**判断理由（設定上の説得力）:**

- **台車側ローダー案の難点**: 台車が「今この瞬間に隣接エンティティがあるから積む/降ろす」というトリガを検出する必要がある。前近代技術レベルではこのトリガ機構を物理的・素朴に説明することが難しい。何らかのプログラマブルロジックを想定せざるを得ず、世界観と整合しない
- **ステーション側ローダー案の利点**: ステーションごとに「積み込み」か「降ろし」かが種別として一意に決まる。台車がステーション横の感圧板を踏むことで物理的にクラッチがつながり、回転動力が積み下ろし機構（往復運動）に変換される、という素朴な物理機構で説明が完結する

**設計上の副次効果:**

- 「畑タイル上を連続作業するもの＝台車アタッチメント（プラウ・シードドリル・ハーベスター・マニュア・スプレッダー等）」と「点で荷物を積み下ろすもの＝ステーション」の責務分離が自然に生まれる
- 台車のアタッチメントスロットは農作業系に専念できるため、スロット数は1個で足りる
- ステーションへの動力供給（シャフトの引き回し）が新しいレイアウトパズル要素になる

**補足:**
- 本書で扱う「肥料自動化」は、まず **堆肥** を中心に設計する
- `doc/05_CULTIVATION.md` にある肥料体系全体（堆肥・草木灰・油粕）のうち、MVP で自動化対象として深く扱うのは堆肥ラインのみ
- 草木灰や油粕は、将来的に同じ物流原則へ接続できるように設計思想だけ揃えておく

## 2. エンティティ層の整理

`doc/17` に既出のエンティティと本設計で追加するエンティティを、**2つのレイヤ**に整理する。

| レイヤ | 性質 | 例 | ボクセル表現 |
|---|---|---|---|
| **地上層（Ground）** | 1タイル1個。互いに排他。エンティティ固有の状態ビットを持つ | 堆肥場、通常チェスト、ローダー/アンローダーステーション、炉、作物、畝間水路、導水路、ケーブル、線路 | エンティティビット + 各種状態ビット |
| **移動層（Mobile）** | タイル非拘束の動くもの | 台車、プレイヤー | ボクセル外で管理 |

### 2.1 設計の経緯（簡略化の背景）

当初は「同じタイルにチェストとケーブルが共存する」要求を想定して、地上層とは別に**ネットワーク層**という独立レイヤを設ける案を検討していた。しかし、設計を詰める過程で:

- アイテム移動はローダー/アンローダーが**隣接タイル間**で行う方式に決まった
- そのため、チェストとケーブルは**隣接配置で済む**（同タイルに重なる必要がない）
- 既存の畝間水路も「自身の接続ビットを持つ地上層エンティティ」として実装されている
- ケーブルも同じパターンで実装できるため、独立したネットワーク層を設ける必要がない

これらを踏まえ、MVP では**全てのタイル設置物を地上層に統一**する設計を採用する。将来「やはり重ねる必要がある」となれば、その時に分離レイヤを導入できる余地は残しておく。

### 2.2 共存ルール

- **Ground × Ground** は排他（1タイルにつき1エンティティ）
  - 例: チェストと堆肥場は同タイルに置けない
  - 例: ケーブルと畝間水路は同タイルに置けない
- **Mobile × Ground** は共存可（台車は常にタイルの上に乗る）

### 2.3 ケーブル・畝間水路のクロス

- ケーブル × ケーブル、ケーブル × 畝間水路、畝間水路 × 畝間水路 のいずれも、**MVP では同タイル排他**＝**クロス禁止**
- これらのクロスを解決する手段として、将来的に**陸橋エンティティ**（地上層エンティティを上下2層に分離するメカニズム）の実装を予定する
- 陸橋は本設計のスコープ外

### 2.4 ケーブル設置の制約

- ケーブルを設置したタイルは**耕すことができない**（畑と物流経路は排他）
- ケーブルは**端末・直線・90度曲がり**のスプライトを接続状態から自動選択する（`doc/16` の畝間水路と同じロジック）
- **MVP では分岐（T字・十字）は実装しない**。ケーブルは始点と終点を持つ一本道として敷設する
- ケーブルのクロスは **MVP では禁止**。将来的に陸橋エンティティで解禁予定

### 2.5 ケーブル構造: 「一本道」と「ループ」

ケーブルの構造には、本来「真のループ」と「始点・終点を持つ一本道」の2種類がありうる:

| 構造 | 動作 | プレイヤー操作 | 実装難度 |
|---|---|---|---|
| 真のループ | 台車が周回し続ける。停止には自動停止機構（トリップレバー＋クラッチ自動切断）が必要 | クラッチ ON/OFF のみ | 高（自動停止の機構が必要） |
| 一本道 | 台車が始点 → 終点に進み、終端で自然停止。台車を始点に戻すのは手作業 | クラッチ ON/OFF + 終端到達後の台車手動移動 | 低 |

**MVP ではすべてのループを「一本道」として実装する**:

- 自動停止機構（トリップレバー）の実装が不要
- 台車は終点（レールの端末）で物理的に進めなくなり、自然停止する
- プレイヤーがクラッチ OFF にし、台車を始点に戻す
- 物流ループのように「常時走り続ける」運用は MVP では成立しないが、第一段階として畑ループのみを成立させる
- 将来段階的にループ化を進める計画とする（後述）

## 3. 動力系

`doc/17` の動力系をそのまま採用する。本設計では、動力系は**複数のループと複数のステーションを独立に駆動**する目的で使う。

```
水車（水タイルに隣接）
  │
  シャフト（メインライン）
  │
  ├─ クラッチA ─ シャフト → ウインチA → 畑ループ（ハーベスター台車）
  │
  ├─ クラッチB ─ シャフト → ウインチB → 物流ループ（運搬台車）
  │
  ├─ シャフト → ローダーステーション群（線路沿い、常時動力）
  │
  ├─ シャフト → アンローダーステーション群（線路沿い、常時動力）
  │
  └─ シャフト → 加工機械（搾油プレス等、doc/17参照）
```

**各ループは独立にクラッチ ON/OFF 可能**。プレイヤーは「畑ループだけ回す」「物流ループだけ回す」を選べる。MVP では操作は手動。

### 3.1 クラッチの操作仕様（MVP）

- **サイズ**: 1×1 タイル
- **配置**: シャフトラインの途中
- **操作**: **左クリックで ON / OFF をトグル**
- **見た目**: ON 状態 / OFF 状態の 2 種類のスプライトで状態を表現
- 将来的にカム連動による自動 ON/OFF を追加予定（MVP スコープ外）

### 3.2 ウインチの仕様（MVP）

- **配置**: ケーブル一本道の**終点側に1個**設置する（始点側にはアンカーのみ、ウインチ不要）
- **動作**: シャフトから回転力を受け、ケーブルを巻き取って台車を終点側に牽引する
- **ロープの巻き取り問題**: 現実にはロープが有限なので巻き取り続けると枯渇するが、**MVP ではロープを実質無限として扱う**（巻き取り表現は省略）
- 将来的に「ロープを別の所から再供給する仕組み」や「ループ化による解決」を検討する余地あり

### 3.3 ステーションへの動力供給（MVP）

- ステーション（ローダー/アンローダー）は **回転動力を必要としない**
  - 回転動力を必要とする案もあったが、レイアウトが困難になるため中止した

## 4. 台車（Cart）とアタッチメント

### 4.1 移動層カテゴリと台車

台車（Cart）は、ボクセルマップ上には存在しない **移動層（Mobile）エンティティ** である。プレイヤーと同じカテゴリに属するが、専用のサブカテゴリとして「Cart」を持つ。

- **カテゴリ名**: Mobile（doc/21 §2 既出）
- **サブカテゴリ**: Cart
- **データ保持**: ボクセルマップ外。専用の配列/Map で位置・インベントリ・アタッチメントを管理

### 4.2 台車の基本構造

- 台車は**ケーブルが敷設されたタイルの上**に配置される移動層エンティティ
- 台車のサイズは**1×1**（カーブでの描画問題を避けるため、MVP では小型固定）
- 台車は**ケーブルの牽引**によって始点から終点へ一方向に進む（MVP は一本道）
- 台車は**インベントリ**を持つ（後述）
- 台車には**アタッチメント**を装着できる。アタッチメントは作業の種類を決める
- 台車の**アタッチメントスロット数は 1個**（MVP）
  - 農作業系アタッチメント（プラウ・シードドリル・ハーベスター・マニュア・スプレッダー等）は同時装着の必要がないため
  - ローダー/アンローダーは台車から削除し、ステーション側に移管（§5 参照）

### 4.2.1 台車のインベントリ容量

- **MVP では 16 スロット**
- 実プレイでの感触を見て調整する
- 単一スタックの個数上限は他のチェスト系と合わせる（要決定）

### 4.2.2 台車のUI（右クリック起動）

- 台車を **右クリック** すると、台車専用 UI パネルが開く
- UI は他の DailyProcessingPanel.tsx 等の施設 UI と同じパターンで作る
- 構成:
  - **アタッチメントスロット**: 1個
  - **インベントリスロット**: 16個
- 右クリック時の座標から台車を特定するロジックが新規必要（台車はボクセル外管理のため、既存の `open_facility_ui` フローでは引けない）
- 実装方針:
  - `_boundary/events.ts` に台車起動用イベントを追加（例: `open_cart_ui`）、または既存の `open_facility_ui` イベントを拡張して `target: 'tile' | 'cart'` を持たせる
  - 入力ハンドラ（`src/input/InputHandler.ts`）で、右クリック座標に台車がいるかをまずチェックし、いれば台車UI、なければ既存の施設UIを起動

### 4.2.3 台車の取り回し（MVPの一本道運用）

一本道運用に伴い、台車を始点に戻す手段が必要:

- 台車は**斧でインタラクト**するとアイテム化してプレイヤーが拾える
- プレイヤーが任意の場所（始点）に再度配置できる
- アタッチメントも同様に拾い直して、再度装着する必要がある
- 1サイクル（数日に1回）の手作業として許容範囲とする
- 将来的にループ化と自動停止機構が実装されれば、この手作業は不要になる

### 4.3 アタッチメント一覧（台車側）

ローダー/アンローダーはステーション側に移管されたため、台車に装着するアタッチメントは「畑タイル上で連続作業するもの」のみとなる。

| アタッチメント | 作業 | 動力要件 | 用途 | 備考 |
|---|---|---|---|---|
| ハーベスター | 収穫（2ビン出力） | 牽引のみ | 畑ループ | **本設計で仕様拡張** |
| スプレッダー | 畑に堆肥を散布/種子植え付け | 牽引 + 車輪回転 | 畑ループ | 新規 |


下記のアタッチメントは、検討のみ。

| アタッチメント | 作業 | 動力要件 | 用途 | 備考 |
|---|---|---|---|---|
| プラウ | 耕起 | 牽引のみ | 畑ループ | 既存（doc/17） |
| シードドリル | 小粒種子の植え付け | 牽引 + 車輪回転 | 畑ループ | 既存 |
| ポテトプランター | 種イモの植え付け | 牽引 + 車輪回転 | 畑ループ | 既存 |
| リッジャー | 土寄せ・畝立て | 牽引のみ | 畑ループ | 既存 |
| マニュア・スプレッダー | 畑に堆肥を散布 | 牽引 + 車輪回転 | 施肥ループ | 新規 |

> ローダー/アンローダーは台車アタッチメントから外れ、独立した地上層エンティティ「ローダーステーション / アンローダーステーション」として §5 で定義する。

### 4.4 ハーベスターの仕様拡張（2ビン出力）

現実世界の脱穀機・コンバインは、脱穀・選別・排藁分離が同じ機械内で行われ、**穀物と藁が別々に排出される**。この仕組みを踏襲し、ハーベスターは**内部で作物と残渣を分離して2つのビンに分ける**。

#### 物理的配置

- ハーベスターは**3×1 サイズ**のマルチタイルアタッチメント
- 台車の**後方**に接続される（台車1×1 + ハーベスター3×1）
- 中央のタイルはレール上にあり、**収穫対象外**（接続部・走行部分）
- 左右の各1タイルが**畑タイルから収穫を行う**
- 1通過につき左右合計**2タイル分**の畑を収穫

```
進行方向 ↑
  [台車 1×1]                       ← レール上
  [H左][H中][H右]                  ← ハーベスター 3×1（後方接続）
  [畑] [線路][畑]                  ← H左・H右が畑から収穫、H中は線路上
   ↑          ↑
  収穫       収穫
```

#### 作物・残渣マッピング（MVP）

各作物について、ハーベスターが**作物ビン**と**残渣ビン**にどう振り分けるかを正式定義する:

| 作物 | 作物ビン | 残渣ビン | 備考 |
|---|---|---|---|
| ジャガイモ | ジャガイモ（本体） | 茎葉 | 茎葉は緑色の地上部 |
| 大豆 | 大豆（豆） | 茎 | 脱穀済み相当 |
| 亜麻 | 亜麻の種 | 亜麻の茎 | 「残渣」と呼ぶには茎は本来主用途品（繊維）だが、MVP では分類の都合で残渣ビン側に格納する |
| ひまわり | ひまわりの種 | ひまわりの茎 | 種は次回の播種用、茎は堆肥原料 |

**亜麻の特例について:**

亜麻は本来「繊維（茎）」が主産物だが、ハーベスター段階では「収穫直後＝脱穀後」のような扱いとし、**作物ビン＝種、残渣ビン＝茎** で振り分ける。亜麻の茎は堆肥原料ではなくレッティングを経て繊維となるが、MVP の物流上は残渣ビンに入れて、別ラインで処理することを想定する（亜麻の繊維加工ラインは将来実装）。

#### ステーションへの排出マッピング（左右決め打ち方式）

ハーベスターは作物ビン・残渣ビンの2ビンを持つ台車インベントリに収穫物を格納する。ステーションが台車のどちらのビンに作用するかは、**ステーションが台車の進行方向に対して左にあるか右にあるかで決め打ち**となる:

- **台車の進行方向に対して左にあるステーション** → 左ビン（作物ビン）に作用
- **台車の進行方向に対して右にあるステーション** → 右ビン（残渣ビン）に作用

> 左右どちらをどちらに割り当てるかは台車仕様として固定する（MVP の暫定: 左=作物、右=残渣）。プレイヤーが反転設定する仕組みは持たない。

**この方式の利点:**

- ステーションが「隣接チェストの中身を読んで判定する」ような抽象的なロジックが不要
- 前近代技術レベルでも素直に説明できる（左腕は左に、右腕は右にしか動かない、というシンプルな機構）
- 実装が単純（ステーションは自身に対する台車の相対位置を見るだけ）

**この方式のトレードオフ:**

- 「特定のビンを特定の場所のチェストに排出したい」場合、レール経路をうまく設計する必要がある
- 場合によっては、線路の左右を入れ替えるために**陸橋エンティティ（将来実装）**が必要になる
- このトレードオフは受け入れ、レイアウトパズル要素として保持する

詳細は §6 物流発火ルールを参照。

> なお、単一ビンの台車（マニュア・スプレッダー専用車・純粋な物流台車など）では、左右どちらに置いても同じ唯一のビンに作用するため、左右の区別は事実上意味を持たない。左右マッピングが意味を持つのは、ハーベスター付き2ビン台車のみ。

### 4.5 マニュア・スプレッダー

- 現実世界の**マニュア・スプレッダー（肥料散布機）** の再現。19世紀末に発明された実在の農機
- 台車インベントリの堆肥を、**通過中の畑タイル（soil/wetSoil）に1タイルずつ散布**する
- 施肥効果を発生させる（`doc/05` の施肥システムと統合）
- 動力要件: 牽引 + 車輪回転（撒き出し機構の駆動）

### 4.6 アタッチメントの視覚・アニメーション設計（台車側）

台車側に残るアタッチメント（ハーベスター・マニュア・スプレッダー等）のアニメーション方針。ローダー/アンローダーのアニメーション設計は §5 ステーション側に移管。

#### 基本方針

- **機構を物理的に見せる**: マイクラのホッパー的な「アイテムが勝手に移動する」抽象表現は使わない。物理的な機構の動きを示す
- **静止時もアタッチメントの存在を視認可能**にする（台車の上に小さなシルエットが常時表示される）
- チルな雰囲気を保つため、動作は**素朴な木製農具**のテイストで統一する

#### マニュア・スプレッダーのアニメーション

- **静止時**: 台車後方に散布ディスク（小さな車輪状の機構）
- **動作時**: 散布ディスクが回転し、畑タイルに**小さな粒子エフェクト**（こげ茶色のドットが散らばる）が発生
- 通過するたびに連続的に撒かれるため、「伸ばす・戻す」型のアニメは不要

これは現実の肥料散布機の「後方の回転ディスクが遠心力で肥料を散布する」挙動に近い（実際の散布機は牽引後方にドラムや回転ディスクを持つ）。

#### サウンド（案）

| アタッチメント | 動作音 |
|---|---|
| マニュア・スプレッダー | "shhh"（散布する音） |
| ハーベスター | "click" / "snap"（刈刃の動き） |

いずれも控えめな音量で、チルな雰囲気を壊さないこと。

## 5. ステーション（ローダー / アンローダー）

ローダー/アンローダーは台車のアタッチメントではなく、**線路脇に設置する独立した地上層エンティティ**として実装する。本セクションでその仕様を定義する。

### 5.1 ステーションの基本構造

| 項目 | 仕様 |
|---|---|
| 種別 | **ローダーステーション**（積み込み専用）／**アンローダーステーション**（降ろし専用）の2エンティティ |
| 占有サイズ | 1×1 タイル |
| 向き | 縦/横 |
| 動力要件 | なし |
| 動作条件 | 以下すべてを満たした時のみ発火: 1. 隣接縦・横2方向のいずれかに台車がいる（線路上）／2. 台車のいる側と反対側の隣接タイルに、対象となる地上層エンティティ（チェスト等）がある／3. 容量の余裕がある |

### 5.2 配置の自由度

- ステーションは **線路や他のエンティティに隣接していなくても設置できる**
- プレイヤーが先にステーションを置いて、後から線路やチェストを配置することも可能
- 動作条件は実行時に判定するため、必要な隣接が揃っていない間は単にアイドル状態となる
- これにより、レイアウト設計の自由度を高く保つ

### 5.3 ステーション種別

#### 5.3.1 ローダーステーション

- **動作**: 「対象エンティティ（チェスト・堆肥場など）」から「台車」へアイテムを移動させる
- 隣接4方向のうち、片側に台車・反対側に対象エンティティがある時に発火
- 台車のインベントリに空きがあり、対象エンティティに在庫がある場合に1回ぶん移動

#### 5.3.2 アンローダーステーション

- **動作**: 「台車」から「対象エンティティ（チェスト・堆肥場など）」へアイテムを移動させる
- 隣接4方向のうち、片側に台車・反対側に対象エンティティがある時に発火
- 台車のインベントリに在庫があり、対象エンティティに空きがある場合に1回ぶん移動

### 5.4 感圧板（自動付与）

- ステーション設置時に、**隣接する線路タイルへ感圧板が自動的に付与される** (ビジュアルには反映しない。概念のみ)
- 感圧板はステーションの動作トリガとして機能する（台車が踏んだ瞬間にステーション内部のクラッチがつながる）

### 5.5 通過時の積み下ろし挙動

- 台車はステーション横を**通過しながら**積み下ろしを行う（停止しない）
- 「踏んだ瞬間に1回ぶん成立」というモデル: 台車がステーション横タイルに進入した瞬間に、5.1 の動作条件をすべてチェックし、満たしていれば1回ぶんのアイテム移動を行う
- 通過速度と積み下ろし量のリアル感はシミュレートしない（MVP）
- 1回あたりの移動量はステーション種別ごとに定数で持つ（要決定。MVP は数アイテム〜1スタック程度）

### 5.6 堆肥場の扱い（向きなし）

操作性とコードの統一感を優先し、**堆肥場も向きを持たない**。

| 項目 | 仕様 |
|---|---|
| 占有サイズ | 2×2 タイル |
| 方向 | **持たない**（無向） |
| 投入 | 隣接4辺（2×2 = 8タイル分）のどこからでも受け付ける |
| 取出 | 隣接4辺（2×2 = 8タイル分）のどこからでも取り出せる |
| 内部状態 | 未発酵原料カウンタ、発酵進行度、完成堆肥カウンタ |

**ステーションと堆肥場の組み合わせ:**

- 堆肥場のどの辺にでも **アンローダーステーション** を置き、その反対側に線路を敷けば、台車から堆肥場へ残渣を投入できる
- 堆肥場のどの辺にでも **ローダーステーション** を置き、その反対側に線路を敷けば、堆肥場から台車へ完成堆肥を取り出せる
- 同じ堆肥場に対して投入用ステーションと取出用ステーションを別の辺に並列に置くこともできる

**設計判断の根拠:**

- ステーション側が無向のため、堆肥場だけが向きを持つと「向きモデル」が中途半端に2方式残ることになる
- 全エンティティを無向に統一することで、設置・配置UIや内部のロジックが単純化される
- 「投入と取出が同じ場所」というのは現実的にはやや抽象的だが、ゲーム上の操作性とコードの一貫性を優先する

### 5.7 通常チェストの扱い（向きは持たない）

物流の中継点として使用する通常チェストは、**向きを持たない**。

- 4方向どこからでもアクセス可（隣接ステーションは投入/取出の両方ができる）
- 容量は所定のスタック数（要決定）
- doc/21 旧版にあった「ステーションチェスト（向きあり）」という概念は廃止し、通常チェスト + ステーションの組み合わせで代替する

### 5.8 ステーションの視覚・アニメーション設計

旧版の「台車側ローダー/アンローダー」のアニメーション設計をステーション側に移植する。

#### ローダーステーション: 伸びるフォークアーム

- 現実世界の**ピッチフォーク / ヘイフォーク**を機械化したような見た目
- ステーション本体に折りたたまれた木製アーム、先端に2〜3本歯のフォーク
- 動作時、アームが対象エンティティ方向に伸び、引き戻されて反対側の台車へアイテムを渡す

**アニメーション（3〜4フレーム想定）:**

1. アーム折りたたみ（通常状態）
2. アームが対象エンティティ方向に伸びる
3. アームが引き戻される（アイテムが歯に引っかかってついてくる）
4. アームが反対側の台車方向にアイテムを渡す（必要なら）

#### アンローダーステーション: 倒れるサイドシュート

- 現実世界の**サイドダンプワゴン / 石臼小屋の粉シュート**のような見た目
- ステーション本体に折りたたまれた小さな木製シュート（滑り板）
- 動作時、シュートが対象エンティティ方向に倒れ、その上をアイテムが滑り落ちる

**アニメーション（3フレーム想定）:**

1. シュート折りたたみ（通常状態）
2. シュートが対象エンティティ方向に倒れて伸びる
3. シュート上をアイテムが滑り落ちて隣接タイル（対象エンティティ）に着地

#### 補助エフェクト: アイテムアイコンの浮遊

機構のアニメに加えて、**アイテムアイコンが台車と対象エンティティの間を小さく浮遊**する補助エフェクトを併用する:

- **ローダー発火時**: アイテムアイコンが対象エンティティ → ステーション → 台車方向に浮遊移動
- **アンローダー発火時**: アイテムアイコンが台車 → ステーション → 対象エンティティ方向に浮遊移動
- アイコンは品目ごとに色分け（例: 残渣=緑系、堆肥=こげ茶、ひまわりの種=黄系）

#### サウンド（案）

| ステーション | 動作音 |
|---|---|
| ローダーステーション | "scrape" / "scoop"（こすれる音） |
| アンローダーステーション | "thump" / "shuffle"（軽く落とす音） |
| 感圧板（台車通過時） | "click"（小さなスイッチ音） |

いずれも控えめな音量で、チルな雰囲気を壊さないこと。

## 6. 物流の発火ルール

> **正式方針**
>
> 物流の発火は、複雑な条件分岐やプログラム記述ではなく、  
> **ステーション種別 × 隣接配置 × 台車の通過 × 容量状態** の組み合わせで決まる。
>
> これは MVP における重要な設計方針であり、
>
> - プレイヤーが理解しやすい
> - 見た目と挙動が一致する
> - チルな雰囲気を壊さない
> - 後から高度制御を追加しても土台を壊さない
>
> という利点を持つ。

台車の通過時に発生する積み込み・降ろし動作は、**ステーション側でチェックする**以下の単一ルールで記述できる:

```
台車がタイルTに進入した時:
  Tに隣接する地上層エンティティを4方向について調べる:
    隣接するステーションSがあれば、Sについて以下を判定:
      - Sの逆側（台車のいるTタイルの反対）の隣接タイルに、対象エンティティEがある
      - Sが台車の進行方向に対して左にあるか右にあるかで、台車のどのビンに作用するかを決定（左=左ビン、右=右ビン）
          - 単一ビン台車の場合: 唯一のビンに作用（左右の区別は意味なし）
          - 2ビン台車（ハーベスター付き）の場合: 左ビン=作物、右ビン=残渣（仕様固定）
      - Sがローダーステーション かつ E→台車（対象ビン） のアイテム移動が可能（Eに在庫あり、台車対象ビンに空きあり）
          → ローダー発火（1回ぶん移動）
      - Sがアンローダーステーション かつ 台車（対象ビン）→E のアイテム移動が可能（台車対象ビンに在庫あり、Eに空きあり）
          → アンローダー発火（1回ぶん移動）
      - 上記以外 → 素通り
```

### 6.1 容量ベースの動作

- **堆肥場（アンローダーステーション経由で投入）**: 原料カウンタが10未満なら不足分だけ投入を受け付ける。10に達したら発酵開始し、以降投入不可
- **堆肥場（ローダーステーション経由で取出）**: 完成堆肥がある場合のみ取り出し可能
- **通常チェスト**: 容量上限まで受け入れる、在庫がある限り取り出し可能

**プレイヤーはカムやプログラミングを書く必要がない**。容量制約だけで「空いているところに自動で流れる」挙動が成立する。

### 6.2 アイテム種の扱い（MVPではレイアウトで解決）

- **MVPでは台車のインベントリにアイテム種別フィルタを持たせない**
- 別種のアイテムが混ざらないようにするのは**プレイヤーのレイアウト責任**
- 混ざった場合の挙動は「意図しない物が投入される」可能性があるが、MVPでは自己責任
- ハーベスター付き2ビン台車では、**ステーションの左右位置で作用ビンが決まる**ため、プレイヤーが線路レイアウトで「どちら側に何用のステーションを置くか」を設計する必要がある
- レイアウト都合で線路の左右を入れ替えたい場合、将来実装の **陸橋エンティティ**（§11 将来実装参照）が必要になる可能性がある
- 単一ビン台車では、ステーションの左右位置は意味を持たず、ローダーは「在庫があれば積む」、アンローダーは「在庫があれば降ろす」だけ
- 将来、実プレイで頻繁に事故が起きるようならフィルタ機能の追加を検討

この方針は、フィルタインサータ的な「記号的なルール設定」を避けるためでもある。物流の挙動は**物理的な通過と容量**だけで決まり、世界観に馴染む。

**MVP境界の明確化:**
- ここでいう「自己責任」は、設計ミスをゲームオーバー級の罰にするという意味ではない
- あくまで「レイアウトの工夫が必要」というパズル性を残すための方針である
- 実プレイでストレスが大きすぎる場合は、将来拡張としてフィルタや優先制御を追加する余地を残す

## 7. 肥料自動化ラインの全体構成

> **MVPでの読み方**
>
> この章では 3ループ構成を提示しているが、これは「最終的に目指す完成形」に近い図でもある。  
> MVP 実装では、この全体像を一度に完成させる必要はない。
>
> 優先順位としては以下を想定する。
>
> 1. **畑ループ A の一本道実装**（MVP 第一段階）
> 2. 残渣を集める
> 3. 堆肥場へ運ぶ
> 4. 完成堆肥を取り出す
> 5. 畑へ撒く
>
> つまり、**ループA・B・C を概念上は分けつつ、実装は段階的に進める**。
>
> なお MVP では、**全ループを「一本道」として実装する**（セクション 2.5 参照）。  
> 「ループ」という名称は使い続けるが、構造としては始点と終点を持つ一方向の道である。  
> 台車を始点に戻す手段はプレイヤーが斧で台車をアイテム化して持ち運ぶ方式を取る（セクション 4.1.1 参照）。

### 7.1 3ループ構成

MVP で組む肥料自動化ラインは、以下の **3つのループ**から成る。各ループは水車から独立した動力分岐を持ち、ウインチで駆動される。

#### ループ A: 畑ループ（収穫側）

- 畑の周囲に敷設されたループケーブル
- **ハーベスター装着の台車**が周回
- 畑上で作物＋残渣を2ビンに分離して収穫
- ループ上の **作物用アンローダーステーション**（裏に作物チェスト）で作物ビンを排出
- ループ上の **残渣用アンローダーステーション**（裏に残渣チェスト）で残渣ビンを排出

※ アンローダーステーションは別タイルにする（作物と残渣を物理的に別の場所に降ろす）。これにより「チェストにアイテム種別を指定する」という抽象ルールが不要になる。

#### ループ B: 物流ループ（残渣→堆肥場→堆肥チェスト）

- 残渣チェスト・堆肥場・堆肥チェストの周囲に敷設されたループケーブル
- 台車B1（アタッチメントなし、純粋な物流台車）が周回:
  1. 残渣チェストに隣接するローダーステーション → 残渣を台車に積む
  2. 堆肥場に隣接するアンローダーステーション → 残渣を堆肥場に投入
  3. 堆肥場に隣接するローダーステーション → 完成堆肥を台車に積む
  4. 堆肥チェストに隣接するアンローダーステーション → 堆肥を堆肥チェストに降ろす

※ 同じ台車が残渣と堆肥の両方を運ぶのは混在リスクがあるため、**専用台車を2台配置**する運用も可（1台は残渣専用、もう1台は堆肥専用）。これはレイアウト次第。

#### ループ C: 施肥ループ（堆肥→畑）

- 堆肥チェストと施肥対象の畑の周囲に敷設されたループケーブル
- 台車C（**マニュア・スプレッダー**装着）が周回:
  1. 堆肥チェストに隣接するローダーステーション → 堆肥を台車に積む
  2. 畑タイルの上を通過 → マニュア・スプレッダー発火、堆肥を撒く

※ 施肥ループは畑ループと同じ領域を周回するため、**両ループを畑の周囲に二重に敷く**か、**時期によって使い分ける**かのレイアウト設計が必要。

### 7.2 全体図

```
             ┌─── [畑ループ A: ハーベスター台車] ───┐
             │                                        │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │                                        │
             └──[作物U]──[残渣U]─────────────────────┘
                 │         │
                 ↓         ↓
                作物     残渣チェスト ─[残渣L]─┐
                チェスト                          │
                                                  ↓
                                              [台車B経路]
                                                  │
                                                  ↓
                                          [堆肥場（隣接Uで投入 / 隣接Lで取出）]
                                                  │
                                                  ↓
                                              堆肥チェスト
                                                  │
                                                  ↓
                                          [堆肥L]─→[施肥ループC]→畑へ撒く

凡例:
  U = アンローダーステーション（台車→裏のエンティティ）
  L = ローダーステーション（裏のエンティティ→台車）
```

★ = ローダー/アンローダーステーションが物流の乗り換え点となる

### 7.3 レイアウトの自由度と制約

- **クロス禁止**のため、各ループは交差しないようにレイアウトする必要がある
- **共有チェスト + ステーション** によりループ間でアイテムを受け渡す
- 畑ループと施肥ループが同じ畑領域を回るため、**二重に敷設する**か**時期分離**するかの設計判断が生まれる
- ステーションごとにシャフトを引く必要があるため、**動力配線のレイアウトもパズル要素**となる
- これらがプレイヤーにとってのレイアウトパズルとなる

## 8. ボクセルデータ構造の拡張

### 8.1 既存の割り当て（参考）

- bits 0-7: 地形タイプ
- bits 8-15: 地上エンティティ
- bits 16-18: 作物育成カウンタ
- 既に 64bit に拡張済みのため、余裕は十分

### 8.2 本設計で追加するビット（案）

ケーブルは**畝間水路と同じく地上層エンティティ**として実装するため、追加で必要なのはエンティティ固有の状態ビットのみ。

| 用途 | ビット数 | 備考 |
|---|---|---|
| ケーブルの接続状態（上下左右） | 4bit | 畝間水路と同じロジック |
| 線路の感圧板状態（隣接ステーションによる付与フラグ） | 1bit | ステーション設置時に隣接線路へ自動付与 |

**廃止された向きビット:**

- ステーションチェスト（旧）の向きビットは不要（ステーション側ローダー方式に変更したため廃止）
- 堆肥場の向きビットは不要（向きなし方針に変更したため廃止）
- 通常チェストは向きを持たない
- ステーション（ローダー/アンローダー）も向きを持たない

**設計指針:**

- 本設計に登場する地上層エンティティはすべて**無向**で実装する（向きビット2 を持つエンティティは存在しない）
- ケーブル・畝間水路・導水路・線路・ステーション・チェスト・堆肥場はそれぞれ**別個のエンティティ値**として登録される（同タイルには1種のみ存在）
- 各エンティティ種別ごとに、必要に応じて固有の状態ビット（接続状態・感圧板有無など）をボクセル内に配置する
- 64bit の余裕の中で、地上層エンティティが必要に応じて状態ビットを使う方針
- 具体的なビット配置は実装時に決定する

### 9.1.1 必要スプライトの詳細

**ケーブル（地上層、MVP分）:**

- 直線（縦・横）: 2種
- 90度曲がり: 4種（4方向）
- 端末（行き止まり）: 4種（4方向）
- 計 **10種**（接続状態から自動選択）

**台車（移動層）:**

- 4方向別スプライト（上下左右）: 4種
- 直線移動アニメ: 各方向の前進フレーム
- 直角曲がりアニメ: 90度回転の中間フレーム
- ピックアップ用アイテムスプライト（斧でアイテム化された状態）: 1種

**ハーベスター（3×1 アタッチメント）:**

- 4方向別スプライト × 3タイル分: 12種程度
- 中央タイル（接続部）と左右タイル（収穫ブレード）でデザインを分ける
- 動作アニメ（収穫時の刈刃回転など）

**ローダーステーション / アンローダーステーション（1×1 地上層、向きなし）:**

- 静止スプライト: 1種ずつ（無向のため4方向対応不要）
- 動作アニメ: ローダーは「伸びるフォークアーム」、アンローダーは「倒れるサイドシュート」（§5.8 参照）
- 動作方向は実行時に「台車のいる側 ↔ 対象エンティティ側」で動的に決まるため、アーム/シュートを4方向に伸ばす派生スプライトが必要（または1方向作って回転/反転で対応）

**マニュア・スプレッダー（台車アタッチメント、後方接続）:**

- 4方向別スプライト: 4種
- 散布ディスク回転アニメ
- 散布粒子エフェクト

**動力系:**

- 水車: 静止 + 回転アニメ
- シャフト: 直線2 + 90度4 + 回転アニメ
- クラッチ: ON / OFF の2状態
- ウインチ: 静止 + 回転アニメ

**補助エフェクト:**

- アイテムアイコン浮遊（残渣・作物・堆肥の各色違い）
- 収穫時の小エフェクト（葉が散る等）
- 散布時の粒子エフェクト

|---|---|---|
