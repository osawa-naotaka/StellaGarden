# 肥料生産自動化システム設計

> **位置づけ**
>
> 本ドキュメントは、`doc/05_CULTIVATION.md` の肥料体系と `doc/17_AUTOMATION.md` の自動化設計を接続し、  
> **堆肥を中心とした肥料生産・物流・施肥の自動化**を具体化する正式設計書である。
>
> ただし、本書には **MVP で実装する範囲** と **将来拡張として残す範囲** が混在するため、以下のルールで読むこと。
>
> - **正式方針として採用済み**
>   - ホッパー的な瞬間移動物流は導入しない
>   - 物流は台車・ループ・ステーションで視覚的に表現する
>   - 動力源は水車を中心とする
>   - 肥料自動化の主対象はまず **堆肥ライン**
> - **MVP で実装対象**
>   - 堆肥ラインの半自動化
>   - 共有チェストによるループ間受け渡し
>   - ローダー / アンローダー / マニュア・スプレッダー
> - **将来拡張**
>   - カムやピンシリンダーによる高度制御
>   - 水流搬送
>   - ケーブルクロス
>   - アイテム種フィルタ
>
> したがって、本書は正式設計書ではあるが、**全記述が即MVP実装対象という意味ではない**。  
> MVP の境界は本文中の「スコープ」「将来実装」節を優先すること。

> 本ドキュメントは `doc/05_CULTIVATION.md`（堆肥体系）と `doc/17_AUTOMATION.md`（ケーブル牽引システム）の設計を踏まえ、肥料（特に堆肥）の生産を自動化するための具体的な設計をまとめたものである。

## 1. 設計方針

### 1.1 背景

- 現状の肥料体系（`doc/05`）では、堆肥は**有機物×10 → 堆肥×1、発酵3日**という高コストな生産レシピが設定されている
- 輪作のためにひまわりを育て、刈り取って作物残渣を得、堆肥場で発酵させ、完成した堆肥を畑に撒く、という工程が手作業では大きな負担
- 草木灰のルートは比較的軽量だが、樹木供給に制約がある（持続的な植林が必要）
- いずれにせよ肥料生産は**自動化の価値が高い**領域であり、中盤の主要な自動化ターゲットとなる
- 手作業でも回るが、面積が広がるにつれ破綻する → 自動化への動機

### 1.2 基本原則

- 動力源は**水車**のみ（`doc/17` と共通）
- 物流は**台車＋ケーブル**で行う。マイクラ的な「ホッパーで自動的にアイテムが移動する」抽象機構は導入しない
- **全ての物流は物理的に視認できる**（台車が走り、積み、降ろす姿が見える）
- 抽象的な分類機・フィルタ機能は最小限。**現実の農機具の類推で成立する範囲**でメカニクスを組む
- 点と点の搬送が必要な場合、**ループを交差させず、共有チェスト（ステーション）で乗り換える**

### 1.3 「ホッパーを導入しない」設計思想

マイクラのホッパーのような「タイル間で自動的にアイテムが瞬間移動する」機構は、StellaGarden では**意図的に採用しない**:

- 台車が物理的にアイテムを運ぶ様子が「眺める楽しさ」の核になる
- チルな雰囲気との整合性（急がない・機械的でない・のんびり）
- 世界観（水力時代・前近代技術）との一致
- 結果として、**物流はすべて台車の巡回として実装される**

### 1.4 スコープ

**MVP（本設計で実装するもの）:**
- 堆肥ライン（作物残渣 → 堆肥場 → 施肥）の半自動化
- 必要なアタッチメントとエンティティの追加
- 共有チェストによる「ステーション乗り換え」方式
- 「容量ベースで自然に流れる」物流ルール
- プレイヤーのレイアウト責任によって混在を避ける設計

**MVP スコープ外（将来実装）:**
- 水流搬送（フルーム）— ノーリアによる揚水が前提のため後半実装
- 陸橋エンティティ（ケーブルのクロス）— 第二段階で追加
- カム・ピンシリンダーによる自動プログラミング
- アイテム種フィルタ機能（台車の特化）
- 草木灰ラインや油粕ラインの本格自動化
- 複数ループの高度な優先制御

**補足:**
- 本書で扱う「肥料自動化」は、まず **堆肥** を中心に設計する
- `doc/05_CULTIVATION.md` にある肥料体系全体（堆肥・草木灰・油粕）のうち、MVP で自動化対象として深く扱うのは堆肥ラインのみ
- 草木灰や油粕は、将来的に同じ物流原則へ接続できるように設計思想だけ揃えておく

## 2. エンティティ層の整理

`doc/17` に既出のエンティティと本設計で追加するエンティティを、**2つのレイヤ**に整理する。

| レイヤ | 性質 | 例 | ボクセル表現 |
|---|---|---|---|
| **地上層（Ground）** | 1タイル1個。互いに排他。エンティティ固有の状態ビットを持つ | 堆肥場、ステーションチェスト、炉、作物、畝間水路、導水路、ケーブル | エンティティビット + 各種状態ビット |
| **移動層（Mobile）** | タイル非拘束の動くもの | 台車、プレイヤー | ボクセル外で管理 |

### 2.1 設計の経緯（簡略化の背景）

当初は「同じタイルにチェストとケーブルが共存する」要求を想定して、地上層とは別に**ネットワーク層**という独立レイヤを設ける案を検討していた。しかし、設計を詰める過程で:

- アイテム移動はローダー/アンローダーが**隣接タイル間**で行う方式に決まった
- そのため、チェストとケーブルは**隣接配置で済む**（同タイルに重なる必要がない）
- 既存の畝間水路も「自身の接続ビットを持つ地上層エンティティ」として実装されている
- ケーブルも同じパターンで実装できるため、独立したネットワーク層を設ける必要がない

これらを踏まえ、MVP では**全てのタイル設置物を地上層に統一**する設計を採用する。将来「やはり重ねる必要がある」となれば、その時に分離レイヤを導入できる余地は残しておく。

### 2.2 共存ルール

- **Ground × Ground** は排他（1タイルにつき1エンティティ）
  - 例: チェストと堆肥場は同タイルに置けない
  - 例: ケーブルと畝間水路は同タイルに置けない
- **Mobile × Ground** は共存可（台車は常にタイルの上に乗る）

### 2.3 ケーブル・畝間水路のクロス

- ケーブル × ケーブル、ケーブル × 畝間水路、畝間水路 × 畝間水路 のいずれも、**MVP では同タイル排他**＝**クロス禁止**
- これらのクロスを解決する手段として、将来的に**陸橋エンティティ**（地上層エンティティを上下2層に分離するメカニズム）の実装を予定する
- 陸橋は本設計のスコープ外

### 2.4 ケーブル設置の制約

- ケーブルを設置したタイルは**耕すことができない**（畑と物流経路は排他）
- ケーブルは**端末・直線・90度曲がり**のスプライトを接続状態から自動選択する（`doc/16` の畝間水路と同じロジック）
- **MVP では分岐（T字・十字）は実装しない**。ケーブルは始点と終点を持つ一本道として敷設する
- ケーブルのクロスは **MVP では禁止**。将来的に陸橋エンティティで解禁予定

### 2.5 ケーブル構造: 「一本道」と「ループ」

ケーブルの構造には、本来「真のループ」と「始点・終点を持つ一本道」の2種類がありうる:

| 構造 | 動作 | プレイヤー操作 | 実装難度 |
|---|---|---|---|
| 真のループ | 台車が周回し続ける。停止には自動停止機構（トリップレバー＋クラッチ自動切断）が必要 | クラッチ ON/OFF のみ | 高（自動停止の機構が必要） |
| 一本道 | 台車が始点 → 終点に進み、終端で自然停止。台車を始点に戻すのは手作業 | クラッチ ON/OFF + 終端到達後の台車手動移動 | 低 |

**MVP ではすべてのループを「一本道」として実装する**:

- 自動停止機構（トリップレバー）の実装が不要
- 台車は終点（レールの端末）で物理的に進めなくなり、自然停止する
- プレイヤーがクラッチ OFF にし、台車を始点に戻す
- 物流ループのように「常時走り続ける」運用は MVP では成立しないが、第一段階として畑ループのみを成立させる
- 将来段階的にループ化を進める計画とする（後述）

## 3. 動力系

`doc/17` の動力系をそのまま採用する。本設計では、動力系は**複数のループを独立に駆動**する目的で使う。

```
水車（水タイルに隣接）
  │
  シャフト（メインライン）
  │
  ├─ クラッチA ─ シャフト → ウインチA → 畑ループ（ハーベスター台車）
  │
  ├─ クラッチB ─ シャフト → ウインチB → 物流ループ（残渣/堆肥運搬台車）
  │
  └─ シャフト → 加工機械（搾油プレス等、doc/17参照）
```

**各ループは独立にクラッチ ON/OFF 可能**。プレイヤーは「畑ループだけ回す」「物流ループだけ回す」を選べる。MVP では操作は手動。

### 3.1 クラッチの操作仕様（MVP）

- **サイズ**: 1×1 タイル
- **配置**: シャフトラインの途中
- **操作**: **左クリックで ON / OFF をトグル**
- **見た目**: ON 状態 / OFF 状態の 2 種類のスプライトで状態を表現
- 将来的にカム連動による自動 ON/OFF を追加予定（MVP スコープ外）

### 3.2 ウインチの仕様（MVP）

- **配置**: ケーブル一本道の**終点側に1個**設置する（始点側にはアンカーのみ、ウインチ不要）
- **動作**: シャフトから回転力を受け、ケーブルを巻き取って台車を終点側に牽引する
- **ロープの巻き取り問題**: 現実にはロープが有限なので巻き取り続けると枯渇するが、**MVP ではロープを実質無限として扱う**（巻き取り表現は省略）
- 将来的に「ロープを別の所から再供給する仕組み」や「ループ化による解決」を検討する余地あり

## 4. 台車とアタッチメント

### 4.1 台車の基本構造

- 台車は**ケーブルが敷設されたタイルの上**に配置される移動層エンティティ
- 台車のサイズは**1×1**（カーブでの描画問題を避けるため、MVP では小型固定）
- 台車は**ケーブルの牽引**によって始点から終点へ一方向に進む（MVP は一本道）
- 台車は**インベントリ**を持つ（作物ビン・残渣ビンなど複数ビンを持つ場合あり）
- 台車には**アタッチメント**を装着できる。アタッチメントは作業の種類を決める
- 台車には**前方**と**後方**があり、進行方向に対してアタッチメントの取り付け位置が異なる
  - 後方接続: ハーベスター（収穫した畑が背後になるよう配置）
  - 前方接続: アンローダー、ローダー、マニュア・スプレッダー

### 4.1.1 台車の取り回し（MVPの一本道運用）

一本道運用に伴い、台車を始点に戻す手段が必要:

- 台車は**斧でインタラクト**するとアイテム化してプレイヤーが拾える
- プレイヤーが任意の場所（始点）に再度配置できる
- アタッチメントも同様に拾い直して、再度装着する必要がある
- 1サイクル（数日に1回）の手作業として許容範囲とする
- 将来的にループ化と自動停止機構が実装されれば、この手作業は不要になる

### 4.2 アタッチメント一覧

| アタッチメント | 作業 | 動力要件 | 装着台車 | 備考 |
|---|---|---|---|---|
| プラウ | 耕起 | 牽引のみ | 畑ループ | 既存（doc/17） |
| シードドリル | 小粒種子の植え付け | 牽引 + 車輪回転 | 畑ループ | 既存 |
| ポテトプランター | 種イモの植え付け | 牽引 + 車輪回転 | 畑ループ | 既存 |
| リッジャー | 土寄せ・畝立て | 牽引のみ | 畑ループ | 既存 |
| ハーベスター | 収穫（2ビン出力） | 牽引のみ | 畑ループ | **本設計で仕様拡張** |
| **ローダー** | 隣接タイルの取出面から積み込む | 牽引のみ | 物流ループ、施肥ループ | **新規** |
| **アンローダー** | 隣接タイルの投入面に降ろす | 牽引のみ | 物流ループ | **新規** |
| **マニュア・スプレッダー** | 畑に堆肥を散布 | 牽引 + 車輪回転 | 施肥ループ | **新規** |

### 4.3 ハーベスターの仕様拡張（2ビン出力）

現実世界の脱穀機・コンバインは、脱穀・選別・排藁分離が同じ機械内で行われ、**穀物と藁が別々に排出される**。この仕組みを踏襲し、ハーベスターは**内部で作物と残渣を分離して2つのビンに分ける**。

#### 物理的配置

- ハーベスターは**3×1 サイズ**のマルチタイルアタッチメント
- 台車の**後方**に接続される（台車1×1 + ハーベスター3×1）
- 中央のタイルはレール上にあり、**収穫対象外**（接続部・走行部分）
- 左右の各1タイルが**畑タイルから収穫を行う**
- 1通過につき左右合計**2タイル分**の畑を収穫

```
進行方向 ↑
  [台車 1×1]                       ← レール上
  [H左][H中][H右]                  ← ハーベスター 3×1（後方接続）
  [畑] [線路][畑]                  ← H左・H右が畑から収穫、H中は線路上
   ↑          ↑
  収穫       収穫
```

#### 作物・残渣マッピング（MVP）

各作物について、ハーベスターが**作物ビン**と**残渣ビン**にどう振り分けるかを正式定義する:

| 作物 | 作物ビン | 残渣ビン | 備考 |
|---|---|---|---|
| ジャガイモ | ジャガイモ（本体） | 茎葉 | 茎葉は緑色の地上部 |
| 大豆 | 大豆（豆） | 茎 | 脱穀済み相当 |
| 亜麻 | 亜麻の種 | 亜麻の茎 | 「残渣」と呼ぶには茎は本来主用途品（繊維）だが、MVP では分類の都合で残渣ビン側に格納する |
| ひまわり | ひまわりの種 | ひまわりの茎 | 種は次回の播種用、茎は堆肥原料 |

**亜麻の特例について:**

亜麻は本来「繊維（茎）」が主産物だが、ハーベスター段階では「収穫直後＝脱穀後」のような扱いとし、**作物ビン＝種、残渣ビン＝茎** で振り分ける。亜麻の茎は堆肥原料ではなくレッティングを経て繊維となるが、MVP の物流上は残渣ビンに入れて、別ラインで処理することを想定する（亜麻の繊維加工ラインは将来実装）。

#### 左右マッピングと反転設定

ハーベスター/アンローダーが台車のどちら側のチェストにどのビンの中身を排出するかは、**台車のレベルで設定**する:

- **デフォルト**: 左 = 残渣ビン、右 = 作物ビン
- **反転設定**: 台車に対する設定操作で、左右を入れ替えられる
- レイアウトの都合で「残渣チェストを右側に置きたい」場合に反転できる
- MVP の設定 UI は要検討（左クリックトグル等）

### 4.4 ローダーとアンローダー

**ローダー（積み込み用アタッチメント）:**

- **サイズ**: 1×1
- **配置**: 台車の**前方**に接続
- 台車の左右1タイル先のタイルを検出する
- 隣接タイルに**取出面**を持つ地上層エンティティ（チェスト・堆肥場取出面など）がある時、**台車インベントリに空きがあれば自動的に積み込む**
- 現実世界では 19 世紀の**マニュア・ローダー**や**グラブ・バケット**に相当
- 動力要件: 牽引のみ（構造的にはフォーク/スクープ式を想定）

**アンローダー（降ろし用アタッチメント）:**

- **サイズ**: 1×1
- **配置**: 台車の**前方**に接続
- 台車の左右1タイル先のタイルを検出する
- 隣接タイルに**投入面**を持つ地上層エンティティ（堆肥場投入面・チェスト投入面など）がある時、**投入先に空きがあれば自動的に降ろす**
- 左右に検出した時、**どちら側にどのビンを排出するかは台車の左右マッピング設定**による（4.3 参照）
- 現実世界では**マニュア・ダンパー**や**グレイン・シュート**に相当
- 動力要件: 牽引のみ

**ローダー/アンローダーの同時装着:**

物流ループの台車は通常、**ローダー＋アンローダーを両方装着**する（「積む地点」と「降ろす地点」の両方を通過するため）。どちらが発火するかは**通過中のタイルの隣接エンティティの面**によって決まる（後述のセクション6参照）。

**台車全体の典型的な構成（畑ループの場合）:**

```
進行方向 ↑
  [チェスト]  [アンローダー1×1]  [チェスト]   ← 左右にチェストがある場合
                  [台車1×1]
                  [H左][H中][H右]              ← ハーベスター 3×1
                  [畑] [線路][畑]
```

- アンローダーは台車の前方に位置し、左右のチェストを検出
- ハーベスターは台車の後方に位置し、左右の畑から収穫
- 前後の役割分担により、収穫した作物がチェストに排出される流れが自然になる

### 4.5 マニュア・スプレッダー

- 現実世界の**マニュア・スプレッダー（肥料散布機）** の再現。19世紀末に発明された実在の農機
- 台車インベントリの堆肥を、**通過中の畑タイル（soil/wetSoil）に1タイルずつ散布**する
- 施肥効果を発生させる（`doc/05` の施肥システムと統合）
- 動力要件: 牽引 + 車輪回転（撒き出し機構の駆動）

### 4.6 アタッチメントの視覚・アニメーション設計

俯瞰ピクセルアートの16pxタイル上で、ローダー/アンローダーの動作を**読みやすく表現する**ための設計。俯瞰から見える「横方向の動き」を主軸に、台車の機構そのものを視認可能にする方針とする。

#### 基本方針

- **機構を物理的に見せる**: マイクラのホッパー的な「アイテムが勝手に移動する」抽象表現は使わない。物理的な機構の動きを示す
- **補助エフェクトとしてアイテムアイコンの浮遊**を併用して、何が起きているかを補強する
- **静止時もアタッチメントの存在を視認可能**にする（台車の上に小さなシルエットが常時表示される）
- チルな雰囲気を保つため、動作は**素朴な木製農具**のテイストで統一する

#### ローダー: 伸びるフォークアーム

- 現実世界の**ピッチフォーク / ヘイフォーク**を機械化したような見た目
- 台車の側面に折りたたまれた木製アーム、先端に2〜3本歯のフォーク
- 動作時、アームが隣接タイル方向に伸び、引き戻される

**アニメーション（3フレーム）:**

```
フレーム1:        フレーム2:           フレーム3:
┌───┐              ┌───┐                 ┌───┐
│台車│─             │台車│━━━━━           │台車│━━●
└───┘              └───┘     (伸ばす)      └───┘  (引き戻す)
                                              ↑アイテム
```

1. アーム折りたたみ（通常状態）
2. アームが隣接タイル方向に伸びる
3. アームが引き戻される（アイテムが歯に引っかかってついてくる）

#### アンローダー: 倒れるサイドシュート

- 現実世界の**サイドダンプワゴン / 石臼小屋の粉シュート**のような見た目
- 台車の側面に折りたたまれた小さな木製シュート（滑り板）
- 動作時、シュートが隣接タイル方向に倒れ、その上をアイテムが滑り落ちる

**アニメーション（3フレーム）:**

```
フレーム1:        フレーム2:           フレーム3:
┌───┐              ┌───┐               ┌───┐
│台車│              │台車│╲             │台車│╲
└───┘              └───┘  ╲            └───┘  ╲●
                           ╲                      ↑着地
```

1. シュート折りたたみ（通常状態）
2. シュートが隣接タイル方向に倒れて伸びる
3. シュート上をアイテムが滑り落ちて隣接タイルに着地

#### 補助エフェクト: アイテムアイコンの浮遊

機構のアニメに加えて、**アイテムアイコンが台車と隣接タイルの間を小さく浮遊**する補助エフェクトを常時併用する:

- **ローダー発火時**: アイテムアイコンが隣接タイル → 台車方向に 4〜6px 浮遊移動
- **アンローダー発火時**: アイテムアイコンが台車 → 隣接タイル方向に 4〜6px 浮遊移動
- アイコンは品目ごとに色分け（例: 残渣=緑系、堆肥=こげ茶、ひまわりの種=黄系）

これは Stardew Valley の収穫時のアイテム飛び出しや Factorio のインサータのアイテム保持表示と同系統の、ピクセルアートにおける定番の視覚言語。

#### 静止時のアタッチメント表示

台車に何が装着されているかが一目で分かるように、**静止時も小さなシルエットを台車上に表示**する:

- **ローダー装着中**: 台車の側面に折りたたみアームが見える（1〜2px 突起）
- **アンローダー装着中**: 台車の側面に閉じたシュート板が見える（1〜2px 突起）
- **マニュア・スプレッダー装着中**: 台車の後方に小さな散布ディスクが見える

#### 方向性の扱い

ローダー/アンローダーは**作用する側（台車の左右どちら側のタイルか）** を向きとして持つ:

- **MVP では左右2方向のみ**（ケーブル上の台車の進行方向は固定なので、「左腕」「右腕」の区別で十分）
- スプライトは左右反転で作れるため、画像自体は1方向分だけ用意
- 将来的に複雑なレイアウト（4方向対応）が必要になったら拡張する

#### マニュア・スプレッダーのアニメーション

マニュア・スプレッダーは畑タイル上で連続的に動作するため、ローダー/アンローダーとは異なるアニメーション方針を取る:

- **静止時**: 台車後方に散布ディスク（小さな車輪状の機構）
- **動作時**: 散布ディスクが回転し、畑タイルに**小さな粒子エフェクト**（こげ茶色のドットが散らばる）が発生
- 通過するたびに連続的に撒かれるため、「伸ばす・戻す」型のアニメは不要

これは現実の肥料散布機の「後方の回転ディスクが遠心力で肥料を散布する」挙動に近い（実際の散布機は牽引後方にドラムや回転ディスクを持つ）。

#### サウンド（案）

| アタッチメント | 動作音 |
|---|---|
| ローダー | "scrape" / "scoop"（こすれる音） |
| アンローダー | "thump" / "shuffle"（軽く落とす音） |
| マニュア・スプレッダー | "shhh"（散布する音） |

いずれも控えめな音量で、チルな雰囲気を壊さないこと。

## 5. 方向性を持つ地上層エンティティ

**堆肥場**と**ステーションチェスト**は、投入と取り出しを区別するために**方向性**を持つ。

### 5.1 統一ルール

向きを持つ地上層エンティティは、**1つの方向ビット**（N/S/E/W の2bit）を持つ:

- **指定した向き側の辺 = 取出面**（ローダーが作用する側）
- **反対側の辺 = 投入面**（アンローダーが作用する側）
- 残り2辺は**不活性**（どちらも作用しない）

### 5.2 堆肥場（2×2マルチタイル）

| 項目 | 仕様 |
|---|---|
| 占有サイズ | 2×2 タイル |
| 方向 | 1つの向きを持つ（2bit） |
| 投入面 | 指定向きの反対側の辺（2タイル分） |
| 取出面 | 指定向き側の辺（2タイル分） |
| 内部状態 | 未発酵原料カウンタ、発酵進行度、完成堆肥カウンタ |

**動作:**

- 投入面に隣接した台車が**アンローダー**装着で通過すると、残渣を最大10個まで投入（容量ベース）
- 10個貯まると**発酵開始**（3日間）
- 完成後、取出面に隣接した台車が**ローダー**装着で通過すると、堆肥を積み込み

### 5.3 ステーションチェスト（1×1）

| 項目 | 仕様 |
|---|---|
| 占有サイズ | 1×1 タイル |
| 方向 | 1つの向きを持つ（2bit） |
| 投入面 | 指定向きの反対側（1辺） |
| 取出面 | 指定向き側（1辺） |
| 不活性面 | 残り2辺（両サイド） |
| 容量 | 所定のスタック数（要決定） |

**用途:**

- 畑ループと物流ループの**乗り換え点**として使用
- 畑ループの台車がアンローダーで残渣をチェストに投下、物流ループの台車がローダーで積み取る
- 方向を設定することで、どちら側のケーブルから投入され、どちら側のケーブルに取り出されるかが決まる

**将来の拡張（スコープ外）:**

- 4辺を独立に設定できる「ハブチェスト」への拡張は将来の検討事項
- MVP では1方向指定で十分

### 5.4 堆肥場とチェストの共通ルールの価値

両エンティティが同じ「向きモデル」に従うことで、**物流システムの挙動が1つのルールで記述可能**になる（次節参照）。

## 6. 物流の発火ルール

> **正式方針**
>
> 物流の発火は、複雑な条件分岐やプログラム記述ではなく、  
> **隣接面の種別 × 台車の装着アタッチメント × 容量状態** の組み合わせで決まる。
>
> これは MVP における重要な設計方針であり、
>
> - プレイヤーが理解しやすい
> - 見た目と挙動が一致する
> - チルな雰囲気を壊さない
> - 後から高度制御を追加しても土台を壊さない
>
> という利点を持つ。

台車の通過時に発生する積み込み・降ろし動作は、以下の**単一ルール**で記述できる:

```
台車がタイルTを通過した時:
  - Tに隣接する地上層エンティティを4方向について調べる
  - 隣接面が「取出面」 かつ 台車がローダー装着 かつ 台車に空きあり
      → ローダー発火（容量ベースで積む）
  - 隣接面が「投入面」 かつ 台車がアンローダー装着 かつ 投入先に空きあり
      → アンローダー発火（容量ベースで降ろす）
  - 上記以外 → 素通り
```

### 6.1 容量ベースの動作

- **堆肥場の投入面**: 原料カウンタが10未満なら不足分だけ投入を受け付ける。10に達したら発酵開始し、以降投入不可
- **堆肥場の取出面**: 完成堆肥がある場合のみ取り出し可能
- **チェストの投入面**: 容量上限まで受け入れる
- **チェストの取出面**: 在庫がある限り取り出し可能

**プレイヤーはカムやプログラミングを書く必要がない**。容量制約だけで「空いているところに自動で流れる」挙動が成立する。

### 6.2 アイテム種の扱い（MVPではレイアウトで解決）

- **MVPでは台車のインベントリにアイテム種別フィルタを持たせない**
- 別種のアイテムが混ざらないようにするのは**プレイヤーのレイアウト責任**
- 混ざった場合の挙動は「意図しない物が投入される」可能性があるが、MVPでは自己責任
- 将来、実プレイで頻繁に事故が起きるようならフィルタ機能の追加を検討

この方針は、フィルタインサータ的な「記号的なルール設定」を避けるためでもある。台車の挙動は**物理的な通過と容量**だけで決まり、世界観に馴染む。

**MVP境界の明確化:**
- ここでいう「自己責任」は、設計ミスをゲームオーバー級の罰にするという意味ではない
- あくまで「レイアウトの工夫が必要」というパズル性を残すための方針である
- 実プレイでストレスが大きすぎる場合は、将来拡張としてフィルタや優先制御を追加する余地を残す

## 7. 肥料自動化ラインの全体構成

> **MVPでの読み方**
>
> この章では 3ループ構成を提示しているが、これは「最終的に目指す完成形」に近い図でもある。  
> MVP 実装では、この全体像を一度に完成させる必要はない。
>
> 優先順位としては以下を想定する。
>
> 1. **畑ループ A の一本道実装**（MVP 第一段階）
> 2. 残渣を集める
> 3. 堆肥場へ運ぶ
> 4. 完成堆肥を取り出す
> 5. 畑へ撒く
>
> つまり、**ループA・B・C を概念上は分けつつ、実装は段階的に進める**。
>
> なお MVP では、**全ループを「一本道」として実装する**（セクション 2.5 参照）。  
> 「ループ」という名称は使い続けるが、構造としては始点と終点を持つ一方向の道である。  
> 台車を始点に戻す手段はプレイヤーが斧で台車をアイテム化して持ち運ぶ方式を取る（セクション 4.1.1 参照）。

### 7.1 3ループ構成

MVP で組む肥料自動化ラインは、以下の **3つのループ**から成る。各ループは水車から独立した動力分岐を持ち、ウインチで駆動される。

#### ループ A: 畑ループ（収穫側）

- 畑の周囲に敷設されたループケーブル
- **ハーベスター装着の台車**が周回
- 畑上で作物＋残渣を2ビンに分離して収穫
- ループ上の**作物排出ステーション**で作物ビンの中身を作物チェストに排出（アンローダー装着）
- ループ上の**残渣排出ステーション**で残渣ビンの中身を残渣チェストに排出（アンローダー装着）

※ 排出ステーションは別タイルにする（1ループ内で作物と残渣を物理的に別の場所に降ろす）。これにより「チェストにアイテム種別を指定する」という抽象ルールが不要になる。

#### ループ B: 物流ループ（残渣→堆肥場→堆肥チェスト）

- 残渣チェスト・堆肥場・堆肥チェストの周囲に敷設されたループケーブル
- 台車B1（**ローダー＋アンローダー**装着）が周回:
  1. 残渣チェストの取出面 → ローダー発火、残渣を積む
  2. 堆肥場の投入面 → アンローダー発火、残渣を降ろす
  3. 堆肥場の取出面 → ローダー発火、完成堆肥を積む
  4. 堆肥チェストの投入面 → アンローダー発火、堆肥を降ろす

※ 同じ台車が残渣と堆肥の両方を運ぶのは混在リスクがあるため、**専用台車を2台配置**する運用も可（1台は残渣専用、もう1台は堆肥専用）。これはレイアウト次第。

#### ループ C: 施肥ループ（堆肥→畑）

- 堆肥チェストと施肥対象の畑の周囲に敷設されたループケーブル
- 台車C（**ローダー＋マニュア・スプレッダー**装着）が周回:
  1. 堆肥チェストの取出面 → ローダー発火、堆肥を積む
  2. 畑タイルの上を通過 → マニュア・スプレッダー発火、堆肥を撒く

※ 施肥ループは畑ループと同じ領域を周回するため、**両ループを畑の周囲に二重に敷く**か、**時期によって使い分ける**かのレイアウト設計が必要。

### 7.2 全体図

```
             ┌─── [畑ループ A: ハーベスター台車] ───┐
             │                                        │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │                                        │
             └──[作物★]──[残渣★]──[堆肥★]─────────┘
                 │         │         │
                 ↓         ↓         ↑
                作物     ┌[残渣★]   [堆肥★]┐
                チェスト │   │         │   │
                         │   ↓         ↑   │
                         │ [堆肥場 投入→取出] │
                         │                  │
                         └─[物流ループ B]───┘

             ┌─── [施肥ループ C: スプレッダー台車] ───┐
             │                                        │
             │   畑畑畑畑畑畑畑畑畑畑畑畑畑畑         │
             │   ...                                  │
             │                                        │
             └────────────[堆肥★]────────────────────┘
                              ↑
                           物流ループBと共有
```

★ = 共有ステーションチェスト（2ループが両脇を通る乗り換え点）

### 7.3 レイアウトの自由度と制約

- **クロス禁止**のため、各ループは交差しないようにレイアウトする必要がある
- **共有チェスト**によりループ間でアイテムを受け渡す
- 畑ループと施肥ループが同じ畑領域を回るため、**二重に敷設する**か**時期分離**するかの設計判断が生まれる
- これがプレイヤーにとってのレイアウトパズルとなる

## 8. ボクセルデータ構造の拡張

### 8.1 既存の割り当て（参考）

- bits 0-7: 地形タイプ
- bits 8-15: 地上エンティティ
- bits 16-18: 作物育成カウンタ
- 既に 64bit に拡張済みのため、余裕は十分

### 8.2 本設計で追加するビット（案）

ケーブルは**畝間水路と同じく地上層エンティティ**として実装するため、追加で必要なのはエンティティ固有の状態ビットのみ。

| 用途 | ビット数 | 備考 |
|---|---|---|
| ケーブルの接続状態（上下左右） | 4bit | 畝間水路と同じロジック |
| 地上層エンティティの向き（N/S/E/W） | 2bit | 堆肥場・チェストなど方向性を持つエンティティ用 |

**設計指針:**

- ケーブル・畝間水路・導水路はそれぞれ**別個のエンティティ値**として登録される（同タイルには1種のみ存在）
- 各エンティティ種別ごとに、必要に応じて固有の状態ビット（接続状態など）をボクセル内に配置する
- 64bit の余裕の中で、地上層エンティティが必要に応じて状態ビットを使う方針
- 具体的なビット配置は実装時に決定する

## 9. 新規エンティティ・アイテム一覧

### 9.1 新規エンティティ

すべて**地上層エンティティ**として登録する。

| エンティティ | 備考 |
|---|---|
| ケーブル | 自身の4方向接続ビットを持つ。MVP では端末4＋直線2＋90度4＝**10種**（T字・十字は不要） |
| ステーションチェスト | 向きビット2、容量あり、4方向別スプライト |
| 堆肥場（方向性付き 2×2） | 既存仕様を拡張、向きビット2、状態スプライト（空・原料投入中・発酵中・完成） |
| 水車 | doc/17 既出。回転アニメ |
| シャフト | 直線2＋90度4 ＝ 6種、回転アニメ（駆動中の動きを示す） |
| クラッチ | 1×1。ON/OFF の2状態スプライト。左クリックでトグル |
| ウインチ | 1×1。終点側に1個配置。回転アニメ（駆動中） |

### 9.1.1 必要スプライトの詳細

**ケーブル（地上層、MVP分）:**

- 直線（縦・横）: 2種
- 90度曲がり: 4種（4方向）
- 端末（行き止まり）: 4種（4方向）
- 計 **10種**（接続状態から自動選択）

**台車（移動層）:**

- 4方向別スプライト（上下左右）: 4種
- 直線移動アニメ: 各方向の前進フレーム
- 直角曲がりアニメ: 90度回転の中間フレーム
- ピックアップ用アイテムスプライト（斧でアイテム化された状態）: 1種

**ハーベスター（3×1 アタッチメント）:**

- 4方向別スプライト × 3タイル分: 12種程度
- 中央タイル（接続部）と左右タイル（収穫ブレード）でデザインを分ける
- 動作アニメ（収穫時の刈刃回転など）

**ローダー / アンローダー（1×1 アタッチメント、前方接続）:**

- 4方向別スプライト: 4種ずつ
- 静止スプライト + 動作アニメ（4.6 参照）
- 装着時の台車上の小シルエット表示

**マニュア・スプレッダー（前方接続）:**

- 4方向別スプライト: 4種
- 散布ディスク回転アニメ
- 散布粒子エフェクト

**動力系:**

- 水車: 静止 + 回転アニメ
- シャフト: 直線2 + 90度4 + 回転アニメ
- クラッチ: ON / OFF の2状態
- ウインチ: 静止 + 回転アニメ

**補助エフェクト:**

- アイテムアイコン浮遊（残渣・作物・堆肥の各色違い）
- 収穫時の小エフェクト（葉が散る等）
- 散布時の粒子エフェクト

### 9.2 新規アタッチメント

| アタッチメント | 必要素材（案） | 備考 |

> **整理方針**
>
> 以下の項目は、
>
> - すでに正式方針として固まっているもの
