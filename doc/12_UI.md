# UI設計書 - Stella Garden

> 本ドキュメントは旧UI仕様を、より新しい設計方針に合わせて整理し直したものである。  
> 特に `15_RE_SYNOPSIS.md`、`16_IRRIGATION.md`、`17_AUTOMATION.md`、`20_FORGE.md` の内容を優先し、旧仕様との矛盾を解消している。

---

## 1. UI設計の基本方針

### 1.1 目標

Stella Garden の UI は、以下を満たすことを目標とする。

- **チルで圧迫感がない**
- **農業・加工・自動化の状態が直感的にわかる**
- **操作体系が一貫している**
- **複雑な内部計算をそのまま見せず、プレイヤーには意味のある情報だけを見せる**
- **手動作業から半自動化・自動化へ進んでも、UIの思想が破綻しない**

### 1.2 基本思想

- フィールド上の操作は、できるだけ **「選択中の道具/アイテムを対象に使う」** で統一する
- UI ウィンドウは中央ダイアログではなく **右からスライドインするサイドバー** として、世界が常に見える状態を保つ
- 施設UIは、できるだけ **インベントリUIの派生形** として統一する
- 自動化設備は、複雑な設定画面よりも **配置・接続・見た目の状態** で理解できるようにする
- プレイヤーを急かす通知や警告は最小限にし、必要な情報だけを静かに提示する

### 1.3 実装上の方針（ハイブリッド構成）

UI は描画系を 2 系統に分ける:

| 描画対象 | 技術 | 理由 |
|---|---|---|
| 世界（地形・キャラ・配置プレビュー・ホバー強調） | PixiJS canvas | リアルタイム描画・カメラ追従が必要 |
| ウィンドウUI（インベントリ・施設UI・通知・ツールバー） | React + HTML/CSS | スタイル統一・アクセシビリティ・レイアウト柔軟性 |

両者は同じ engine 状態（インベントリ、UIState、各 Storage）を読み、**世界は ticker 駆動・UI はイベント駆動** という役割分担になっている。

詳細な実装は `doc/07_RE_ARCHETECTURE.md` および `doc/13_RE_RE_ARCHETECTURE.md` を参照。

## 2. 画面構成

## 2.1 メイン画面

ゲーム中に常時表示される基本画面。

- 中央: フィールド（PixiJS canvas）
- 左上: プロパティビュー（ホバーしているタイルの情報。クリック貫通で常時表示）
- 下部中央: ツールバー
- 右側: サイドバーパネル（必要に応じてスライドインで表示）

```
┌──────────────────────────────────────────────┬─────────────────┐
│ [Property]                                    │                 │
│  hovered tile info                            │                 │
│                                               │  Sidebar Panel  │
│              フィールド                       │  (slide-in,     │
│                                               │   full height)  │
│                                               │                 │
│                                               │  必要に応じて   │
│                                               │  右から         │
│                  ┌──────────────┐             │  スライドイン   │
│                  │  ツールバー  │             │                 │
│                  └──────────────┘             │                 │
└──────────────────────────────────────────────┴─────────────────┘
```

### 2.2 サイドバーパネル

すべてのウィンドウUI（インベントリ・チェスト・炉・転移ゲート・将来の NPC 会話やチュートリアル）は **画面右側からスライドインするサイドバー** として表示される。

特徴:
- 画面右端に固定、**フルハイト**
- 開いている間も世界は左側に見えており、チル感を保つ
- アニメーション: 220ms `cubic-bezier(0.2, 0.8, 0.2, 1)` の `transform: translateX(...)` で右からスライド
- 同時に開けるパネルは 1 つのみ（`UIState.mode` で排他管理）
- `Escape` または `×` ボタンで閉じる
- 開いている時、世界（canvas）への直接操作は無効

サイドバー内のレイアウトは縦スタック構造で、各UIで内容セクションが異なる。

### 2.3 PanelRegistry による UI 拡張

サイドバーに表示するパネルは **自己登録方式** で管理される（`src/react-ui/PanelRegistry.tsx`）。

新しいパネルを追加する手順:
1. `src/view/UIState.ts` の `UIMode` に新しいモード名を追加
2. `src/react-ui/panels/<Name>Panel.tsx` を新規作成し、ファイル末尾で `registerPanel({ mode, component })` を呼ぶ
3. `src/react-ui/SgUiRoot.tsx` の import 一覧に 1 行追加（副作用 import）

`SgUiRoot` の Dispatcher は登録済みパネルを iterate して描画するため、編集不要。NPC 会話・ヘルプドキュメント・チュートリアル等もこの仕組みで追加できる。

### 2.4 フィールド画面の役割

フィールド画面は単なる背景ではなく、ゲームの中心である。

ここでプレイヤーは:

- 移動する
- 地形を見る
- 作物の状態を見る
- 水路や水門の状態を見る
- 施設をクリックする
- 道具を使う
- 配置プレビューを見る
- 自動化設備の動作を眺める

つまり、**ほぼ全てのゲームプレイの基盤**となる。

## 3. 操作体系

## 3.1 基本操作

| 操作 | 入力 | 備考 |
|---|---|---|
| 移動 | `W/A/S/D` または矢印キー | 斜め移動時は速度正規化 |
| ズームイン/アウト | マウスホイール | 段階的ズーム |
| インベントリ開閉 | `E` | UIを閉じる操作も兼ねる |
| キャンセル | `Escape` | ピックアップ中断、配置キャンセル、UIクローズなど |
| スロット選択 | 数字キー or 左クリック | 実装詳細は調整可 |
| フィールド上の主操作 | 左クリック | 施設UIを開く、配置確定など |
| フィールド上の道具使用 | 右クリック | 選択中アイテム/道具の使用 |

### 3.2 左クリックと右クリックの役割分担

最新方針では、役割を以下のように整理する。

#### 左クリック
- UI上の選択・決定
- 施設UIを開く
- 配置モード中の配置確定
- 一部施設への primary interact

#### 右クリック
- 選択中の道具/アイテムをワールドに使う
- 農作業
- 地形操作
- 植え付け
- 水やり
- 施肥
- 収穫
- 撤去

この分担により、**「左クリックは選択・開く」「右クリックは使う」** という一貫性を持たせる。

## 4. フィールド上のインタラクト

## 4.1 基本ルール

フィールド上で右クリックしたとき、選択中の道具/アイテムと対象タイルの状態に応じて処理が決まる。

処理の優先順位の考え方は以下。

1. 対象エンティティへの操作
2. 選択中アイテムの使用
3. 地形への操作

これは内部実装の Registry 方針とも整合する。

## 4.2 主な右クリック操作

| 選択中 | 対象 | 効果 |
|---|---|---|
| くわ | 草地/土系地形 | 耕地にする |
| じょうろ | 作物の植わった耕地 | 水やりする |
| 肥料 | 耕地/湿った耕地 | 施肥する |
| ジャガイモ | 耕地 | 植え付ける |
| 大豆 | 耕地 | 植え付ける |
| 亜麻の種 | 耕地 | 植え付ける |
| ひまわりの種 | 耕地 | 植え付ける |
| シャベル | 成熟ジャガイモ | 収穫する |
| シャベル | 成熟亜麻（繊維用） | 引き抜き収穫する |
| 鎌 | 成熟大豆 | 収穫する |
| 鎌 | 成熟ひまわり | 収穫する |
| 鎌 | 成熟亜麻（種子用） | 刈り取り収穫する |
| 斧 | 樹木 | 伐採する |
| ピッケル | 隕鉄・石・対象施設 | 採掘/撤去する |
| 土 | 地面 | 土を盛る |
| シャベル | 地面 | 土を掘る |

### 4.3 旧仕様からの整理ポイント

旧仕様では、以下のような古い前提が混在していた。

- `waterSource` を直接UI仕様に書いている
- 施設撤去の対象が古い
- 鍛造フローが旧仕様前提
- UIモードの整理前の記述がある

これらは最新方針に合わせ、以下のように整理する。

- 水は「水タイル」として扱い、旧来の水源ブロック前提の説明はUI仕様から外す
- 施設ごとの詳細な撤去条件は、UI仕様ではなく各施設仕様に委ねる
- 鍛造は `20_FORGE.md` の炉UI前提で整理する
- UIモードは `normal / inventory / craft / placement / chest / forge` を前提にする

## 5. ツールバー

## 5.1 役割

ツールバーは、プレイヤーが今すぐ使う道具・アイテムを保持するUIである。

- 常時表示
- 画面下部中央
- 選択中スロットを強調表示
- フィールド操作と直結

## 5.2 スロット構成

- 9スロットを基本とする
- `hand` 相当の素手スロットを含むかどうかは実装依存だが、UI上は「何も持っていない状態」を明示できる必要がある
- 各スロットには以下を表示する
  - アイコン
  - 個数
  - 選択状態
  - 必要に応じて耐久や状態

## 5.3 表示ルール

各スロットには以下の視覚情報を持たせる。

- 通常: 標準枠
- 選択中: 明るい枠・太い枠
- 空スロット: 薄い背景
- スタックあり: 右下に個数表示
- 使用不可状態: 必要なら半透明化

## 6. インベントリUI

## 6.1 概要

`E` キーで開閉する基本UI。**右側からスライドインするサイドバー** として表示される。
クラフト UI も同じパネルに統合されており、`hand` クラフトステーション（素手レシピ）が使える。
作業台を左クリックで開いた場合は、同じパネル構造でステーションだけが `workbench` に切り替わる。

## 6.2 レイアウト

サイドバー内は縦スタック構造:

```

│                                  │
│ ┌──┬──┬──┬──┬──┬──┐              │  ← レシピグリッド（6×4 = 24/page）
│ │  │  │  │  │  │  │              │
│ ├──┼──┼──┼──┼──┼──┤              │
│ │  │  │  │  │  │  │              │
│ └──┴──┴──┴──┴──┴──┘              │
│ [Prev]  1 / N  [Next]            │  ← ページネーション
│                                  │

`hand` ステーション時はタイトルが「Inventory & Craft」、`workbench` ステーション時は「Workbench」と表示される。

## 6.3 スロット操作

| 操作 | 入力 | 効果 |
|---|---|---|
| 全量ピックアップ | 左クリック | スロットの中身を全て持つ |
| 全量配置/交換 | 左クリック | 持っているものを置く/交換する |
| 1個ピックアップ | 右クリック | 1個だけ持つ |
| 1個配置 | 右クリック | 1個だけ置く |
| キャンセル | `Escape` | 元スロットに戻す |
| UIを閉じる | `E` | ピックアップ中なら戻す |

### 6.4 基本ルール

- ピックアップ中のアイテムはカーソル追従表示
- 元スロット情報を保持し、キャンセル可能
- スタック可能な場合は自動で積む
- 不正な配置先には置けない

## 7. UIモード

最新方針では、UI状態をモードとして整理する。

## 7.1 モード一覧

| モード | 内容 |
|---|---|
| `normal` | 通常プレイ中 |
| `inventory-craft` | インベントリ + クラフトUI（hand または workbench ステーション）表示中 |
| `placement` | 配置モード |
| `chest` | チェストUI表示中 |
| `forge` | 炉UI表示中 |
| `warp_gate` | 転移ゲートUI表示中 |

クラフトステーションは `UIState.craftStation`（`"hand"` または `"workbench"`）で区別する。`E` キーで開いた場合は `hand`、作業台クリックで開いた場合は `workbench` になる。

## 7.2 モードごとの基本挙動

### `normal`
- フィールド操作可能
- ツールバー表示
- 通常の移動・右クリック操作が有効

### `inventory-craft`
- インベントリ + クラフトサイドバー表示
- ステーション（`hand` / `workbench`）でレシピ一覧が切り替わる
- フィールドへの直接操作は無効
- スロット操作・レシピ選択・クラフト実行が有効

### `placement`
- 配置プレビュー表示
- 左クリックで配置確定
- `Escape` でキャンセル

### `chest`
- チェスト内容とインベントリを同時表示
- アイテム移動が可能

### `forge`
- 炉スロットとインベントリを同時表示
- 原材料・燃料・結果の管理が可能

### `warp_gate`
- 転移ゲートUI表示
- プレイヤーインベントリ・地球側インベントリ・評価値・アンロック進行状況を同時表示
- フィールドへの直接操作は無効

## 8. 配置モード

## 8.1 概要

配置可能アイテムを選んだ状態で配置モードに入る。  
これは施設・設備・将来的な水路や自動化設備にも共通する基本UIである。

## 8.2 表示内容

- カーソル追従の半透明プレビュー
- 配置可能位置: 緑表示
- 配置不可位置: 赤表示
- 必要に応じて占有範囲の表示
- 向きを持つ設備では向きのプレビュー表示

## 8.3 操作

| 操作 | 入力 |
|---|---|
| 配置確定 | 左クリック |
| キャンセル | `Escape` |
| 向き変更 | 将来追加候補（例: `R`） |

## 8.4 配置条件の見せ方

プレイヤーに内部ルールをそのまま見せるのではなく、以下のように視覚で伝える。

- 高さ不一致 → 赤
- 他エンティティと衝突 → 赤
- 地形不適合 → 赤
- 設置可能 → 緑

これにより、説明文を読まなくても置ける/置けないがわかるようにする。

## 9. クラフトUI

## 9.1 基本方針

クラフトUIはインベントリパネル（§6）に**統合**されており、独立したダイアログを持たない。
プレイヤーが「持ち物を見る」と「作る」を同じパネル内で連続的に扱えるようにする。

## 9.2 ステーション

クラフトステーションは `hand` / `workbench` の 2 種類。`UIState.craftStation` で管理される。

| ステーション | 開き方 | 表示レシピ |
|---|---|---|
| `hand` | `E` キー | 素手で作れるレシピのみ |
| `workbench` | 作業台を左クリック | 全レシピ（素手 + 作業台） |
| 将来の加工施設 | 対応する施設をクリック | 各ステーション固有のレシピ |

## 9.3 構成要素

サイドバー上部から順に:

1. **ツールスロット** — レシピが要求するツールを差し込むスロット（独立した 1 マス）
2. **レシピグリッド** — 6×4 = 24 レシピ/ページ。ページネーション付き
3. **選択中レシピの詳細** — 必要素材、要求ツール、成果物を一覧表示
4. **インベントリ + ツールバー** — プレイヤー所持品（§6 と同じ）

## 9.4 レシピ表示ルール

- 作成可能: 通常表示
- 素材不足 or ツール不足: 半透明（透明度 0.4）
- 選択中: 枠強調
- 成果物個数 ≥ 2: アイコン右下に個数を重ねて表示

## 9.5 操作

| 操作 | 入力 | 効果 |
|---|---|---|
| レシピ選択 | 左クリック | 詳細表示 |
| 1個クラフト | 右クリック | 選択 + 即時作成（`canCraft` 通過時のみ） |
| ツールスロット | 左クリック | ツールアイテムの取り出し/差し込み（ツール類のみ受け付け） |
| ページ遷移 | Prev / Next ボタン | 24 件単位で前後にページ送り |
| UIを閉じる | `E` または `×` または `Escape` | 閉じる |

## 11. 炉UI

## 11.1 最新仕様での位置づけ

炉UIは `20_FORGE.md` に基づく正式UIである。  
旧仕様の「炉で加熱 → トングで運ぶ → 金床で叩く」を前提にしたUIではない。

現在の正式仕様では:

- 炉に原材料を入れる
- 炉に木炭を入れる
- 日経過で赤熱した隕鉄が生成される
- 金床で刃に変換する

## 11.2 レイアウト

サイドバー内の縦スタック構成:

```
┌──────────────────────────────────┐
│ Forge (burning)        [×]        │  ← burning 中はタイトルに付与
├──────────────────────────────────┤
│ Forge Slots                      │
│   Ingredient   [□]               │  ← meteoric_iron のみ受け入れ
│   Fuel         [□]               │  ← charcoal のみ受け入れ
│   Output       [□]               │  ← hot_meteoric_iron 取り出し

## 12. 転移ゲートUI

### 12.1 役割

転移ゲートは、地球（または他の星系）への出荷の入口である。
プレイヤーが収穫物・加工品を地球側インベントリ（出荷バッファ）に積み、評価値（reputation）に変換する。

このUIは以下を統合した「取引ハブ」として機能する（サイドバー縦スタック）:

- **Reputation セクション**: 評価値 + 出荷プレビュー
- **Earth Inventory セクション**: 地球側インベントリ（出荷バッファ）
- **Tier Progression セクション**: アンロック進行表示
- **Inventory セクション**: プレイヤーインベントリ
- **Toolbar セクション**: ツールバー（hand 除く 9 スロット）

詳細な評価・アンロック設計は `22_REPUTATION_SYSTEM.md` を参照。

### 12.3 地球側インベントリ

- **4行×8列 = 32スロット**
- プレイヤーインベントリと同じピックアップ/配置操作
- ここに積まれたアイテムが「出荷予定品」となる
- 出荷確定で地球に送られ、評価値に変換される

旧来は 8×8=64 スロットだったが、出荷バッファとしては過大であり、下部にアンロック進行表示を確保するため 4×8 に縮小する。

### 12.4 評価値・出荷プレビュー

右上の領域に以下を表示する。

- **現在の累計評価値**: `XX pt`
- **出荷プレビュー**: 地球側インベントリの中身を出荷した場合の獲得ポイント `+YY pt`

これにより、プレイヤーは出荷前に「これを送るとどれだけ得られるか」を確認できる。

### 12.5 アンロック進行表示

評価システム（`22_REPUTATION_SYSTEM.md`）の Tier 進行を、地球側インベントリの下部に**縦リスト**で表示する。

#### 表示方針

- **全 Tier を一覧表示**（ページネーションなし）
  - 8 Tier 程度であれば一画面に収まる
  - プレイヤーが「次の目標」と「全体像」を同時に把握できる
- **並行アンロック**（Tier 3a/3b、Tier 6a/6b）は同階層に **2列** で並べる
  - 「先に 3a を取らないと 3b に進めない」という誤解を防ぐ
- **将来のツリー化に備える**が、初期実装は一直線（並行 Tier のみ2列）に留める

#### 行の構成

各 Tier 行は状態に応じて以下を表示する。

| 状態 | 表示内容 |
|---|---|
| アンロック済 | チェックマーク + 品目アイコン + 累計出荷数 |
| 進行中（次の目標） | 矢印マーク + 品目アイコン + 進捗バー（n/N 個） |
| 未アンロック | 鍵マーク + 品目アイコン（暗色）+ アンロック条件テキスト |

イメージ:

```
[✓] Tier 1   🥔 じゃがいも              出荷済 320個
[✓] Tier 2   🫘 大豆（生）              出荷済 85個
[▶] Tier 3a  🛢️ 亜麻仁油  ← 現在        ████░░░░ 40/100個
[▶] Tier 3b  🛢️ 大豆油                 ░░░░░░░░ 0/100個
[🔒] Tier 4   🧵 糸                     亜麻仁油100個でアンロック
[🔒] Tier 5   🪡 布                     糸XX個でアンロック
[🔒] Tier 6a  📦 袋詰めじゃがいも       布XX個でアンロック
[🔒] Tier 6b  📦 袋詰め大豆 ★          布XX個でアンロック
```

各行は薄い区切り線または背景色で区切り、過度な装飾は避けて静かなロードマップとして見せる。

### 12.6 操作

| 操作 | 入力 | 効果 |
|---|---|---|
| アイテム全量移動 | 左クリック | プレイヤーインベントリ ⇔ 地球側インベントリ |
| アイテム1個移動 | 右クリック | 1個ずつピックアップ/配置 |
| 出荷確定 | 出荷ボタン（将来追加予定） | 地球側インベントリの中身を評価値に変換 |
| UIを閉じる | `Escape` | 通常モードに戻る。ピックアップ中なら元スロットに戻す |

アンロック進行表示そのものは**情報表示のみ**でクリック操作を持たない（フィージビリティ範囲）。

### 12.7 UIモードとの関係

転移ゲートUIは UIモード `warp_gate` として扱う。
- フィールド上の転移ゲートエンティティを左クリックで開く
- `Escape` で閉じる
- 開いている間はフィールドへの直接操作は無効

### 12.8 将来の拡張

- **ツリー型のアンロック表示**: Tier の枝分かれが増えた段階で、横方向の階層構造に変更する
- **取引先別の表示**（`22_REPUTATION_SYSTEM.md` §6.3 と連動）: 取引先タブを追加し、取引先ごとに異なる需要を表示
- **アンロック演出**: 新 Tier 解放時の通知UI（§17. 通知・フィードバック と連動）
- **明示的な出荷ボタン**: 現状は地球側インベントリに置いた時点で評価値に変換される設計だが、明示的な「出荷」アクションを追加する余地がある

## 14. 灌漑設備のUI

## 14.1 基本方針

灌漑設備は、できるだけ専用ダイアログを持たず、**フィールド上の見た目で状態がわかる**ようにする。

対象:
- 水門
- 畝間水路
- 石組み導水路
- 将来のノーリア

## 14.2 水門

水門は開閉状態を見た目で明確に区別する。

- 閉: 板が下りている
- 開: 水が通っている

操作はシンプルに:

- クリックで開閉切り替え
- 将来的にはカムや自動化機構から制御

UIダイアログは不要。

## 14.3 畝間水路・導水路

これらは接続状態と通水状態をスプライトで表現する。

プレイヤーが知りたいのは主に以下。

- つながっているか
- 水が来ているか
- どの方向に伸びているか

そのため、専用ウィンドウではなく、**フィールド上の状態表示が主UI**となる。

## 15. 自動化設備のUI

## 15.1 基本方針

自動化設備は、複雑な設定パネルよりも、以下で理解できるようにする。

- 配置
- 接続
- 向き
- 動作中アニメーション
- 停止状態

## 15.2 プレイヤーが見たい情報

自動化設備について、プレイヤーが知りたいのは主に以下。

- 動力が来ているか
- どこへつながっているか
- 動いているか止まっているか
- 何を運んでいるか
- どこで積み降ろししているか

これらは可能な限り、フィールド上の視覚表現で示す。

## 15.3 例

### 水車
- 回転していれば稼働中
- 止まっていれば非稼働

### シャフト
- 回転アニメーションまたは明滅で動力伝達を示す

### クラッチ
- 接続中/切断中を見た目で区別

### 台車
- 実際に移動する
- 積載物が見える
- ローダー/アンローダーの動作が見える

### 堆肥ライン
- 堆肥場の熟成段階が見える
- 台車が残渣を運ぶ
- 施肥ループが畑を巡回する

## 18. 旧仕様からの主な変更点

この版で整理した主な変更点は以下。

### 18.1 鍛造フロー
- 旧: 炉 → トング → 金床 → ハンマー
- 新: 炉UIで加熱 → `hot_meteoric_iron` → 金床で刃化

### 18.2 水システム
- 旧: `waterSource` をUI仕様に直接書いていた
- 新: UIでは「水タイル」「通水状態」を扱い、内部実装詳細は持ち込まない

### 18.3 UIモード
- 旧: インベントリ/配置中心、`inventory` と `craft` が分かれていた
- 新: `inventory-craft / placement / chest / forge / warp_gate` に整理。`inventory` と `craft` を `inventory-craft` に統合（`craftStation` で hand/workbench 切替）

### 18.4 自動化設備
- 旧: UI設計が未整理
- 新: 専用ダイアログよりフィールド上の視覚表現を重視

### 18.5 報酬設計との整合
- 旧: 会社から設備が来る前提が混ざりやすかった
- 新: プレイヤーが自分で作る前提に統一

### 18.6 UI実装の React 化（フィージビリティ後半）

- 旧: 全UIを PixiJS Container として canvas 上に描画。中央ダイアログ形式でレイアウトを手書き計算
- 新: ウィンドウUIを React + HTML/CSS で実装し、**右からスライドインするサイドバー** に統一
- 駆動方式: PixiJS canvas は ticker 駆動（世界描画）、React UI は engine 状態を直接読みつつ `useFrameTick` で再レンダ（将来的にイベント駆動に置換予定）
- 効果:
  - スタイル統一・フォント・アクセシビリティが改善
  - パネル間の共通要素（Slot, ItemIcon, InventoryGrid, SidePanel）を React コンポーネントとして再利用
  - パネル追加が PanelRegistry の自己登録 1 行で済む
  - 旧 PixiJS UI 約 1400 行が削除され、コード重複が大幅に減少

## 20. まとめ

Stella Garden の UI は、  
**「複雑な農業と自動化を扱うが、見た目と操作は静かでわかりやすい」**  
ことを目指す。

プレイヤーは、画面を開いて数値表とにらめっこするのではなく、

- 畑を見る
- 水が流れるのを見る
- 台車が走るのを見る
- 施設を開いて材料を入れる
- 少しずつ仕組みが回り始めるのを見る

という体験を通して、世界を理解していく。

そのためUIは、情報を詰め込みすぎず、  
**フィールド上の出来事を主役にするための補助線**として設計する。
