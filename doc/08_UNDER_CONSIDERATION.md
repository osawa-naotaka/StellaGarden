## 農作業の自動化システム設計

### 基本方針

**ガジェット連携システム**を採用する。各ガジェットが「入力」と「出力」を持ち、それらを組み合わせることで自動化を実現する。

段階的な実装により、初期は物理シミュレーションなしで範囲型の自動化を実現し、将来的にパイプやケーブルなどの明示的な接続システムを追加可能にする。

### Phase 1: 範囲型自動化（暗黙的連携）

#### 概要
- ガジェット同士が**近接していれば自動的に連携**する仕組み
- 物理的な接続（パイプ、ケーブルなど）の描画は不要
- 各ガジェットは「入力範囲」と「出力範囲」を持つ
- 配置時に依存関係を計算し、動作可否を判定

#### ガジェットの入出力モデル

各ガジェットは以下の属性を持つ：

```
入力 (inputs):
  - リソースタイプ（water, power, cropsなど）
  - 入力受取範囲（マス数）
  - 必須/オプショナル

出力 (outputs):
  - リソースタイプ
  - 出力影響範囲（マス数）
  - 効果（Effect）
```

#### 初期実装ガジェット一覧

**1. 井戸（水源）**
- 入力: power(範囲3マス)
- 出力: water（範囲3マス）
- 効果: 範囲内のガジェットに水を供給
- 備考: 井戸は無限に掘れる。しかし、揚水にはポンプが必要。ポンプは持ち込みのため、実際に揚水可能な井戸数には上限がある。将来的には鉱業の発達により増産が可能。

**2. 発電機（太陽電池）**
- 入力: なし（日中のみ稼働）
- 出力: power（範囲5マス）
- 効果: 範囲内のガジェットに電力を供給
- 備考: 持ち込んだ資源のため、設置可能な数量には上限がある。将来的には鉱業の発達により増産が可能。

**3. スプリンクラー**
- 入力: water（範囲2マス、必須）、power（範囲3マス、オプション）
- 出力: watering（電力あり→5マス、なし→3マス）
- 効果: 範囲内の作物に「水やり済み」状態を付与
- 備考: 電力があると範囲が拡大
- 備考: 持ち込んだ資源のため、設置可能な数量には上限がある。将来的には鉱業の発達により増産が可能。

**4. 自動耕作機**
- 入力: power（範囲3マス、必須）、seeds（インベントリから消費、必須）
- 出力: planting（範囲4マス）
- 効果: 範囲内の耕された土地に種を植える
- 備考: 持ち込んだ資源のため、設置可能な数量には上限がある。将来的には鉱業の発達により増産が可能。


**5. ハーベスター（収穫機）**
- 入力: power（範囲3マス、必須）
- 出力: harvesting（範囲4マス）
- 効果: 範囲内の成長した作物を収穫し、インベントリに追加
- 備考: 持ち込んだ資源のため、設置可能な数量には上限がある。将来的には鉱業の発達により増産が可能。

### 追記2: 稼働率と段階的システム進化の検討

#### 新たな視点：稼働率による最適化

農作業の自動化において、**機械の稼働率**が重要な要素となることが判明した。例えば水やりが1日1回の作業である場合、固定式の水やりガジェットは残りの23時間は稼働しない。これは機械あたりの収量が低く、非効率である。

この課題を解決するため、システムを段階的に進化させることで、プレイヤーが自然に「より効率的な方法」を求めるゲームデザインを実現できる。

#### システム進化の3段階

**Phase 1: 一体型ガジェット（初期）**

- **構成**: センサー + アクチュエータ + 命令が一体となったガジェット
- **利点**:
  - 配置するだけで動作する（理解しやすい）
  - 初期実装コストが低い
  - チュートリアルに最適
- **欠点**:
  - 稼働率が低い（水やりは1日1回 = 約4%稼働）
  - 機械あたりの収量が少ない
  - 多くの機械を配置する必要がある
  - **機械の数に上限があるため、スケールに限界**

→ プレイヤーは「もっと効率よくできないかな？」と自然に感じる

**Phase 2: パイプ分離システム（中期）**

- **構成**: 水やりパイプ + 可動式アクチュエータ + センサーを分離
- **水やりパイプ**:
  - 細いパイプで水を流すだけ（低コスト）
  - 1セルに配置可能（サイズが小さい）
  - 3セル分の範囲に水が飛ぶ
  - 動力不要（重力や水圧で流れる）
- **可動式アクチュエータ**:
  - レール上を移動
  - 複数の場所を巡回して作業
  - 稼働率が大幅に向上（30-50%程度）
- **センサー**:
  - 小型のため各セルに配置可能
  - 「作物が育った」「土地が乾いた」を検知

**配置例**:
```
[センサー][センサー][センサー]
[パイプ━━][パイプ━━][パイプ━━] ← 水は自動で流れる
   ↓レール↓
[アクチュエータ] ← 左右に移動して収穫
```

**Phase 3: レール最適化システム（後期）**

- **構成**: レールネットワーク + 複数の可動式機械 + 高度な命令塔
- **レールシステム**:
  - 複雑なルート設計
  - 複数のアクチュエータが巡回
  - 稼働率が非常に高い（80%以上）
- **高度な命令塔**:
  - 条件分岐（「雨の日は水やり停止」）
  - スケジューリング（「朝は収穫、昼は耕作」）
  - 最適化アルゴリズム（ILP的な自動割り当て）

#### 1セル複数配置システム

各機械・部品に**サイズパラメータ**を設定し、1セルの容量内であれば複数配置を許可する。

**サイズ定義例**:
```typescript
type GadgetSize = 'tiny' | 'small' | 'medium' | 'large'

// 1セルの容量 = 100 とする
const sizeMap = {
  tiny: 10,    // センサー、配線、小型部品
  small: 25,   // パイプ、ケーブル
  medium: 50,  // 小型アクチュエータ
  large: 100,  // 一体型ガジェット（セル専有）
}
```

**配置の例**:
- パイプ(25) + センサー(10) + 配線(10) = 45 → 同じセルに配置可能
- 一体型ガジェット(100) → これだけで1セル専有
- パイプ(25) + センサー(10) + アクチュエータ(50) = 85 → 配置可能

この仕組みにより、プレイヤーは「どう組み合わせれば効率的か」を考える楽しさを得られる。

#### パイプとレールの違い

**水やりパイプ**:
- **動力**: 不要（重力・水圧で流れる）
- **コスト**: 低（鉄パイプ少量）
- **設置**: 簡単（セル上に這わせるだけ）
- **範囲**: 3セル分に散水
- **稼働率への影響**: 水やり作業を自動化し、アクチュエータを他の作業に専念させられる

**レール**:
- **動力**: 必要（電気で動く）
- **コスト**: 中（レール敷設 + アクチュエータ本体）
- **設置**: ルート設計が必要
- **範囲**: アクチュエータが巡回可能な全範囲
- **稼働率への影響**: 1台のアクチュエータで広範囲をカバー、稼働率が大幅に向上

#### ゲームプレイの自然な流れ

**序盤（Phase 1）**:
1. 一体型ガジェットを数個配置
2. 自動化の気持ちよさを体験
3. 「機械が足りない！でも機械は高くて数が限られている…」と気づく

**中盤（Phase 2導入）**:
4. パイプを使った水やりシステムを構築
   - 井戸 → パイプ → 広範囲に水やり
   - アクチュエータは収穫だけに専念できる
5. 「水やりが自動化されたから、アクチュエータ1台で複数箇所を収穫できるのでは？」
6. センサーで「育ったら収穫」のトリガーを設定

**後半（Phase 3発展）**:
7. レール敷設で可動式アクチュエータを本格導入
8. 1台のアクチュエータが広い農場を巡回
9. 複数の司令塔で複雑な作業フローを構築
10. 条件分岐やスケジューリングで最適化

#### 命令塔の役割の進化

**Phase 1（一体型時代）**:
- 命令塔は不要（各ガジェットが自律）
- または、ガジェット自体が簡易的な命令を持つ

**Phase 2（分離時代）**:
- 命令塔が必須
- 「この範囲のセンサーを監視」
- 「作物が育ったらアクチュエータを派遣」
- 「水やりは毎朝6時」
- 範囲内の機械を調整・連携させる

**Phase 3（プログラム時代）**:
- 高度な命令
- 「小麦が3回収穫されたら、次はトマトに切り替え」
- 「雨の日は水やり停止」
- 「収穫量が目標に達したら、新しいエリアの開拓を開始」
- 複数の司令塔間で連携

#### 分離システムを選ぶ必然性

| 方式 | 初期コスト | 機械稼働率 | 機械あたり収量 | 面積あたり収量 | 備考 |
|------|----------|----------|--------------|--------------|------|
| 一体型 | 低 | 低（5-10%） | 低 | 中 | 初期向け |
| パイプ分離 | 中 | 中（30-50%） | 中 | 高 | 水やり効率化 |
| レール分離 | 高 | 高（80%以上） | 高 | 非常に高 | 本格最適化 |

**プレイヤーが分離システムを選ぶ理由**:
- **機械の数に制約がある**（持ち込んだ資源が限られている）
- **稼働率を上げたい**（少ない機械で広い農場を管理したい）
- **面積あたりの収量を最大化したい**（評価を上げたい）

Phase 1 で「機械不足」を体感したプレイヤーが、自然に Phase 2, 3 へと進むゲームデザインとなる。

#### フィージビリティスタディとしての実装優先順位

実際の検証では、以下の順序で段階的に実装し、各段階で「楽しさ」を確認する：

1. **Phase 1: 一体型ガジェット**
   - センサー + アクチュエータ + 命令が一体
   - 周囲3マスに効果
   - **検証ポイント**: 自動化の気持ちよさを体感できるか

2. **Phase 2a: パイプシステム**
   - 1セル複数配置の仕組みを実装
   - 水やりだけでもパイプで分離してみる
   - **検証ポイント**: 稼働率の改善を実感できるか、配置パズルとして面白いか

3. **Phase 2b: 可動式アクチュエータ（レール）**
   - レール上を移動する仕組みを実装
   - **検証ポイント**: 移動する様子が楽しいか、効率化の実感があるか

4. **Phase 3: 高度な命令塔**
   - 条件分岐やスケジューリング
   - **検証ポイント**: 複雑さが楽しさに繋がるか、チルさを損なわないか

各段階で「これは面白い」と確認できたら次に進む。もし Phase 2a で手応えがなければ、別のアプローチを検討する。

#### 現実の農業との類似性

この設計は、現実の農業とも類似している：
- **固定式スプリンクラー**: 稼働率は低いが設置が簡単
- **移動式スプリンクラー**: 稼働率は高いが設置・運用コストが高い
- **点滴灌漑**: パイプで水を流すだけ、低コスト・高効率

プレイヤーが直感的に理解でき、リアリティも感じられる設計となる。

#### まとめ

- **稼働率**という視点を導入することで、段階的な最適化の必然性が生まれる
- **一体型 → パイプ分離 → レール最適化**という自然な進化の流れ
- **1セル複数配置**により、配置パズルとしての戦略性を提供
- **RTS的な命令の楽しさ**と**チルな眺める楽しさ**を両立
- フィージビリティスタディでは段階的に検証し、各段階で楽しさを確認する

## 追記3: 「水と重力と歯車」による自動化 — 原始的メカニズムの組み合わせシステム

### 背景と動機

専門の機械（「耕作機」「脱穀機」など）を用意するだけでは楽しみに欠ける。プレイヤーが少数の汎用的な要素を自分で組み合わせ、発想力により様々な応用ができるようにしたい。Factorioが「ベルトコンベアとインサータ」を原始要素にしたように、Stella Gardenでは**「水・重力・回転力」**を原始要素とする方向を検討する。

惑星開拓で化学肥料が手に入らないのと同様に、電気も潤沢にはない。代わりに水力・風力・重力という自然エネルギーと、歯車・滑車・カムといった古典的な機械要素でプレイヤーが仕組みを組み上げる。木製の歯車、亜麻のロープベルト、水道橋といった素材は、ゲーム内で自給可能なものに限定できる。雰囲気としてはスチームパンク的な方向性もあり得る。

### 川の追加と灌漑の基礎

#### 川が農業に果たす役割（歴史的背景）

世界四大文明がすべて大河の流域で生まれたのは偶然ではない。

- **メソポタミア（チグリス・ユーフラテス川）**: 紀元前6000年頃から灌漑農業。川から運河を掘って農地に水を引くシステム。灌漑の維持管理が組織的な労働力を必要とし、都市国家が生まれた
- **エジプト（ナイル川）**: 年1回の予測可能な洪水に依存。洪水後にシルト（肥沃な泥）が堆積した土地に種を撒く。大規模灌漑工事なしで農業が成立

共通点: 川は単なる水源ではなく、**肥沃な土壌の運搬者**でもある。

#### ゲームへの適用

- **地形生成に川を追加**: 高地（山岳地帯）から低地（海岸）に向かって流れる川をシンプレックスノイズで生成
- **川沿いの土壌は肥沃**: 川に隣接するタイルは初期状態でも土壌品質が高い設定にできる
- **高台の水源問題の解決**: 川は高地から流れてくるので、川の上流が自然な高所水源になる
- ~~洪水イベント~~: ユーザーの作った耕地や建物が水浸しになるリスクがあるため、今回は除外

### 揚水技術 — 水を高いところに上げる

#### シャドゥーフ（天秤式揚水装置）

- 紀元前2000年頃のエジプトで使用された最古の揚水装置
- 天秤の原理: 長い棒の一端にバケツ、反対端に重石。重石の力で水を汲み上げる
- 人力だが重石のおかげで少ない力で済む
- ゲーム序盤の手動揚水に使える

#### ノーリア（水力揚水車）

- **川の水流自体を動力にして、水を高所に持ち上げる**装置
- 巨大な水車の外周にバケツ（区画）がついていて、水車が回ると下で水を汲み、頂点で水路に注ぐ
- **外部動力が一切不要** — 川が流れていればそれだけで動く
- 歴史的実績: シリアのハマのノーリアは直径20m、毎分95リットルを汲み上げ。スペインのトレドでは40m以上の高さに揚水

**ゲームでの灌漑フロー:**
```
[山] ← 川の源流（自然な高所水源）
 │
 ├─ [川] ──→ [ノーリア] ──→ [高所の水路/水道橋] ──→ [農地へ散水]
 │                ↑
 │          川の流れが動力
 │
[海] ← 高さ0の水面
```

プレイヤーの体験フロー:
1. 川沿いに畑を作り、手動で水やり（序盤）
2. ノーリアを川に設置 → 高所の水路に水が上がる → 水路から重力で農地へ（中盤）
3. 複数のノーリア + 水路網で広域灌漑（後半）

### 灌漑の必要性に関する再検討

#### 天水農業（雨水のみ）の可能性

調査の結果、Stella Gardenの主要作物はいずれも比較的乾燥に強く、灌漑なしでもそれなりに育つことがわかった。

| 作物 | 水の必要性 | 備考 |
|------|-----------|------|
| ジャガイモ | 低〜中 | 雨水だけでそれなりに育つ。灌漑は収量向上の任意工程 |
| 大豆 | 低〜中 | 雨水農業で広く栽培されている。開花期に水があると良い程度 |
| 亜麻 | 低（育成中） | 育成中の水やりはさほど重要でない。むしろ収穫後のレッティング（浸漬）工程で大量の水を使う |

#### 堰による用水路への導水

河川がある環境では、**堰（ウィア）を設けるだけで用水路に水を流すことができる**。これは既に本文書の「水門（スルースゲート）」節で詳述した通りで、堰→導水路→水門の組み合わせにより、ノーリアのような揚水装置なしで農地への灌漑が成立する。

乾燥地帯では、畝立てをした土地に用水路から水を少し流し込む**畝間灌漑（furrow irrigation）**で土を湿らせる方法もある。高頻度の水やりは不要で、必要なときに水門を開けるだけでよい。

#### ノーリアの位置づけ（再評価）

上記を踏まえると、**灌漑目的でノーリアが必要になる場面は限定的**である。

- 川沿いの農地: 堰＋導水路で十分
- 高台の農地: ノーリアが有効だが、そもそも主要作物は天水でそれなりに育つ
- レッティング用の水場: 川沿いに施設を置けば揚水不要

ノーリアの本来の価値は「灌漑」よりもむしろ**動力源としての揚水**（高所の貯水槽に水を上げ、位置エネルギーとして蓄える → 上掛け水車の動力源にする）にある。灌漑のためだけにノーリアを導入する必然性は薄いため、ゲーム序盤〜中盤の灌漑はノーリアなしの設計とし、ノーリアは動力系統の要素として後から導入する方向で検討する。

ただし、ノーリアの技術的な仕様・設計検討は以下の節にそのまま残す（将来の動力設計で必要になるため）。

**亜麻ロープによるベルトドライブの歴史的根拠:**

18世紀〜19世紀の工場では、水車1台の動力を建物全体に伝達するためにロープドライブが広く使われていた。素材は麻（hemp）、マニラ麻、綿ロープが主流。亜麻（flax/linen）も同系統の繊維であり、ゲーム的な嘘ではなく歴史的に妥当な設定。

産業革命期の工場の動力伝達（ラインシャフトシステム）:
```
[水車] → [主軸（ラインシャフト）] ━━━━━━━━━━━━━━━━━→ 工場の端まで
              │          │          │          │
           [プーリー]  [プーリー]  [プーリー]  [プーリー]
              │          │          │          │
           [ベルト]    [ベルト]    [ベルト]    [ベルト]
              │          │          │          │
           [織機]     [旋盤]     [製粉]     [紡績機]
```

1776年、ジェデダイア・ストラットの水力紡績工場では直径5.5mの水車1台で工場全体の機械を駆動。19世紀末には1つの建物内に1マイル（1.6km）以上のラインシャフトを持つ工場もあった。

**ゲームにおける亜麻の循環構造:**

亜麻はゲーム内で既に栽培→紡績→糸の生産ラインが設計されている。亜麻糸/ロープを動力伝達に使えるなら、農業と機械化が亜麻を介して直接つながる:
```
亜麻栽培 → 収穫 → レッティング → 紡績 → 亜麻ロープ
                                              ├→ 袋（大豆出荷用）  ← 既存設計
                                              ├→ ベルト（動力伝達） ← 新用途
                                              └→ ロープ（滑車・巻き上げ）
```

#### 速度制御（一定のリズムを作る）

一定速度の実現は機械設計の根本的な課題。水車の回転速度は水量で変わり、そのままでは安定しない。

**ヴァージ脱進機（13世紀ヨーロッパ）:**

```
        [フォリオット（天秤棒）]
     ←重り─────┼─────重り→
               │
          [ヴァージ（軸）]
            ┌─┤├─┐
          パレット  パレット    ← 2枚の爪が互い違いに
            │        │           冠歯車に噛み合う
         [冠歯車（エスケープホイール）]
               │
          [歯車列] ← 錘の重力で回転しようとする
               │
            [錘]
```

動作原理:
1. 動力が歯車列を通じて冠歯車を回そうとする
2. 冠歯車の歯がパレットAに引っかかり、ヴァージを押す
3. ヴァージが回転するとフォリオット（天秤棒）も一緒に回る
4. フォリオットの慣性で「行き過ぎて」反対側に振れ、パレットBが反対側の歯に引っかかる
5. **1往復で歯が1つだけ進む** → 一定速度の実現

速度調整: フォリオットの重りを外側に動かす→遅くなる、内側に動かす→速くなる。プレイヤーが調整する要素として直感的。

| 要素 | 機能 | 備考 |
|------|------|------|
| **フォリオット脱進機** | 歯車の進みを一定間隔に制限 | 屋外機械向け。調整可能 |
| **振り子** | より正確な周期運動 | 建物内の固定設備向け。振り子の長さで周期が決まる |
| **ガバナー（遠心調速機）** | 回転速度が上がると自動減速 | 蒸気機関時代。回転が速くなると遠心力で弁が閉じ蒸気を絞る |

#### 制御・プログラム（何をいつやるか）

**ピンシリンダー — 歯車による原始的プログラム:**

9世紀バグダッドのバヌー・ムーサー兄弟が水力オルガンに交換可能なピン付きシリンダーを使用。「機械的にプログラムを再生する」最古の例。1804年のジャカード織機ではパンチカードで織りパターンを制御し、これがコンピュータの祖先となった。

```
[ピンシリンダー]        回転方向 →
  ┌─────────────────┐
  │ ●   ●     ●     │  ← ピンの位置 = 「いつ」
  │   ●     ●   ●   │  ← ピンの列 = 「何を」
  │     ●       ●   │
  └─────────────────┘
         ↓ ピンが押す
  [レバーA][レバーB][レバーC]
     ↓        ↓        ↓
  [水門開] [鋤を下ろす] [刃を動かす]
```

プレイヤーがピンシリンダーにピンを差し込んで「プログラム」を作る。シリンダーが1回転する間に、どのタイミングでどのアクションを実行するかを設計できる。これはフィージビリティスタディで言及されている「ヴィジュアルプログラミングみたいなこと」の原始的な実現形態。

| 要素 | 機能 | 備考 |
|------|------|------|
| **ピンシリンダー** | 回転1周を「プログラム」として実行 | ピンの配置 = プログラムコード |
| **カムシャフト** | 複数のカムで複数動作を同期 | エンジンのカムシャフトと同原理 |
| **ラチェット** | 一方向にだけ回転を許可 | 逆回転防止。巻き上げ機構に必須 |
| **クラッチ** | 動力の接続/切断 | センサーと組み合わせてON/OFF |
| **トリップハンマー** | カムで持ち上げ→落下の反復 | 鍛冶、精米、亜麻の叩き（スカッチング）に |
| **感圧板** | アイテムの有無を検知 | ホッパーが満杯→水門閉じる等 |
| **成長センサー** | 作物の成長段階を検知 | 収穫タイミングの自動判定 |
| **リンク棒** | センサーの信号を機械的に伝達 | 電気ワイヤーではなく物理的な棒 |

### 蒸気機関によるエンドゲーム

外燃機関/蒸気機関は終盤のコンテンツとして、技術ツリーの自然な延長上にある。

#### 技術ツリーの全体像

| 時代 | 動力源 | 揚水 | 速度制御 | 雰囲気 |
|------|--------|------|----------|--------|
| 序盤 | 人力 | シャドゥーフ（天秤） | なし（手動） | 素朴な開拓 |
| 中盤前期 | 水力（水車） | ノーリア | フォリオット脱進機 | 水車小屋の牧歌的風景 |
| 中盤後期 | 風力（風車） | 風車+ポンプ | 振り子時計 | 風車のある丘の風景 |
| 終盤 | 蒸気力 | 蒸気ポンプ | ガバナー（遠心調速機） | スチームパンク |

#### 蒸気機関の特性

メリット:
- 場所を選ばない（水車は川の近く、風車は高台が必要）
- 出力が安定（天候に依存しない）
- 強い力が出る（重い機械を動かせる）

コスト:
- 燃料が必要（木材を大量消費 → 森林管理とのジレンマが深まる）
- 水が必要（ボイラー用）
- メンテナンスが必要

05_CULTIVATION.mdで設計した「森の二択」（伐採 vs 維持）との相乗効果: 蒸気機関を動かすために森を伐採しすぎると、堆肥原料も草木灰も失い、農業自体が成り立たなくなる。

### チルな雰囲気との両立

この設計がチルである理由:
- **眺める楽しさ**: 水が流れる、水車が回る、歯車が噛み合う、作物が刈られて斜面を転がる — 本質的に見ていて気持ちいい
- **音の心地よさ**: 水のせせらぎ、歯車のカチカチ、風車のきしみ。ASMR的な環境音
- **急がなくていい**: 水力・風力は自然のペース。プレイヤーが離席しても機械は勝手に動き続ける
- **失敗が致命的でない**: 水路の勾配を間違えても水が流れないだけ。壊れたり爆発したりしない
- **スチームパンク的雰囲気**: 蒸気の「しゅー」という音、規則正しい機械音はASMR的でチルさと共存できる

### 水車・ノーリアの停止・制御機構

水車やノーリアのON/OFF制御は、プログラムによる自動化の基礎となる重要な要素。歴史的に3つの方法が使われていた。

#### 方法1: 水門（スルースゲート）— 水を止める

最も一般的で基本的な方法。水車そのものではなく、**水車に到達する水を制御する**。

##### 堰（ウィア）の構造

堰は**川幅いっぱいに作る低い壁**。これにより上流側の水位が上がり、「ミルポンド（水車池）」と呼ばれる貯水域ができる。堰は水を完全にせき止めるダムほど高くなく、余った水は堰の上を越えて下流に流れる（溢水）。堰を川幅全体に設けないと、水は堰のない部分を素通りしてしまい、導水路に十分な水圧を確保できない。

堰の脇（または一部）に**水門付きの取水口**を設け、そこから狭い導水路（ミルレース）に水を引き込む。ミルレースは川本体より幅が狭いため、同じ水量でも流速が速くなり、水車を効率よく回せる。

```
              川上（上流）
                 │
  ═══════════════╤══════════════  ← 堰（川幅いっぱいの低い壁）
  ～～～～～～～ │ ～～～～～～      堰で水位が上がる（ミルポンド）
               [水門]
                 │
            [導水路（ミルレース）]  ← 狭い水路。狭いから流速が速い
                 │
            [水車/ノーリア]
                 │
            [放水路（テイルレース）] → 下流で川に合流
```

##### ゲームでの簡略化

川幅がゲーム内で2〜4タイル程度であれば、堰は2〜4個の堰ブロックで表現でき、そのうち1つが水門というシンプルな構造になる:

```
川のタイル表現（幅3タイルの場合）:

  ～ ～ ～     ← 川（上流）
  ═ ═ ■       ← 堰（═）+ 水門（■）
  ～ ～ │       ← 堰を越えた水はそのまま下流へ / 水門から導水路へ
        │
       [導水路] → [水車]
```

##### 停止の原理

水車が回るには水車の前後で**水位差（落差）**が必要。水門を閉じて導水路への水を止めると水位差がなくなり、回転が止まる。水門を開けると導水路に水が流れ込み、水車が回り始める。

ゲームでの表現:
- 水門 = ON/OFFスイッチの最も基本的な形
- 手動で開閉する → 序盤
- リンク棒やカムで自動開閉する → 中盤以降（プログラム制御の第一歩）

#### 方法2: バンドブレーキ — 回転を止める

風車で特に重要だった方法。水門がない風車は風が吹く限り回り続けるため、ブレーキが必須。

```
       [ブレーキバンド（木製帯）]
            ┌──────────┐
           ╱            ╲
          │  [ブレーキ   │
          │   ホイール]  │    ← 木製の帯が歯車の外周を囲む
          │              │
           ╲            ╱
            └──────┬───┘
                   │
              [ブレーキレバー]  ← 引くと帯が締まる→摩擦で停止
```

- **ブレーキホイール**: 水車/風車の主軸に取り付けられた大きな歯車
- **ブレーキバンド**: ニレ材の帯がブレーキホイールの外周を囲む
- **ブレーキレバー**: レバーを引くとバンドがホイールに押し付けられ、摩擦で回転が止まる

実例: オランダの風車では直径約3m（10フィート）のオーク材のブレーキホイールにニレ材のブレーキバンドが巻かれていた。

ゲームでの表現:
- 水車にも使える汎用的な「停止装置」
- 水門とは異なり、**動力伝達の途中に挟める**

#### 方法3: ドッグクラッチ — 回転を伝えない

水車は回り続けるが、**その回転を後段に伝えない**ための機構。

```
[水車] → [軸A] → [ドッグクラッチ] → [軸B] → [歯車列]
                       │
                  噛み合い/離脱
                  をスライドで切替
```

- 2つの軸の端に**噛み合う歯（ドッグ）**がある
- スライドさせて歯を噛み合わせると → 動力が伝わる（ON）
- スライドさせて歯を外すと → 動力が切れる（OFF）
- 摩擦クラッチと違い**滑りがない**（完全なON/OFF）
- 木製でも十分に作れる構造

歴史的な製粉所ではベベルギア（かさ歯車）の間にドッグクラッチを置いて製粉機のON/OFFを制御していた。

ゲームでの表現:
- 水車を止めずに、特定の機械だけON/OFFできる
- 1つの水車から複数の機械に動力を分配するとき、個別にON/OFFする手段

#### 3つの方法の比較

| 方法 | 何を止めるか | 特徴 | ゲーム用途 |
|------|------------|------|-----------|
| **水門** | 水の流れ | 水車自体が止まる。灌漑の制御にも兼用 | 水路システム全体のON/OFF。タイマーとの相性◎ |
| **バンドブレーキ** | 回転自体 | 回転軸に直接作用。風車では必須 | 緊急停止。風車の制御 |
| **ドッグクラッチ** | 回転の伝達 | 動力源は動き続け、末端だけ切断 | 個別機械のON/OFF。分岐制御 |

#### フロート弁 — 自動ON/OFFの鍵

貯水槽の水位制御は**フロート（浮き）**で実現できる。トイレのボールタップ（ballcock）と同じ原理で古代から使われていた技術。

##### 構造: てこの原理（レバーとピボット）

```
                    ピボット（支点）
                        ▼
  ┌─────────────────────●─────────────────┐  ← レバーアーム
  │                                        │
  │                                        │
[水門の弁]                              [フロート（浮き球）]
  ↑閉じる力                               ↑浮力
```

- **レバーアームの一端**: フロート（浮き球や浮き板）が取り付けられている
- **レバーアームの途中**: ピボット（支点）で貯水槽の壁面等に固定
- **レバーアームのもう一端**: 水門の弁やプランジャーに接続

##### 動作原理

1. **水位が上がる** → フロートが浮力で持ち上がる → レバーアームのフロート側が上がる
2. ピボットを支点にして → **反対側（弁側）が下がる** → 弁が閉じる（=水門を閉じる）
3. **水位が下がる** → フロートが下がる → 弁側が上がる → 弁が開く（=水門を開く）

##### 弁を閉じる力 = フロートの浮力

弁を閉じる力はフロートの浮力そのもの。フロートに働く浮力は「水に沈んだ体積 × 水の密度 × 重力加速度」で決まる。レバー比（支点からフロート側の距離 : 支点から弁側の距離）で力を増幅できる:

- フロート側のアームが長い（例: 3）: 弁側が短い（例: 1）→ 弁を閉じる力 = 浮力 × 3（力は強いが弁の動きは小さい）
- フロート側が短い（1）: 弁側が長い（3）→ 弁を閉じる力 = 浮力 × 1/3（力は弱いが弁の移動量が大きい）

##### ゲームでの調整パラメータ

| 調整項目 | 効果 | ゲーム上の意味 |
|---------|------|-------------|
| **フロートの大きさ** | 大きい→浮力が強い→弁を強く閉じられる | 大きな水門を制御するには大きなフロートが必要 |
| **レバーアームの長さ比** | 支点の位置で力と移動量のトレードオフ | 力が必要な弁 vs 素早く反応するシステム |
| **フロートの取り付け高さ** | 水位何mで弁が閉じるかが変わる | 貯水槽の「満杯」の基準を調整 |

##### 配置イメージ

```
[ノーリア] → [水路] → [貯水槽]
                         │
                    ┌────┤
                    │    │  水位
                    │   ○│  ← フロート（浮き球）
                    │  ／ │
                    │／   │
                    ●     │  ← ピボット（壁面に固定）
                   ╱      │
                  ╱       │
             [弁/水門]    │
                │         │
          [導水路へ]  or  [ノーリアの水門を閉じるリンク棒へ]
```

フロートが貯水槽の中にあり、レバーアームが壁を貫通して外の水門に接続される。貯水槽の水位が一定以上になるとフロートが浮き、てこの原理で水門が閉じてノーリアが止まる。水を使って水位が下がればまた開く。

**電気を使わない自動フィードバック制御**。プレイヤーが「貯水槽が満杯になったらノーリアを止めたい」と思ったとき、フロート+リンク棒+水門の組み合わせで解決できる。

#### 組み合わせの例: 自動水位制御付きノーリア

```
[川] → [水門A] → [ノーリア] → [貯水槽]
           ↑                      │
      [フロート弁]  ← ← ← ← ←  │  ← 水位が上がるとフロートが浮き、
           │                           リンク棒で水門Aを閉じる
      「貯水槽が満杯→ノーリア停止」を自動で実現！
```

#### 組み合わせの例: 1台の水車で複数機械を個別制御

```
[川] → [水門B] → [水車] → [ドッグクラッチA] → [製粉機]
                     │
                     └→ [ドッグクラッチB] → [紡績機]
                     │
                     └→ [ドッグクラッチC] → [コンベア]

水車は常時回転、必要な機械だけクラッチで接続/切断
```

#### プログラム制御への発展経路

制御機構の段階的な進化として、以下の流れが自然に生まれる:

```
手動操作（序盤）
  → フロート弁による自動フィードバック（中盤前期）
  → タイマー歯車による定期制御（中盤後期）
  → ピンシリンダーによるシーケンス制御（終盤）
```

#### 制御系プリミティブの更新

前節のプリミティブ一覧に以下を追加:

| 要素 | 機能 | ON/OFFの対象 |
|------|------|-------------|
| **水門（スルースゲート）** | 水流の開閉 | 水路・水車・ノーリア |
| **堰（ウィア）** | 川の水圧を導水路に集中させる | ノーリア・水車への水流制御の前提 |
| **導水路（ミルレース）** | 堰から水車への水路 | 水門と組み合わせて水車の制御 |
| **バンドブレーキ** | 回転軸の制動 | 水車・風車（回転自体を停止） |
| **ドッグクラッチ** | 動力伝達の接続/切断 | 個別の機械（動力源は動き続ける） |
| **フロート弁** | 水位に応じた自動開閉 | 水門と連動して貯水槽の自動制御 |

### 農作業の機械化

農作業の各フェーズ（耕す・植え付け・土寄せ・収穫）をプリミティブ要素で自動化する方法を検討する。

#### 各農作業の機械的な仕組み（トラクター農具の原理）

**1. 耕す（プラウ／犂）**

犂（moldboard plow）は3つの部品で構成される：
- **コールター（coulter）**: 垂直な円盤刃。土を縦に切る
- **シェア（share）**: 水平な刃。土を下から持ち上げる
- **モールドボード（moldboard）**: 湾曲した板。持ち上がった土を横に反転させる

特徴：**牽引力のみで動作**し、回転動力は不要。ロープで引っ張るだけで耕作が成立する。

**2. 植え付け（シードドリル）**

種まき機の仕組み：
- **コールター**: 土に溝を切る
- **種子タンク**: 上部に種を溜める
- **繰り出しローラー**: 回転して一定量ずつ種を落とす（回転動力が必要）
- **チューブ**: ローラーから溝まで種を導く
- **鎮圧輪**: 後方で土を押さえて覆土する

繰り出しローラーの回転は**車輪の回転からギアで取る**のが一般的。台車が進むこと自体が動力源になる。

**3. 土寄せ（リッジャー）**

ジャガイモの土寄せ：
- **ディスク式**: 2枚の傾斜した円盤が左右から土を中央に寄せる
- **翼型コールター**: V字型の翼が土をかき分けて畝の両側に盛る

**牽引力のみで動作**し、回転動力は不要。

**4. 収穫**

ジャガイモ収穫機の基本構造：
- **掘り取り刃**: 土ごとジャガイモを持ち上げる
- **振動篩（エレベーターチェーン）**: 格子状のチェーンが振動して土を落とす
- **分離ローラー**: 石や茎を分離する

振動篩には回転動力が必要だが、ゲーム的には「掘り取り刃で持ち上げる」だけに簡略化可能。

#### 農作業ごとの動力要件まとめ

| 農作業 | 牽引力 | 回転動力 | ゲーム的な簡略化 |
|--------|--------|----------|-----------------|
| 耕す | 必要 | 不要 | ロープで引っ張るだけ |
| 植え付け（小粒種子） | 必要 | 車輪から取れる | 台車が進めば自動で種まき |
| 植え付け（種いも） | 必要 | 車輪から取れる | ポテトプランター（後述） |
| 土寄せ | 必要 | 不要 | ロープで引っ張るだけ |
| 水やり | 不要 | 不要（水路+重力） | 既に設計済み |
| 茎刈り（ハウムトッピング） | 必要 | **回転動力必要** | じゃがいも収穫前の必須工程（後述） |
| 収穫 | 必要 | あると良い | 掘り取りのみなら牽引だけ |

**重要な発見**: ほとんどの農作業は「牽引力」だけで成立する。水車からロープで台車を引っ張る仕組みさえあれば、農具を付け替えるだけで多くの作業を自動化できる。

- 参考資料 https://www.ndl.go.jp/exposition/s2/9.html
  - 耕うん機、刈り取り機、脱穀機、コンバインなどの説明がある

#### じゃがいも農業の機械化（詳細）

じゃがいもは他の作物（小麦・大豆・亜麻など）と比べて、植え付けと収穫に**専用機械**が必要になる点が特徴的。

##### シードドリルとポテトプランターの違い

通常のシードドリルは小さな種を繰り出しローラーの小穴から一定間隔で落とす機械であり、**種いも（40〜60gの塊）には対応できない**。じゃがいもの植え付けには**ポテトプランター**という専用機械を使う。

| 機械 | 対象 | 繰り出し方式 | 動力 |
|------|------|------------|------|
| **シードドリル** | 小粒種子（小麦・大豆・亜麻等） | ローラーの小穴から落とす | 牽引＋車輪回転 |
| **ポテトプランター** | 種いも（40〜60gの塊） | カップまたはベルトで1個ずつ拾い上げて落とす | 牽引＋車輪回転 |

どちらも車輪の回転からギアで繰り出し機構を駆動するため、牽引するだけで動作する。

##### ハウムトッピング — 収穫「前」の茎刈り

**じゃがいもの茎（ハウム）は収穫前に除去する**。これはじゃがいも農業の重要な工程。

茎を付けたまま掘り起こすと：
- 茎が収穫機の振動篩やローラーに絡まって詰まる
- 分離ローラーの役割は**土・小石とじゃがいもの分離**であり、茎の切断は想定外

ハウムトッパー（フレイルモア）の仕組み：
- 回転する刃（フレイル）が地上部の茎を粉砕する
- **回転動力が必要**（牽引だけでは動かない）
- 車輪からギアで取るか、別途動力ベルトで回転を伝達する

現実では茎を刈った後1〜2週間待って皮を硬化させるが、ゲームでは省略可能。

##### じゃがいもの正確な農作業フロー

```
1. [プラウ]           土を耕す（牽引のみ）
       ↓
2. [ポテトプランター]  種いもを植え付け（牽引＋車輪回転）
       ↓
3. [リッジャー]        土寄せ・畝立て（牽引のみ）
       ↓
   （成長期間：水やりは水路+重力で自動灌漑、または天水に任せる）
       ↓
4. [ハウムトッパー]    茎を粉砕（牽引＋回転動力）
       ↓
5. [ポテトハーベスター] 掘り取り＋振動篩で土を落とす（牽引＋回転動力あると良い）
       ↓
   傾斜面 → ホッパー → チェストへ
```

##### 専用機械のクラフト方針

農具アタッチメントは**クラフトレシピによる専用機械**として提供し、プレイヤーに内部機構を設計させない。

**プレイヤーが設計する部分（自由度あり）:**
- 動力系: 水車 → シャフト → ウィンチ → ケーブル
- 制御系: タイマー歯車、トリップレバー、ピンシリンダー
- レイアウト: 畑・レール・水路の配置

**クラフトレシピで入手する部分（既製品）:**

| アタッチメント | 主な素材（案） | 工程 |
|--------------|---------------|------|
| **プラウ** | 木材＋鉄 | 耕起 |
| **シードドリル** | 木材＋鉄＋歯車 | 小粒種子の植え付け |
| **ポテトプランター** | 木材＋鉄＋歯車 | 種いもの植え付け |
| **リッジャー** | 木材＋鉄 | 土寄せ |
| **ハウムトッパー** | 木材＋鉄＋刃 | 茎刈り（要回転動力） |
| **ポテトハーベスター** | 木材＋鉄＋チェーン | 収穫 |

Factorioにおける「組立機は既製品、ベルトとインサータの配置はプレイヤー設計」と同じ構造。**「何を動かすか」は既製品、「どう動かすか」はプレイヤーの設計**という分離により、自由度と複雑さの丁度良い塩梅を実現する。

#### ケーブル耕作システム（ファウラー式）

19世紀イギリスで実用化された**ケーブル耕作（cable plowing）**システム。プレイヤーの「台車にロープを張って水車から動力を伝える」構想の歴史的先例。

**基本構造:**

```
[ウィンチA] ═══════ロープ═══════ [ウィンチB]
    ‖                                ‖
    ‖        ←── 犂 ──→             ‖
    ‖                                ‖
  畑の端                           畑の端
```

- 畑の両端にウィンチ（巻き取り機）を設置
- 犂をロープで繋ぎ、**片方が巻き取り、もう片方が繰り出す**ことで犂を往復させる
- 1往復ごとにウィンチが**数フィートずつ前進**して次の列に移る
- 犂は**バランスプラウ**（左右対称の犂）を使い、往路と復路で反転せずに耕せる

#### ゲームへの適用案

```
        水車
         ‖
      主シャフト
       ╱    ╲
  ウィンチA   ウィンチB    ← ロープ/ベルトで水車から動力を伝達
      ‖         ‖
      ╚═══台車═══╝         ← 台車は2本のロープで往復
          ‖
        農具（プラウ/プランター/リッジャー/トッパー/ハーベスター等）
```

台車への動力伝達は二系統：
- **牽引ロープ**: ウィンチからの巻き取りで台車を移動させる
- **動力ベルト**（オプション）: シードドリル・ハウムトッパー等、回転動力が必要な農具を動かす。ただし車輪からギアで取れる場合は不要

#### 方向転換と制御の解決策

##### 端の検知 — トリップレバー方式

フロート弁と同じ「物理的な力 → レバー → 制御機構」のパターンで、台車の位置を検知する。工場の自動織機や自動旋盤で19世紀から使われていた仕組み。

```
  台車の進行方向 →→→

                        ┌─ トリップレバー（ピボットで固定）
                        │    ↑ 台車が押すと倒れる
  ══════════════════════╪═══════
                        │
                        └─→ リンク棒 → クラッチ切断 or ブレーキ作動
```

- 畑の端に**トリップレバー**（突起棒）を立てておく
- 台車がそこに到達すると、台車の本体がレバーを物理的に押し倒す
- レバーはリンク棒を介して**ドッグクラッチの切断**や**バンドブレーキの作動**に繋がる
- 結果：台車が端に来ると自動的に停止する

フロート弁との共通パターン：

| 要素 | フロート弁での役割 | 農作業での役割 |
|------|-------------------|---------------|
| **検知部** | フロート（水位） | トリップレバー（台車位置） |
| **伝達部** | リンク棒+ピボット | リンク棒+ピボット（同じ） |
| **制御対象** | 水門の開閉 | クラッチ/ブレーキの切断 |

プレイヤーは「フロート弁で学んだ仕組みをそのまま農作業の制御に転用できる」という設計。

##### 方式1: 往復方式（ファウラー式）

- 台車は直線往復のみ。方向転換しない
- 1列耕したらウィンチ側が横にずれて次の列へ

**利点:**
- 資材が少ない（ウィンチ2基 + ロープのみ。レールの敷設不要）
- 畑の面積変更が容易（ロープの長さとウィンチの送り距離を変えるだけ）
- 不整形な畑にも対応しやすい

**課題:**
- 制御が複雑（「停止 → ウィンチ送り → 逆転」の3ステップシーケンスが必要）
  1. 台車が端のトリップレバーを押す → ウィンチAのクラッチ切断
  2. 送り機構が作動してウィンチが1列分横移動
  3. ウィンチBのクラッチ接続 → 逆方向に引っ張り開始
- ピンシリンダーのような順序制御が前提 → **中〜上級者向けの自動化課題**

##### 方式2: ループレール方式

- 蛇行する1本の連続レールを畑に敷き、台車がレール上を周回する
- ロープで引っ張るだけで全面をカバー。方向転換の制御が不要

```
  ┌──────────────────────┐
  │  ←←←←←←←←←←←←←←←←  │
  │                      │
  │  →→→→→→→→→→→→→→→→  │
  │                      │  ← 蛇行する1本の連続レール
  │  ←←←←←←←←←←←←←←←←  │
  │                      │
  │  →→→→→→→→→→→→→→→→  │
  └──────────────────────┘
      ↑ 始点 = 終点（ループ）
```

**利点:**
- 制御が簡単（引っ張るだけ。方向転換はレールの物理形状が決める）
- ループなので終点=始点 → 始点にトリップレバー1個で自動停止
- 初心者でも構築しやすい

**課題:**
- レールの資材コストが大きい（畑全面に敷設が必要）
- 畑のサイズ変更にはレールの敷き直しが必要
- カーブ部分での農具の挙動（カーブ中は耕さない？スプライト処理？）

##### 方式の比較まとめ

| 観点 | ファウラー式（往復） | ループレール式 |
|------|---------------------|---------------|
| 資材コスト | 少ない（ウィンチ+ロープ） | 多い（レール全面敷設） |
| 制御の複雑さ | 高い（順序制御が必要） | 低い（引っ張るだけ） |
| 面積の変更 | 容易（ロープ長変更） | 困難（レール敷き直し） |
| プレイヤースキル | 中〜上級者向け | 初心者でも可能 |
| 段階的自動化 | ピンシリンダーと相性良 | トリップレバーで十分 |

両方式を共存させることで、プレイヤーの習熟度に応じた選択肢を提供できる。

##### ケーブル牽引の説得力 — ケーブルカーとの共通原理

ファウラー式ケーブル耕作は農業史上の特殊例に見えるが、「固定動力源＋ケーブル＋軌道上の移動体」という原理自体は、歴史的に広く使われてきた普遍的な技術である。

**フニクラ（ケーブルカー）との共通構造:**

```
ケーブルカー:      [山上の巻き上げ機] ═══ケーブル═══ [客車] ═══ [軌道]
ケーブル耕作:      [畑端のウィンチ]   ═══ケーブル═══ [台車] ═══ [畑/レール]
```

どちらも固定された動力源がケーブルを巻き取り、軌道上の移動体を牽引する。動力源が移動体に搭載されていない点が共通の特徴であり、これにより移動体側を軽量・単純に保てる。

**歴史的な類例:**

| システム | 時代 | 地形 | 原理 |
|---------|------|------|------|
| **フニクラ（鋼索鉄道）** | 1862年〜 | 斜面 | 山上のウィンチがケーブルで客車を上下させる |
| **サンフランシスコ・ケーブルカー** | 1873年〜 | 平地〜丘陵 | 地下を走る連続ケーブルを車両がグリップで掴んで移動 |
| **鉱山ケーブルトロッコ** | 19世紀〜 | 坑道（水平） | ウィンチ＋ケーブルでトロッコを牽引 |
| **運河インクライン** | 18世紀〜 | 斜面 | ケーブルで船を斜面上に引き上げて運河間を接続 |
| **ケーブルロギング（架線集材）** | 19世紀〜 | 山林 | 架線にケーブルを張り、伐採した木材を運搬 |
| **ファウラー式ケーブル耕作** | 1850年代〜 | 平地 | 畑の両端のウィンチでケーブルを巻き取り、犂を往復 |

注目すべきは、**斜面だけでなく平地でも広く使われていた**点である。サンフランシスコのケーブルカーは坂道で有名だが、実際には平坦な区間も含む路線を走っている。鉱山トロッコは水平坑道で日常的に使用されていた。

**ゲーム設計への示唆:**

- プレイヤーへの説明として「ケーブルカーと同じ仕組み」と言えるのは、直感的な理解を助ける強い武器になる
- ケーブル牽引は「農業専用の特殊技術」ではなく「汎用的な動力伝達技術の農業応用」として位置づけられる
- 将来的にケーブル牽引を農業以外（鉱山トロッコ、物資運搬など）に拡張する余地も生まれる
- ケーブルが動く様子は視覚的にわかりやすく、「チルな眺める楽しさ」にも貢献する

**注意点:**

ケーブルカーとの類推がゲーム設計を交通システム方面に引きずるリスクがある（路線設計の自由度、ポイント切り替え等）。農業ゲームとしてのスコープを保つため、ケーブル牽引は「農具・運搬台車を引っ張る」用途に限定し、旅客輸送的な要素は意識的に除外する。

##### ループレール + トリップレバーの段階的自動化

- **初心者**: 手動でクラッチON → ループ1周で全面自動耕作 → 始点のトリップレバーで自動停止
- **中級者**: ピンシリンダーで毎朝自動でクラッチON → 定期実行
- **上級者**: フロート弁で土壌水分を検知 → 水やり台車を自動発進（条件トリガー）

#### アタッチメント自動切り替え — 転車台＋グリップ方式

##### 課題: 農具の付け替え自動化

ケーブル耕作システムでは、農作業の工程ごとに台車のアタッチメント（プラウ、プランター、リッジャー等）を切り替える必要がある。現実の農業でもトラクターへの農具の付け替えは手動作業（1回10〜30分）であり、自動化された実用例はほとんどない。

ゲームとしてはここも自動化したい。解決策として、**転車台（ターンテーブル）とグリップ機構の組み合わせ**を採用する。

##### 基本構造

```
          [メインループ（畑）]
           ↗ 出発          ↖ 帰還
          ╱                  ╲
    ─────●────────────────────●─────
         │    ケーブル（常時走行）    │
         │                          │
    ═════╪══════════════════════════╪═════
         │                          │
         │       [転車台]           │
         │      ╱   │   ╲          │
         │   [A]   [B]   [C]       │
         │  プラウ プランター リッジャー │
         │      [D]   [E]          │
         │    トッパー ハーベスター    │
```

- 転車台の上に複数の台車が放射状に配置されている（各台車にアタッチメントが固定）
- ケーブルは転車台の下を直線的に通過している（常時走行）
- 全台車のグリップは普段**開放状態**（ケーブルが素通りする）

##### 動作手順

1. **転車台回転**: 歯車駆動で転車台を回転させ、目的の台車をケーブルの真上に位置決めする。全グリップが開放状態なので、ケーブルは干渉せず自由に回転できる
2. **グリップ係合**: 制御機構（リンク棒）が位置決めされた台車のグリップを閉じる。台車がケーブルを掴む
3. **出発**: ケーブルが台車を引き出し、メインループ（畑）を1周。転車台のレールがメインループのレールに整列しており、台車はそのまま出ていく
4. **帰還**: 台車がメインループを1周して転車台に戻る。帰還口のトリップレバーがグリップを開放
5. **再回転**: グリップが開いたので転車台が再び回転可能。次の台車を位置決め

##### グリップ機構の詳細

サンフランシスコのケーブルカー（1873年〜）と同じ原理。

```
    [台車]
      │
    [グリップレバー]
      │
    ╔═══╗
    ║   ║ ← 2枚の顎（ジョー）
    ║ ○ ║ ← ケーブル（常時走行中）
    ║   ║
    ╚═══╝

   レバーを引く → 顎が閉じる → ケーブルを掴む → 台車が動く
   レバーを戻す → 顎が開く → ケーブルが素通り → 台車が止まる
```

- **グリップ開放時**: ケーブルは台車の下を完全に素通りする。台車とケーブルは非接触
- **グリップ係合時**: 顎がケーブルを挟み、摩擦力で台車がケーブルと一緒に移動する

##### なぜこの方式が成立するか

| 課題 | 解決方法 |
|------|---------|
| 台車に自走能力がない | グリップを閉じればケーブルが引き出す。転車台上では台車は動かず転車台ごと回る |
| 台車同士が追い越せない | 各台車は転車台の放射状の別スポットにいるので互いに干渉しない |
| 任意の順番で出したい | 転車台の回転角度で任意の台車を選択可能 |
| ケーブルの分岐が複雑 | ケーブルは1本の直線が転車台の下を通過するだけ。分岐不要 |

##### 転車台の回転制御

- **手動期（序盤）**: プレイヤーがレバーで転車台を回す
- **自動期（中盤〜）**: ピンシリンダーで「1日目→プラウ、2日目→プランター…」と制御。帰還時のトリップレバーがグリップ解放と同時に転車台の回転クラッチを接続し、次の台車位置まで回転→位置決めピンで停止

##### 歴史的根拠

この方式は3つの歴史的技術の組み合わせであり、個々の要素にゲーム的な嘘はない。

| 要素 | 由来 | 時代 |
|------|------|------|
| 転車台 | 鉄道の扇形機関庫（ラウンドハウス） | 1830年代〜 |
| グリップ | サンフランシスコのケーブルカー | 1873年〜 |
| ケーブル牽引 | ファウラー式ケーブル耕作 | 1850年代〜 |

##### 検討した代替案

転車台＋グリップ方式の採用に至るまでに、以下の代替案を検討した。

**FIFO（先入れ先出し）方式**: 1本の直線待機線に台車を並べ、先頭から順に出す。機構は最もシンプルだが、順番を自由に変えられない。農作業の順序が概ね固定であるため実用上は対応可能だが、リッジャーだけ毎日繰り返すような運用が難しい。

**並列分岐器方式**: 台車ごとに独立した待機線を用意し、分岐器で切り替える。任意の順番で出せるが、「台車を待機線から分岐点まで出す力」の問題が残り、傾斜＋ブレーキ等の追加機構が必要。

**グリップのみ方式（サンフランシスコ式）**: 全台車が同一線路上に並び、ケーブルが全台車の下を通過。グリップの係合/解放で任意の台車を選択…と考えたが、**同一線路上の台車は物理的に追い越せない**ため、1周するたびに順序が変わり、任意選択ができない問題が判明。転車台の導入で解決した。

#### 回転動力の伝達と方向転換の両立

水車からの回転動力を「曲がり角」で伝える方法：

| 要素 | 機能 | 用途 |
|------|------|------|
| **角度付き滑車** | ロープ/ベルトの方向を変える | 直角含む任意の角度で方向転換（最もシンプル） |
| **ベベルギア（かさ歯車）** | シャフトの方向を90度変換 | 水車→主シャフト→横方向シャフトの中継 |
| **ユニバーサルジョイント（自在継手）** | 角度付きシャフト間で回転を伝達 | シャフトが直線でない場合の接続 |

ゲーム的には**滑車**が最もシンプル。プレイヤーが畑の角に滑車を置くだけでロープの方向が変わる。

### 水理論理ゲート（Hydraulic Logic）

水路の水の有無を二値信号（ON/OFF）として扱い、組み合わせ回路を構築する仕組み。

#### 信号の定義

- **ON** = 水路に水が流れている
- **OFF** = 水路に水が流れていない

#### 基本ゲート

**NOT — フロート弁（逆論理）**

既存のフロート弁をそのまま利用。入力ONでフロートが上がり、別系統の水門を**閉じる**。

```
入力水路 ──→ [フロート槽]
                 │ フロート上昇
                 ↓
              水門が閉じる

別系統の水路 ──→ [水門] ──×──→ 出力なし（OFF）
```

- 入力ON → 出力OFF
- 入力OFF → フロート下降 → 水門開放 → 出力ON

**AND — 直列水門**

2つの水門を**直列**に配置するだけ。

```
水源 ──→ [水門A] ──→ [水門B] ──→ 出力
            ↑            ↑
          入力A         入力B
       （フロート）   （フロート）
```

- 入力A・B**両方**のフロートが水門を開いたときだけ、水が出力に到達する
- どちらか片方でもOFFなら水が止まる

**OR — Y字合流**

2つの水路を**合流**させるだけ。

```
入力A ──→ ╲
            ╲
             ══→ 出力
            ╱
入力B ──→ ╱
```

- どちらか一方でも水が流れていれば、出力に水が到達する
- 両方OFFのときだけ出力がOFF
- **新規パーツ「Y字合流」**1個で実現

**NAND — AND + NOT**

AND出力をNOTに通すだけ。NANDが実現できれば、理論的にはあらゆる組み合わせ回路が構築可能。

```
水源 ──→ [水門A直列水門B] ──→ [フロート槽（逆論理）]
            ↑        ↑              │
          入力A    入力B          水門（閉→開）
                                    │
別水源 ════════════════════════════╪══→ 出力
```

#### 信号の減衰と復元 — 水リレー

論理ゲートを直列に繋ぐと水流が弱くなる問題がある。電子回路のトランジスタに相当する**信号増幅**が必要。

解決策は**水リレー**。フロート弁がそのまま信号増幅器として機能する。

```
弱い入力信号 ──→ [フロート槽（小さい）]
                      │ フロートが上がる
                      ↓ リンク棒
                   [水門]
                      │
新鮮な水源 ═══════════╪══→ 出力（フル水圧）
```

- 小さなフロートは弱い水流でも反応する
- そのフロートが**別系統の新鮮な水源**の水門を制御する
- 出力は常にフル水圧 — 何段繋いでも信号が劣化しない

これは電子回路のリレーやトランジスタと同じ原理。「小さな信号で大きな電力を制御する」が「小さな水流で大きな水流を制御する」になる。

フロートの動作方向による役割の違い：
- **水リレー（正論理）** = バッファ（信号増幅のみ、論理反転なし）
- **水リレー（逆論理）** = NOT（信号増幅 + 論理反転）

#### 代替案 — レバーリンケージ方式

水路を引き回す必要がなく、コンパクトに作れる方式。

**AND（直列ラッチ）:**
- 中間バーに2つのラッチがあり、入力A・B両方のレバーが外さないとバーが動かない

**OR（並列レバー）:**
- どちらか一方のレバーが押されれば出力レバーが動く

ただしレバー方式は力が減衰するため、大規模な回路には水リレー方式の方が適している。

#### 必要な新規パーツまとめ

| パーツ | 論理的な役割 | 新規/既存 |
|--------|-------------|-----------|
| フロート弁（逆論理） | NOT / NAND構成要素 / 信号復元 | 既存 |
| フロート弁（正論理） | バッファ（信号復元） | フロートの動作方向設定を追加 |
| 直列水門 | AND | 既存パーツの配置で実現 |
| Y字合流パーツ | OR | **新規** |

新規パーツは**Y字合流**1個だけで、AND・OR・NOT・NANDすべてが実現できる。

#### 設計上の推奨

水リレー方式を**主軸**にする理由：
1. 既存のフロート弁・水門・水路プリミティブをそのまま活用できる
2. 新規パーツがY字合流のみと最小限
3. 信号復元（増幅）が自然に組み込まれている
4. プレイヤーが「水やりの自動化」で学んだ知識をそのまま論理回路に応用できる（学習曲線がなめらか）

### 回転論理ゲート（Rotary Logic）

シャフトの回転/停止を二値信号（ON/OFF）として扱う方式。水理論理よりコンパクトだが、「回転しているか否か」を安定した位置信号に変換する機構が必要。

#### 信号の定義

- **ON** = シャフトが回転している
- **OFF** = シャフトが停止している

#### カムの問題と遠心ガバナーによる解決

当初、カムを回転検知に使うことを検討したが、以下の致命的な問題がある：

1. **回転中のON/OFF振動**: カムが回転し続ける限り、突起が周期的にフォロワーを押す→離すを繰り返し、安定したON状態を維持できない
2. **停止位置依存**: 入力が停止したとき、カムが突起の位置で止まればON、谷で止まればOFF — 停止位置によって出力が変わってしまう

解決策は**遠心ガバナー（centrifugal governor）**。ジェームズ・ワットが1788年に蒸気機関の速度制御に使った機構。

```
        停止時                    回転時

        ○  ○                 ○        ○
        │  │               ╱            ╲  ← 重りが遠心力で広がる
        ├──┤             ╱                ╲
        │  │           ├──────────────────┤
        ║  ║           ║    スリーブ ↓↓    ║  ← スリーブが下がる
       軸  軸          軸                  軸
```

- シャフトに2つの重りがアームで取り付けられている
- **回転すると**: 遠心力で重りが外側に広がる → 中央のスリーブが下がる（安定したON位置）
- **停止すると**: 重力で重りが内側に戻る → スリーブが上がる（安定したOFF位置）

カムの問題がすべて解消される：
- 回転中はスリーブが**常に**下がった状態を維持（周期的変動なし）
- 停止すると**必ず**スリーブが上がる（停止位置に依存しない）

#### 遠心ガバナー = 回転のフロート

フロート弁と完全に同じ構造パターン：

| 要素 | フロート弁 | 遠心ガバナー |
|------|-----------|-------------|
| 検知対象 | 水位 | 回転速度 |
| 検知原理 | 浮力（上向きの力） | 遠心力（外向きの力） |
| 出力形態 | フロートの位置 → リンク棒 | スリーブの位置 → リンク棒 |
| 復帰力 | 重力（水位が下がればフロートも下がる） | 重力（回転が止まれば重りが戻る） |

#### 回転リレー（機械式トランジスタ）

ガバナーをクラッチと組み合わせると、水リレーの回転版になる：

```
入力シャフト（弱い回転でもOK）
    │
  [遠心ガバナー]  ← 回転を「スリーブ位置」に安定変換
    │
  スリーブ下降 ── リンク棒
    │
  [ドッグクラッチ] を接続
    │
動力シャフト ═══════════→ 出力（フル回転力）
```

- 入力が回転 → ガバナーの重りが広がる → スリーブ下降 → クラッチ接続 → 出力ON
- 入力が停止 → 重りが戻る → スリーブ上昇 → クラッチ切断 → 出力OFF
- 出力は常に動力シャフトからのフル回転力（信号復元）

#### 基本ゲート

**NOT — ガバナー＋クラッチ（逆接続）**

ガバナーのスリーブをクラッチに**逆接続**（スリーブ下降でクラッチ切断）。
- 入力ON → スリーブ下降 → クラッチ切断 → 出力OFF
- 入力OFF → スリーブ上昇 → クラッチ接続 → 出力ON

**AND — 直列クラッチ**

```
動力源 ══→ [クラッチA] ══→ [クラッチB] ══→ 出力
               ↑               ↑
         入力A(ガバナー)   入力B(ガバナー)
```

両方のガバナーがクラッチを接続したときだけ回転が伝わる。

**OR — 並列ラチェット**

```
入力A ──→ [ラチェットA] ──╲
                            ╲
                             ══→ 出力シャフト
                            ╱
入力B ──→ [ラチェットB] ──╱
```

- ラチェット（一方向クラッチ）は一方向にだけ回転を伝える（自転車の後輪ハブと同じ原理）
- 入力Aが回転 → ラチェットAが出力を駆動、ラチェットBは空転
- 入力Bが回転 → ラチェットBが出力を駆動、ラチェットAは空転
- ORゲートではガバナー不要（ラチェットが回転の有無を直接扱える）

#### 水理論理との比較

| 観点 | 水理論理 | 回転論理 |
|------|---------|---------|
| 信号媒体 | 水の流れ | シャフトの回転 |
| 配線 | 水路（タイルを占有） | シャフト＋ギア（空間効率が良い） |
| 集積度 | 低い（水路の引き回しに面積が必要） | 高い（シャフト上にガバナー・クラッチを積める） |
| 視認性 | 高い（水が見える） | 低い（回転は見えにくい） |
| 信号復元 | 水リレー（フロート弁） | 回転リレー（ガバナー＋クラッチ） |
| 新規パーツ | Y字合流のみ | ガバナー、ラチェット |
| 直感性 | 水やりの延長で理解しやすい | 歯車・機械好き向け |

両方を共存させる設計：
- **水理論理**: 農業の制御に自然に溶け込む。初心者向け
- **回転論理**: コンパクトで高速。機械好きの上級者向け
- 水と回転の**変換**はノーリアや水車で既に存在する

#### カムの正しい役割

カムは論理ゲートの信号変換器（回転の有無の検知）には使えないが、**シーケンサー**（回転のタイミングでアクションを発動）としては正しく機能する：

- **ガバナー**: 「回転している？」→ YES/NO（二値検知）
- **カム**: 「回転の何度目？」→ 特定タイミングで発動（パターン生成）
- **ピンシリンダー**: カムの多チャンネル版（複数出力の時間パターン）

### 機械式カウンタ（バベッジ的要素）

ディファレンスエンジンからゲームに持ち込める要素として、**歯車の角度位置を数値として扱う**という発想がある。

#### カウンタ歯車

```
  入力（1回転で1カウント）
      │
    [爪車（ラチェットホイール）]  ← 10歯なら10カウントで1周
      │
      ├── カウント値 = 歯車の角度位置
      │
    [桁上げ機構]
      │
    [次の桁の爪車]  ← 10カウントで1つ進む = 10の位
```

- 爪車（ラチェットホイール）が1クリックずつ進む
- 10歯の歯車なら0〜9をカウント
- 1周すると**桁上げ**で次の桁の歯車を1クリック進める（時計の分針→時針と同じ）

#### カウンタ＋カムによる「n回目に発動」

カウンタ歯車の**特定の位置にカム突起**をつける：

```
  日数カウンタ（day_changed イベントで +1）
      │
    [10歯の爪車]
      │
      ├── 5番目の歯にカム突起
      │        ↓
      │     フォロワーが押される
      │        ↓
      │     クラッチ接続 → 水門を開ける、台車を動かす、等
      │
    5日ごとに1回だけ作動する仕組み
```

プログラマブルタイマーとして機能する。ピンシリンダーが「1回転中の時間的パターン」を制御するのに対し、カウンタは「n回目のイベントで発動」を制御する。

#### ゲーム的な応用例

| カウンタの対象 | カム位置 | 発動する動作 |
|--------------|---------|-------------|
| 日数 | 5日目 | 水やり台車を発進 |
| 日数 | 7日目 | 収穫台車を発進 |
| 収穫回数 | 3回目 | 肥料散布を実行 |
| 水車の回転数 | 100回転目 | 貯水槽の水門を閉じる |

バベッジの「歯車の位置=数値」という発想の直接的な応用。ディファレンスエンジンほど複雑な計算は不要で、「カウント」と「特定値での発動」だけでゲーム的には十分強力。

### プリミティブの全体像

3つの系統と相互変換：

| 系統 | 信号媒体 | 信号変換器 | 増幅/復元 |
|------|---------|-----------|----------|
| **水理系** | 水の流れ | フロート（水位→位置） | フロート弁＝水リレー |
| **回転系** | シャフト回転 | ガバナー（回転→位置） | ガバナー＋クラッチ＝回転リレー |
| **時間系** | 回転の周期 | カム/ピンシリンダー（角度→発動） | エスケープメントで定速化 |
| 共通 | — | リンク棒＋ピボット | 力の伝達・方向変換 |

3系統は**相互に変換可能**：
- 水→回転: 水車、ノーリア
- 回転→水: ポンプ（シャフト駆動で水を汲み上げ）
- 回転→時間: エスケープメントで定速化

3系統の変換器がすべて「物理現象→位置→リンク棒→制御」という**同一パターン**に収まる。プレイヤーは1つのパターンを理解すれば、水でも回転でも応用できる。
