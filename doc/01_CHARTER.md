# プロジェクト憲章 - Stella Garden

## 1. プロジェクト基本情報

### 1.1 プロジェクト名
**Stella Garden** - かわいい女の子たちと楽しむチルな惑星開拓ゲーム

### 1.2 プロジェクト実行の背景・課題

#### 現状の課題
- 既存の箱庭ゲームは毎日プレイを強制する傾向があり、カジュアルに楽しみづらい
- 自動化要素のあるゲームは無機質になりがちで、キャラクターとの交流が少ない
- Factorio系ゲームは最適化に頭を使いすぎて、リラックスして遊べない
- 開発者自身が、メンタルヘルスに配慮しながら楽しめるゲームを必要としている

### 1.3 プロジェクトの目的・ゲーム概要

#### プロジェクトの目的
- 自分自身が癒されながら遊べるチルなゲームを作成する
- 思いついた時に軽く触るだけで楽しめる体験を提供する
- 開発過程をVtuber活動のコンテンツとして活用する
- 無理のないペースで、長期的に楽しめるゲームを育てる

#### ゲーム概要
かわいい女の子たちがミニキャラで動き回る、惑星開拓がテーマの箱庭ゲーム。プレイヤーは未開拓惑星に降り立ち、女の子たちと一緒に農業・加工・灌漑・自動化を少しずつ発展させていく。Factorioライクな自動化要素を持ちながらも、カジュアルでチルな雰囲気を重視する。進行の中心は、ジャガイモ・大豆・亜麻を軸とした持続可能な生産チェーンの構築と、水車・水門・導水路・ケーブル牽引などを使った素朴な自動化である。


## 2. プロジェクトスコープ

### 2.1 スコープ内の項目

#### 機能要件

**コアゲームプレイ（初期実装）**
- クオータービューもしくは真上視点のドット絵マップ表示
- 1キャラ×1惑星の開拓システム
- 農業を中心とした生産システム：
  - 手動での耕作・植え付け・水やり・収穫
  - 加工施設による中間素材・出荷品の生産
  - 水車・水門・導水路・ケーブル牽引を用いた半自動化・自動化
- 施設の配置・配置換えシステム（factorioライク）
- 基本的な自動化ループ
- ズーム操作（2本指ピンチ対応）

**初期実装の資源・施設**
- 資源2〜3種類ではなく、まずは木材・石・土・粘土・隕鉄と、ジャガイモ・大豆・亜麻まわりの農産物・加工品を中心に実装する
- 施設は農業と加工の基礎となるものを優先する（作業台、焚き火、堆肥場、脱穀機、炭焼き窯、炉、石の金床、搾油機、浸漬槽、紡ぎ車、織機など）

**キャラクターシステム**
- 高品質な立ち絵表示
- 高解像度ドット絵のミニキャラアニメーション
- 時間帯や状況に応じたセリフバリエーション
- 簡単な会話・イベントシステム

**収集要素（後追い実装予定）**
- 風景コレクション（スクリーンショット機能）
- レア資源・生物図鑑
- コスチュームバリエーション（性能変化なし）

**データ管理**
- ブラウザ内永続化によるセーブ機能
- クラウドバックアップ（オプション）
- SNS投稿機能（写真・動画）

#### 非機能要件
- ブラウザ上で動作（モバイル対応含む）
- サーバーレスまたは最小限のサーバー構成
- 軽量で快適な動作（1万オブジェクト表示対応）
- チルで癒される雰囲気・BGM・ビジュアル
- ほぼ無課金で遊べる設計

### 2.2 スコープ外の項目

**初期バージョンでは実装しない機能**
- 惑星間の資源輸送システム（後追い実装候補）
- ソーシャル機能（フレンドのみ）
  - フレンドの惑星に訪れることのできる要素のみ
- 課金システム
- チート対策（PvPなしのため優先度低）
- 近代的な電力・ホッパー中心の自動化システム

**対応しない項目**
- ネイティブアプリ版（初期はブラウザのみ）
- 3D表現
- 対戦要素

## 3. 前提条件と制約条件

### 3.1 前提条件
- 開発者は個人（1人）で、Vtuber活動と並行して開発を進める
- 開発過程を週一の動画コンテンツとして公開予定
- スモールスタートで、段階的に機能を追加していく方針

### 3.2 制約条件

#### 技術的制約
- ブラウザゲームとして実装（React Router使用）
- サーバー側：Cloudflare Workers + D1 + R2 + Hono
  - 無料枠内での運用を基本とする
- クライアント側にビジネスロジックを配置（サーバーレス優先）
- フロントエンド：React + PixiJS + pixi-viewport
- 2Dドット絵ベースのビジュアル
- 水システムは複雑な流体シミュレーションではなく、水面＝海面方式を基本とする
- 自動化は水車・水門・導水路・シャフト・ケーブル牽引など、前近代的で視覚的にわかりやすい仕組みを優先する

#### リソース制約
- 開発予算：ポケットマネー範囲内
- ビジュアル・女の子キャラクターには予算を優先配分
- アセットストア（itch.ioなど）の活用を検討
- 初期はダミーまたは汎用アセットで開発を進め、キャラ設定が固まってから本番イラストを発注
- UIや演出は、複雑な数値表示よりも「畑・水・機械が動いている様子を眺めて理解できる」方向を優先する

#### 運用制約
- サーバーコストは最小限に抑える（無料枠内を目指す）
- 将来的にユーザーが増えた場合、クラウド同期を有料オプションにする可能性
- 開発ペースは無理のない範囲で調整（週単位の小さなマイルストーン）
- メンタルヘルスを最優先し、できない週があっても問題なしとする
