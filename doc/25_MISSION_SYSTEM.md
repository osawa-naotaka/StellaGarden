# ミッションシステム設計 - Stella Garden

> **このドキュメントの位置づけ**
>
> Stella Garden のチュートリアル・進行ガイド機能としてのミッションシステムの**正式な設計書**である。
> プレイヤーが基本操作から袋詰め大豆の出荷までを、自然にストレスなく学べるようにすることを目的とする。
>
> **関連ドキュメントとの関係**
>
> - `15_RE_SYNOPSIS.md` — 格付け（D〜S級）と入植船到達というゲーム全体のゴール
> - `22_REPUTATION_SYSTEM.md` — 出荷品目ごとの Tier アンロック仕様
> - `23_USAGE.md` — プレイガイド全文（本書のミッションは原則ここの導線を踏襲する）
>
> ミッションシステムは上記の Tier アンロックを置き換えるものではない。
> **アンロック判定は累積出荷量で行われる既存仕様のまま**であり、
> ミッションは「次に何をすべきかを示す道標」「やり方を教えるガイド層」として機能する。

---

## 1. 設計方針

### 1.1 目的

第一の目的は、**プレイヤーへの操作説明を自然にストレスなく行うこと**である。
従来、操作の説明は `doc/23_USAGE.md` のような GUIDE 画面のみで提供されており、
プレイヤーは自分でドキュメントを読まなければ進行が分からなかった。

第二の目的は、**プレイヤーのモチベーションを上げること**である。
NPC（後輩キャラ）との会話を通じて段階的に目標が提示されることで、
「次に何をやろうか」という小さな目標が常に手元にある状態を作る。

### 1.2 基本原則

- **チル原則の維持**: ミッションは案内であり、強制ではない。スキップ・先送り・無視を許容する
- **アンロック仕様を変更しない**: Tier アンロックは累積出荷量で動く既存仕様のままとする
- **並列フラグモデルによる判定**: 全ミッションが裏で並列にイベントを購読し、達成フラグを立てる。表示は線形だが状態は並列
- **NPC の立ち絵は節目の会話時のみ表示**: 同行設定を活かし、メインミッション開始/完了などの節目では ADV 型のモーダル会話で立ち絵と共に登場する。日常的な進行ガイドは左下ミッションウィンドウで行う
- **会話中はゲーム時間を停止**: ADV 型会話の表示中はゲーム内時間を停止する。「読まされて急かされる」感覚を防ぎ、チル原則を保つため
- **UI は最小限**: 左下のミッションウィンドウには現在のメイン・サブを各 1〜2 行で表示するだけにとどめる

## 2. システム概要

### 2.1 NPC（後輩キャラ）

#### 設定

プレイヤーと共にこの惑星に派遣された**後輩の女性キャラクター**である。
プレイヤーとはパーティを組んで常に同行している設定とし、
画面上のプレイヤーキャラクターは「パーティ全体を記号化した存在」として扱う。

これは JRPG での「画面上は主人公 1 人だが、設定上は仲間が同行している」表現と同じであり、
プレイヤーは違和感なく受け入れられる。

トップビュー上の通常プレイ中は後輩キャラを画面に出さないが、
**ADV 型会話シーン中はバストアップ（首から上）の立ち絵が会話ウィンドウ左端に表示される**。
常に同行している設定なので、すぐ隣にいる後輩から話しかけられるという表現は自然である。

#### 役割

- **ミッションの提示**: 各メインミッションの冒頭で、後輩から ADV 型会話で目標が示される
- **操作の説明**: サブミッションを通じて、具体的な操作を 1 つずつ左下ウィンドウで案内する
- **完了時のリアクション**: メインミッション完了時に、ADV 型会話で次の目標へ繋ぐ
- **将来的な役割**: 詰まった時のヒント、雑談、季節フレーバーなど（本書のスコープ外）

#### 名前・性格・口調

本書では仮置きとし、別途決定する。
ただし以下の方向性は推奨される。

- **押し付けがましくない**: 急かしたり、教師的に振る舞わない
- **明るく前向き**: 失敗してもフォローする側に回る
- **適度な親しみやすさ**: 敬語で喋り、プレイヤーのことを「先輩」と呼ぶ

### 2.2 ミッション構造

#### メインミッションとサブミッション

ミッションは 2 階層構造を持つ。

- **メインミッション**: ゲーム進行上の大きな目標（例: 「じゃがいもを出荷しよう」）
- **サブミッション**: メインを達成するための具体的な手順（例: 「畑を耕そう」）

同時に表示されるのは**メイン 1 個 + サブ 1 個のみ**。
サブを完了すると次のサブが自動的に表示され、最後のサブを完了するとメインが完了する。

#### 進行フロー

```
[メインミッション開始]
   ↓ 後輩との ADV 型会話（時間停止モーダル）→ 会話ログに保存
[サブ 1] → 完了 → [サブ 2] → 完了 → ... → [サブ N] → 完了
   ↓
[メインミッション完了] → 後輩との ADV 型会話 → [次のメインミッション開始]
```

サブを順番に 1 個ずつ消化する線形フローとする。分岐や並列サブは設けない。

`doc/22_REPUTATION_SYSTEM.md` の Tier 3（亜麻仁油 / 大豆油）と Tier 6（袋詰めじゃがいも / 袋詰め大豆）は仕様上は並行アンロックだが、本書のミッションでは実装簡略化のため線形に並べる（§5 参照）。

### 2.3 既存システムとの関係

#### Tier アンロックとの関係

- Tier アンロックは**累積出荷量による判定**で従来通り動作する
- ミッションは Tier アンロックの**先行ガイド**として機能する
  - 例: Tier 2 がまだアンロックされていなくても、「大豆を育ててみよう」というミッションを進められる
  - プレイヤーが準備を整えている間に、累積出荷量が閾値に達し、自動的にアンロックされる
- ミッションを無視しても Tier アンロックは進む（チル原則）

#### イベントシステムとの関係

ミッションの進捗判定は、既存の `EventBroker<GameEventMap>` を購読する形で実装する。
詳細は §4 を参照。

## 3. UI 設計

UI は大きく 3 つの要素で構成される。

- **左下のミッションウィンドウ**: 現在のメイン・サブを常時表示する小型 UI（§3.1）
- **ADV 型会話ウィンドウ**: メインミッション開始/完了などの節目に、画面下部の横長セリフ枠と立ち絵で会話を表示するモーダル UI（§3.2）
- **会話ログ**: 過去の会話を読み返せる UI（§3.3）

### 3.1 左下のミッションウィンドウ

#### 表示内容

画面左下に、半透明の小さなウィンドウを常時表示する。

```
┌─────────────────────────────┐
│ [メイン] じゃがいもを出荷しよう  │
│ [サブ] 鎌でじゃがいもを収穫しよう │
└─────────────────────────────┘
```

- **メインミッション**: 1〜2 行のタイトル文
- **サブミッション**: 1〜2 行の具体的な指示文
- 文字数は各行 30 文字以内を目安とする

#### 表示ルール

- 全てのミッションを完了した状態（最終ゴール到達後）では、ウィンドウは表示しない
- ミッション開始前のオープニング時点では、最初のミッションを開始するためのプロンプトを表示する
- プレイヤーがゲーム内 UI（インベントリ・施設サイドバーなど）を開いている間も、ミッションウィンドウは表示し続ける
- ADV 型会話ウィンドウが表示されている間も、左下ミッションウィンドウは引き続き表示してよい（次の目標を確認しながら会話を読めるようにする）

### 3.2 ADV 型会話ウィンドウ

#### 概要

メインミッション開始/完了などの節目で、後輩キャラとの会話を ADV（アドベンチャーゲーム）型のモーダル UI で表示する。
ゲーム時間を停止し、プレイヤーがじっくり読めるようにする。

#### レイアウト

画面下部に横長のセリフ枠を表示し、左端に後輩キャラのバストアップ立ち絵を配置する。

```
┌──────────────────────────────────────────────┐
│ ┌──────┐                                    │
│ │ 立ち絵 │  後輩（キャラ名）                  │
│ │ 首から │  「先輩、じゃがいも収穫できましたね！│
│ │ 上のみ │   次は地球へ送ってみましょう。」    │
│ └──────┘                              ▼     │
└──────────────────────────────────────────────┘
```

- **立ち絵**: 首から上（バストアップ）のみ、セリフ枠の左端
- **セリフ枠**: 横長、画面下部
- **キャラ名表示**: セリフ枠内の話者名表示
- **進行マーク**: 続きがある場合はセリフ枠右下に「▼」等のマーカーを出す

#### 操作

- **任意の場所をクリック**で次のセリフへ進む（クリックで進行）
- **会話中はゲーム時間を停止**する。プレイヤー操作も無効化される
- **全文スキップ**を用意する（仮: `Esc` キーまたはスキップボタン、要検討）
- 会話終了でモーダルが閉じ、ゲーム時間が再開する

#### 表示タイミング

ADV 型会話は以下の節目で表示する。

- **メインミッション開始時**: 後輩が新しい目標を提示する
- **メインミッション完了時**: 後輩がリアクションし、次の目標へ繋ぐ
- **特別なイベント時**: ゲーム開始時のオープニング、M-17 完了時のエンディングなど

サブミッションの細かい指示では ADV 型会話は使わず、左下ウィンドウのみで案内する。
会話過多を避けるためである。

### 3.3 会話ログ

#### 概要

後輩との会話履歴を蓄積し、いつでも見返せる UI を提供する。

- 左下のミッションウィンドウとは別の UI
- 開閉のショートカットキーを用意（仮: `M` キー、要検討）
- 過去の全会話を時系列で閲覧可能
- 進行中のミッションに紐づく会話は強調表示

#### 役割

- 会話の読み返し・聞き逃した内容の確認
- フレーバーテキスト・世界観説明の参照
- 将来的に雑談や季節フレーバーを追加した際の閲覧手段

### 3.4 完了演出

#### サブミッション完了時（プレイヤーが今その操作を行った場合）

プレイヤーが現在表示中のサブミッションに対応する操作を行った瞬間、左下 UI で**短い完了演出**を行う。

- ✓ アイコンが現れ、サブミッションの文字が薄くフェードアウトする
- 1〜2 秒の余韻の後、次のサブミッションが表示される（フェードイン）

これにより「ベルトコンベア感」「急かされる感」を防ぐ。

#### 既達成サブミッションが表示順になった場合

並列フラグモデル（§4 参照）により、ミッション表示前にプレイヤーが先取りで操作を完了している場合がある。
その場合、初期実装では**既達成サブは UI に表示せず、次の未達成サブへ静かにスキップする**（パターン B）。

- ✓ 演出を行わない（連続して既達成だった場合に違和感が出るため）
- 演出付きスキップ（パターン A）は将来検討（§7.5）

#### メインミッション完了時

メインミッション完了時には、後輩との ADV 型会話が挟まる。

- §3.2 の ADV 型会話ウィンドウを使ってモーダル表示
- ゲーム時間は停止し、プレイヤーがじっくり読める
- 会話終了後、自動的に次のメインミッションが始まり、開始用の ADV 型会話が表示される
- 会話内容は会話ログ（§3.3）に蓄積される

### 3.5 将来検討: フローチャート / リスト表示

メイン・サブの全体像を確認したいプレイヤー向けに、以下を将来検討する。

- メインミッションのみを並べた**リスト表示**（完了したものは ✓ マーク）
- メイン・サブを全て俯瞰する**フローチャート表示**（並行アンロック分岐を含む）

これらは初期実装では不要だが、UI 設計時に拡張余地を残しておく。

## 4. 進捗判定

### 4.1 並列フラグモデル

ミッションシステムは「現在進行中のミッションは何か」というステートを**持たない**。
代わりに、**各メインミッション/サブミッションが独立した達成済みフラグを持つ**設計とする。

- システム起動時に、全ミッションのイベントリスナーが一度だけ登録される
- 対応するイベントが発火すると、関連するフラグが立つ（複数のフラグが同時に立つこともある）
- 表示すべきミッションは、現在の達成済みフラグから動的に導出する
- 「次にどのミッションを表示するか」は状態として保持せず、毎回フラグから計算する

#### 状態として保持するもの

セーブデータに保持するのは、各ミッション/サブの**達成済みフラグのリスト**のみ。

- 進行中ミッション ID、現在のサブ番号などのカーソル状態は持たない
- これにより不整合バグの余地がなくなり、セーブデータも軽くなる

### 4.2 イベントベース判定

各サブミッションの完了条件は、**EventBroker が発行する特定のイベント**で定義する。

例:

| サブミッション | 完了条件（イベント） |
|---|---|
| 畑を耕そう | `terrain_changed` で grass → soil への変化が発生した |
| じゃがいもを植えよう | `entity_placed` で potato（stage=0）が配置された |
| 作業台を作ろう | `item_crafted` で workbench が生成された |
| じゃがいもを出荷しよう | `item_shipped` で potato が出荷された |

- 完了条件は**単一イベントの発火**で判定する
- 「N 個収穫する」など回数指定は最小限にとどめる（基本は 1 回でクリアとする）
- メインミッションは「属する全サブミッションが達成済み」になったら自動的に達成扱いとなる

例外として、Tier アンロックなど累積系の判定が既に達成されているサブミッションは、システム起動時に即座にフラグを立てる扱いとする（同じ出荷をもう一度要求する意味がないため）。

### 4.3 表示優先度（順序づけ）

メインミッションには静的な順序番号（`order`）を振る。同じメインに属するサブにも順序番号を振る。

- **メインの表示**: 未達成のメインのうち、`order` が最も小さいものを 1 個選んで表示する
- **サブの表示**: 表示中のメインに属する未達成サブのうち、`order` が最も小さいものを 1 個選んで表示する
- 線形フローを維持するため、複雑な依存関係グラフは使わない

### 4.4 先回りプレイヤーの自然な対応

並列フラグモデルにより、プレイヤーが現在のミッションとは無関係の操作を先取りしても、
裏で対応するフラグが立つ。後でそのミッションが表示順になったとき、既達成のため
自動的にスキップされる。

- 例: M-02（じゃがいも栽培）の最中にシャベルで土を削った → M-04 のシャベル系サブのフラグが立つ
- 後で M-04 が表示される番になったとき、シャベル系サブはスキップされ、次の未達成サブから始まる

「再度同じ操作をさせる」設計はこれにより不要となる。「もう作業台あるのに、また作るの？」という違和感は発生しない。

既達成サブの表示時の挙動については §3.4 を参照（初期実装はパターン B = 静かにスキップ）。

### 4.5 設計上の利点

- 「現在の進行ミッション」というカーソル状態を持たなくて済む
- セーブデータが軽い・不整合バグが起きない
- イベント購読の動的管理（開始時に subscribe / 完了時に unsubscribe）が不要、起動時に張りっぱなしで OK
- 先回りプレイヤーへの対応が自然に成立する
- 同じ操作が複数ミッションの達成条件になる場合も、両方のフラグが同時に立つだけで自然に処理できる

## 5. ミッションリスト

本節では、本作のミッション全体を具体的に列挙する。
各ミッションは `M-XX` の通し番号で識別する。

### 5.1 全体像

```
M-01: ようこそ、Stella Garden へ（基本操作）
M-02: 食糧を確保しよう（初めての農業）
M-03: 地球へ最初の出荷をしよう（転移ゲート）
M-04: 土地を整えよう（地形・採取）
M-05: 作業台を立てよう
M-06: 肥料を作ろう（草木灰・堆肥）
M-07: 連作障害に対処しよう（輪作・ひまわり）
M-08: 大豆を育てよう
M-09: 大豆を脱穀して出荷しよう
M-10: 鉄製道具を作ろう（金属加工）
M-11: 板を作ろう（割り刃の使い方）
M-12: 灌漑を整えよう（畝間水路）
M-13: 油を搾ろう（搾油機）
M-14: 亜麻を育てよう
M-15: 糸を作って出荷しよう
M-16: 布を織って出荷しよう
M-17: 袋詰め大豆を出荷しよう ★ゴール
```

### 5.2 各ミッションの詳細

#### M-01: ようこそ、Stella Garden へ

**メイン**: 「この惑星を歩いてみよう」

| サブ | 内容 | 完了条件 |
|---|---|---|
| 1 | WASD で歩いてみよう | プレイヤーが一定距離移動した |
| 2 | マウスホイールでズームしてみよう | ズーム操作が行われた |
| 3 | E キーでインベントリを開いてみよう | インベントリが開かれた |

#### M-02: 食糧を確保しよう

**メイン**: 「じゃがいもを 1 つ収穫しよう」

| サブ | 内容 | 完了条件 |
|---|---|---|
| 1 | くわを選んで草地を耕そう | grass → soil の地形変化イベント |
| 2 | じゃがいもを植えよう | potato エンティティが配置された |
| 3 | 成熟まで待とう（約 5 ゲーム内日数） | crop_growth_stage = 5 になった |
| 4 | 鎌で収穫しよう | じゃがいもの収穫イベント |

> **補足**: 待ち時間は早回し UI で短縮可能。本ミッションを通じて早回しの存在も会話で示す。

#### M-03: 地球へ最初の出荷をしよう

**メイン**: 「じゃがいもを地球へ送ろう」

| サブ | 内容 | 完了条件 |
|---|---|---|
| 1 | 転移ゲートを設置しよう | 転移ゲートが配置された |
| 2 | 転移ゲートにじゃがいもを入れよう | 地球側インベントリにじゃがいもが入った |
| 3 | 朝 5 時の出荷を待とう | 出荷イベントが発火した |

#### M-04: 土地を整えよう

**メイン**: 「素材を集めて土地を整えよう」

| サブ | 内容 | 完了条件 |
|---|---|---|
| 1 | シャベルで土を削ってみよう | 土の採取イベント |
| 2 | 土を盛ってみよう | 土の配置イベント |
| 3 | 斧で木を切ろう | 木の幹の取得イベント |
| 4 | ピッケルで石を採取しよう | 石の取得イベント |

#### M-05: 作業台を立てよう

**メイン**: 「クラフトの拠点を作ろう」

| サブ | 内容 | 完了条件 |
|---|---|---|

## 6. セーブデータマイグレーション

### 6.1 方針

本システム導入時、セーブデータには以下を適用する。

- セーブデータに「ミッション達成済みフラグのリスト」フィールドを追加する
- マイグレ時は全フラグを **`false` で初期化** する
- 既存セーブからの所持アイテム・施設のスキャンなどの**特別な初期化処理は行わない**
- フラグはゲームプレイ中のイベント駆動でのみ立っていく

### 6.2 既存セーブとの互換性

- 既存セーブにミッションフラグフィールドがない場合、ロード時に空配列（または全 `false` 配列）を追加する
- 累積系の判定（Tier アンロック）は既存仕様のまま動作するため、既にアンロック済みの Tier 情報は維持される
- §4.2 の例外規定に従い、累積系で既に閾値を超えているサブミッションは起動時にフラグが立つ

### 6.3 理由

- 本作は現在アルファ版であり、プレイ人口が極めて限定的（実質的に開発者のみ）
- 並列フラグモデル（§4.1）により、特別な初期化処理を実装する必要がそもそもない
- 既存セーブで先回り済みの操作（既に持っている作業台など）については、ミッションが表示順になったタイミングで再度操作するか、§7.5 の自動スキップ機能を将来実装したときに対応する

将来、ベータ版・正式版への移行時に、必要であれば再検討する。

## 7. 将来検討事項

### 7.1 ゲームコンフィギュレーション機能

ゲーム全体の設定を保存・編集する画面と機能は、現在存在しない。
ミッション機能オフモードを始めとして、複数の機能で必要性が出てくる見込みである。

- 設定画面の UI 設計
- 設定の保存形式（ローカルストレージ / セーブデータ内に統合）
- 設定可能な項目の列挙

ミッションシステムは、初期実装ではコンフィグなしで動作する。
将来のコンフィグ機能実装時にミッション関連項目を追加する。

### 7.2 ミッション機能オフモード

慣れたプレイヤー・ガイドが不要なプレイヤー向けに、ミッション機能を完全に無効化するモード。

- 左下のミッションウィンドウを非表示
- ADV 型会話を抑止（あるいは自動スキップ）
- 会話ログも非表示
- イベント購読は停止（パフォーマンス的にもメリット）

実装はコンフィギュレーション機能と一緒に行う。

### 7.3 全画面フローチャート / リスト表示

§3.5 で触れた、ミッション全体を俯瞰する UI。

- リスト表示: メインミッションを縦に並べ、完了状態を ✓ で示す
- フローチャート表示: 並行アンロック構造（M-16a/b）を含む全体像を視覚的に表示

### 7.4 並列サブミッション

§2.2 で「並列サブは設けない」としたが、待ち時間中のプレイヤーの手持ち無沙汰を解消するため、
将来的に副次サブを差し込む案は残されている。

例: 「成熟まで待とう」のサブと並行して、「その間に焚き火を作ってみよう」を表示する。

ただし以下の理由から初期実装では見送る。

- メイン 1 + サブ 1 のシンプルさを守る
- 早回し UI で待ち時間そのものを短縮できる
- 設計・UI ともに複雑化する

### 7.5 完了演出パターン A（既達成サブの ✓ 表示）

§3.4 で初期実装はパターン B（既達成サブを静かにスキップ）としたが、
将来的にパターン A（既達成サブを一瞬 ✓ 演出付きで表示してからスキップ）を検討する余地はある。

- パターン A はプレイヤーに「進捗した感」を与えやすい
- ただし連続して何個も既達成サブがある場合、✓ が連続して出て違和感が生じる
- 「まとめて 1 つの ✓ 演出にする」「一定数以上は静かにスキップする」等の工夫が必要

### 7.6 起動時の状態スキャン

既存セーブからの所持アイテム・施設をスキャンして、対応するミッションフラグを起動時に立てる機能。

- 並列フラグモデル（§4.1）のおかげで、これがなくても動作上問題はない
- ただし、既存セーブで既に作業台を建てているプレイヤーが M-05 で「作業台を作ろう」と再度言われるのは違和感がある
- ベータ版・正式版でプレイ人口が増えたら検討する価値がある
- 実装するなら、各ミッション定義に「既達成スキャナ関数」をオプションで持たせる形が綺麗

### 7.6 軽口吹き出し演出

ADV 型会話は節目専用としているため、ゲーム中の細かい場面（朝 5 時の挨拶、収穫直後の一言、季節の変わり目など）では後輩キャラの存在感が薄くなる。
これを補うため、軽量な「吹き出し演出」を将来追加する案。

- プレイヤーキャラの傍に小さな立ち絵と短い吹き出しが一瞬出る
- 1〜2 行の短文のみ、放置で自動フェードアウト
- ゲーム時間は停止しない（チル原則を壊さない）
- クリック・任意キーで即時クローズ可能

これにより、ADV 型会話の節目以外でも、後輩キャラの「同行している感」を演出できる。
ただし初期実装では見送り、ADV 型会話と会話ログの基盤が安定してから検討する。

### 7.7 後輩キャラの詳細設計

- 名前
- 性格・口調
- ビジュアル（バストアップ立ち絵の表情差分、将来フィールド上に登場する場合のドット絵など）
- 会話バリエーション（雑談・季節フレーバー・プレイヤーの行動への反応）
- 詰まったプレイヤーへの救済ヒント機能

### 7.8 ミッション以外のガイド機能との統合

`doc/23_USAGE.md` の GUIDE 画面は、ミッションと並行して引き続き提供する想定。
ただし、両者の役割分担と相互参照は今後整理する。

- GUIDE 画面 = 全機能のリファレンス（百科事典的）
- ミッション = 進行順の段階的ガイド（ストーリー的）

## 8. 実装メモ

### 8.1 想定モジュール構成

ミッションシステムは PixiJS 非依存のロジック層と、表示層の UI に分けて実装する。

- `src/engine/MissionSystem.ts` — ミッション進行状態の管理、イベント購読、完了判定
- `src/engine/MissionDefs.ts` — ミッション定義データ（M-01〜M-17 の構造化データ、各メインに紐づく会話スクリプトへの参照を含む）
- `src/engine/DialogScripts.ts` — ADV 型会話のセリフデータ（話者・テキスト・立ち絵差分など）
- `src/view/MissionView.ts` — 左下の透過ウィンドウ
- `src/view/DialogView.ts` — ADV 型会話ウィンドウ（立ち絵 + セリフ枠 + クリック進行）。表示中はゲーム時間を停止
- `src/view/ChatLog.ts` — 会話ログ UI

詳細な API・データ構造は実装フェーズで設計する。

### 8.2 イベント追加の見込み

既存の `GameEventMap` には未定義のイベントが本書のミッションに必要となる。
実装時には、`_boundary/events.ts` に必要なイベントを追加してから各モジュールを更新する。

追加が予想されるイベント（一例）:
- `crop_harvested` — 作物の収穫
- `item_crafted` — アイテムのクラフト
- `entity_placed` — エンティティの配置
- `item_shipped` — 転移ゲートからの出荷
- `tool_attached` — 作業台へのツール装着

具体的なイベント設計は実装時に確定する。
