## 1. 設計方針

### 1.1 背景

- 現在実装されているのは、じょうろを使った手動での水やりのみ
- 毎日の水やりは手間が大きく、栽培面積が広がると管理が破綻する
- 自動化の段階を「手動→半自動→全自動」に設計し、各段階にそれぞれ楽しさを持たせたい
- Factorioのように、段階的な自動化がプレイヤーの成長体験を生むことを目指す

### 1.2 基本原則

- `10_RIVER.md` の水システム（水面＝海面方式）と整合すること
- `04_FEASIBILITY_STUDY.md` のうち、現在も有効な「水車・歯車・カム等の思想」と接続すること
- 水のシミュレーション（水量計算・フラッドフィル等）は行わない
- 灌漑の制御には「水門の開閉」という物理的操作を基本とする
- **水タイルから畑（soil/wetSoil）への直接的な水供給は行わない** — 畑への散水は必ず畝間水路またはじょうろを経由する
- 旧来の `waterSource` / `flowedWater` 前提の説明は、検討履歴としては残っていても、正式仕様としては採用しない

### 1.3 水タイルから畑への直接供給を行わない理由

- 水辺の畑に常時水が供給されると、水浸しロジック（4章）により作物が育たなくなる
- 水門を閉じても水辺の畑には水が供給され続けるため、水門の開閉が無意味になる
- 現実の農業でも、川の隣に畑があっても畝の高さがあれば水は入らない — 水路から畝間に水を引き込んで初めて灌漑になる
- 散水エンティティ（畝間水路）を経由させることで、水門による灌漑制御が全ての畑で一貫して機能する

## 2. 水の挙動の拡張

> **旧案との関係**  
> この章では、灌漑のために必要な「水の扱い」を説明する。  
> ただし、ここでいう水の扱いは **`10_RIVER.md` の正式仕様を前提にした拡張** であり、過去に検討された `waterSource` / `flowedWater` ベースの旧案をそのまま採用するものではない。  
> 旧案は検討履歴として参照可能だが、実装仕様としては本章と `10_RIVER.md` を優先する。

### 2.1 現在の水の挙動

- 地形生成時: `h < horizonHeight` のタイルに水を配置
- ゲーム中: 掘った結果 `h < horizonHeight` かつ **隣接タイルに水がある** 場合に水になる
- 山中で水平線以下まで掘っても、水に隣接していなければ水は出ない

### 2.2 旧案: 水源と流水の区別（現在は不採用）

> **現在は不採用**  
> 以下は、灌漑を成立させるために一時期検討していた旧案である。  
> 当時は `waterSource` / `flowedWater` を分けることで水の接続性を表現しようとしていたが、現在の正式仕様では **水面＝海面方式** を採用しているため、この区別は正規仕様ではない。  
> したがって、この節は**検討履歴として残す**。
>
> **現在の正式方針**
>
> - 水の存在は地形高さと海面の比較で決まる
> - 灌漑の接続判定は、水タイルそのものの種類分けではなく、**導水路・畝間水路・水門の接続関係**で扱う
> - 実装仕様としては `10_RIVER.md` を優先する

水タイルを2種類に区別する:

| 種別 | テレインタイプ | 生成タイミング | 性質 |
|---|---|---|---|
| 水源 (waterSource) | `TERRAIN_TYPES.waterSource` | 地形生成時のみ | 永続。BFSの起点。埋めると不可逆に消滅 |
| 流水 (flowedWater) | `TERRAIN_TYPES.flowedWater` | プレイヤーが掘った時 | 水源からBFSで到達可能な場合のみ存在 |

**水源の破壊:**

- プレイヤーが水源タイルを土で埋めると、その水源は不可逆に消滅する
- 水源消滅時、関連する流水タイルを全水源から再計算（BFS）し、到達不能になったタイルの水を除去する
- 水源を埋める操作は稀なため、再計算のコストは問題にならない

### 2.3 素掘り水路と石組み水路

導水路に2つの段階を設ける:

| 種類 | コスト | 効果 | フレーバー |
|---|---|---|---|
| 素掘り水路 | 無料（掘るだけ） | 水は流れるが、**水源からBFS距離N（3〜5マス程度）で浸透して消える** | 土の溝に水を流すと地面に染み込む |
| 石組み導水路（レンガ導水路） | 粘土→焼きレンガが必要 | 水源からの**距離制限なし**で水が流れる | 石やレンガで固めれば漏水しない |

**設計意図:**

- 「掘れば水が流れる」という直感は維持する
- 序盤は素掘りで川のすぐ隣に小さな畑を作れる（短い距離なら素掘りで十分）
- 大規模灌漑には石組み導水路が必要 → リソース投資が必要になる
- 水量シミュレーション不要。水源からのBFS距離でカウントするだけ
- 制約の理由が物理的に納得できる（土に染み込む vs 防水された水路）

## 3. 灌漑の段階

> **正式方針**  
> この章で示す段階設計が、現在の灌漑進行の正式方針である。  
> 旧来の「水辺に置くだけで自動散水される設備」や「近代的スプリンクラー中心」の案は採用していない。  
> Stella Garden の灌漑は、**じょうろ → 水門付き水路 → 石組み導水路 → 水車による自動開閉 → ノーリアによる揚水** という、歴史的にも自然な発展をたどる。

### 3.1 段階一覧

| フェーズ | 灌漑方法 | プレイヤーの手間 | 必要な設備 |
|---|---|---|---|
| 序盤① | じょうろで手動水やり（現在実装済み） | 毎日、1マスずつ | じょうろ |
| 序盤② | 川沿いに素掘り水路＋水門＋木製畝間水路で散水 | 毎日、水門を開け閉め | 素掘り水路 + 水門 + 木製畝間水路 |
| 中盤① | 石組み導水路で遠方まで導水＋木製畝間水路で散水 | 毎日、水門を開け閉め（範囲は広い） | 焼きレンガ導水路 + 水門 + 木製畝間水路 |
| 中盤② | 水車＋カムで水門を自動開閉（doc/04の仕組み） | 設置のみ、あとは放置 | 水車 + 歯車 + カム |
| 後半 | ノーリアで高台にも揚水、大規模灌漑 | 設計のみ | ノーリア + 導水路 + 自動水門 |

### 3.2 序盤①: じょうろ（現在実装済み）

- 手動で1マスずつ水やり
- 最も手間がかかるが、最初はこれしかない
- 栽培面積が広がるほど負担が増え、自動化への動機になる

### 3.3 序盤②: 素掘り水路＋水門＋木製畝間水路

- 川から素掘り水路を掘り、水門エンティティを設置する
- 水門の先に**木製畝間水路**を設置し、畑に散水する
- 水門を開く → 素掘り水路に水が流れ → 畝間水路を通じて畑に水が供給される
- 水門を閉じる → 水が止まり、畝間水路からの散水も停止する
- **じょうろより明確に楽**（畝間水路の範囲内の畑に一括で水やりできる）
- **でも完全放置はできない**（毎日開け閉めが必要）
- **次の自動化へのモチベーションになる**（「この開け閉めも自動化したい！」）
- 素掘り水路の距離制限があるため、川から近い範囲に限られる

```
イメージ（序盤②）:
  川川川川川川川川川川川  ← 水源
  ====[水門]====        ← 素掘り水路（距離制限あり）+ 水門
  　　　↓
  　[畝間水路→→→]       ← 木製畝間水路（方向: 横向き）
  　畑畑畑畑畑畑畑畑     ← 畝間水路の上下nマスに水供給
  　畑畑畑畑畑畑畑畑
  　畑畑畑畑畑畑畑畑
  　[畝間水路→→→]       ← もう一本
  　畑畑畑畑畑畑畑畑
  　畑畑畑畑畑畑畑畑
  　畑畑畑畑畑畑畑畑
```

### 3.4 中盤①: 石組み導水路＋木製畝間水路

#### 導水路

- 焼きレンガで作った石組み導水路は距離制限なく水を運べる
- 川から離れた場所にも大規模な畑を作れるようになる
- 素掘り水路の距離制限を超える大規模灌漑が可能になる

#### 木製畝間水路（散水）

- 導水路から分岐して畑の中に設置する散水用エンティティ
- 畝間水路の素材は木材。防水性は不要（水を漏らして畑に浸透させるのが目的）
- 焼きレンガは長距離導水路に使い、畝間水路は木材で十分という素材の役割分担

```
イメージ（中盤①）:
  川川川川川川川川川川川  ← 水源
  ■■■■[水門]■■■■■■    ← 石組み導水路（距離制限なし）+ 水門
  ■                     ← 石組み導水路（長距離を導水）
  ■                     ← 石組み導水路
  ■
  ■→[畝間水路→→→]       ← 導水路から木製畝間水路に分岐
  　　畑畑畑畑畑畑畑畑
  　　畑畑畑畑畑畑畑畑
  　　畑畑畑畑畑畑畑畑
  ■→[畝間水路→→→]
  　　畑畑畑畑畑畑畑畑
  　　畑畑畑畑畑畑畑畑
  　　畑畑畑畑畑畑畑畑
```

### 3.5 中盤②: 水車＋カムによる水門自動開閉

- doc/04_FEASIBILITY_STUDY.md のカム＋カウンター機構を使用
- 水車の回転力で水門を定期的に開閉する
- 設置すれば完全に自動化され、プレイヤーの介入は不要
- 「設計して組み上げる楽しさ」がここにある

### 3.6 後半: ノーリアによる揚水

- doc/10_RIVER.md のノーリア設計に準拠
- 川の水を高台に汲み上げ、そこから導水路で配水
- 農地を水平線レベル以外にも拡張できるようになる

## 4. 水浸しロジック

> **注記**  
> 本章は灌漑に失敗した場合の将来的な深みとして設計されたものである。  
> ただし、現時点では `10. 今後の検討事項` にある通り、**水のやりすぎによる悪影響は正式導入していない**。  
> したがって、この章は「将来導入しうる設計案」として読むこと。

### 4.1 基本ルール

- 畝間水路から水を供給し続けると、作物が水浸しになる
- 一日のうちn時間以上水が供給されると、作物の発育が悪化する
- 「水門を開けっ放しにすれば楽」とはならない設計

### 4.2 作物ごとの耐水性（案）

- 作物ごとに水浸し耐性を変える
- 例: 大豆は水に弱い（6時間で発育停止）、ジャガイモはそこそこ耐える（12時間）
- 畑のレイアウトを作物ごとに変える必要が生まれ、農業設計の深みが増す
- 水門の開閉タイミングを間違えると一部の作物がダメになるリスク → 自動化の動機がさらに強まる

### 4.3 水門による制御

- 水門を開く → 水が流れ、畝間水路を通じて畑に水が供給される
- 適切な時間が経過したら水門を閉じる → 水が止まる
- 序盤は手動で開閉（毎朝開けて、夕方閉める、など）
- 中盤以降は水車＋カムで自動制御

## 5. 畝間水路の水供給ロジック

> **正式仕様としての位置づけ**  
> この章は、現在の灌漑システムの中核となる正式仕様である。  
> とくに以下は本ドキュメントの重要な確定事項である。
>
> - 畝間水路は灌漑の主役である
> - 水門は伝播チェーンの特殊ノードとして機能する
> - 散水は直線・端末の畝間水路からのみ行う
> - L字・T字・十字は導水専用であり、散水しない

### 5.1 概要

畝間水路はエンティティとして畑に設置する散水装置である。水タイルから畑への直接供給は行わず、畝間水路を経由して水を畑に届ける。

### 5.2 水の伝播ルール

1. 畝間水路エンティティのどこかが **水タイル（water/waterSource）に隣接** している
2. その隣接点を **距離0** として、畝間水路エンティティ同士で **BFS距離m** まで水が伝播する
3. 水が供給された各畝間水路エンティティから、**設置方向に対して直交方向にnブロック** の畑（soil/wetSoil）に水が供給される
4. 現時点では **m=16, n=3** とする
5. 水が供給されている畝間水路は、水が入っている見た目のスプライトで表示される

**水門は伝播チェーンの一部:**

- 水門エンティティも畝間水路と同じ水の伝播チェーンに参加する
- 水門が「開」→ 水門を通過して後続の畝間水路に水が伝播する
- 水門が「閉」→ 水門で伝播が遮断され、後続の畝間水路に水が届かない
- 水門は「水を通すか止めるかを切り替えられる、伝播チェーンの特殊ノード」

### 5.3 畝間水路の方向と散水範囲

畝間水路は**設置方向（横向き/縦向き）**を持つ:

- 横向きの畝間水路 → 上下nブロックに散水
- 縦向きの畝間水路 → 左右nブロックに散水

設置方向はボクセルの方向ビットに保持する（64bit化済みのため余裕あり）。設置時にプレイヤーの操作で方向を指定する（具体的なUI/UXは要検討）。

**設計意図:**

- 方向を持たせることで畑レイアウトの自由度が上がる
- 方向なしの場合、畝間水路は常に4方向に散水するため配置の工夫が減る
- 導水路の伸びる方向と畝間水路の散水方向を直交させる、という直感的なレイアウトが可能

### 5.4 スプライト種別ごとの散水ルール

畝間水路は接続状態に応じて複数のスプライト種別を持つ（doc/09_RESOURCE.md 参照）。**散水するのは直線・端末のみ** — 曲がりや分岐は導水専用として扱う。

また、畝間水路の見た目は「接続形状」と「現在水が供給されているかどうか」の組み合わせで決まる。水が供給されていない場合は通常スプライト、水が供給されている場合は水入りスプライトを表示する。

| スプライト種別 | 散水 | 散水方向 |
|---|---|---|
| 直線・縦 | あり | 左右nブロック |
| 直線・横 | あり | 上下nブロック |
| 端末・上向き / 下向き | あり | 左右nブロック（縦軸） |
| 端末・左向き / 右向き | あり | 上下nブロック（横軸） |
| 90度曲がり（L字） | なし | — |
| T字 | なし | — |
| 十字 | なし | — |

**設計意図:**

- **物理的に自然**: 水路の曲がり・分岐は水が流れ抜ける部分。畝間への浸透は直線部分のほうが自然
- **散水アルゴリズムの簡略化**: 各畝間水路タイルについて、スプライト種別を見るだけで散水の有無が決まる
- **プレイヤーの設計の面白み**: 畑のレイアウトを考えるとき、直線部分を畑に隣接させる意識が必要になる。現実の灌漑設計と同じ思考が要求される

※ 石組み導水路は散水機能を持たない（純粋な導水路）。畝間水路にのみ散水ルールが適用される。

### 5.5 接続スプライトの選択アルゴリズム

畝間水路・石組み導水路は、隣接する4方向のタイルに応じてスプライトを自動選択する。プレイヤーは縦/横の初期方向を指定して配置するのみで、曲がり・分岐への変形はシステムが自動で行う。

#### 5.5.1 「接続している」の定義

チャンネルタイル `T`（畝間水路 or 石組み導水路）において、方向 `D ∈ {上, 下, 左, 右}` の隣タイルが**接続している**とみなす条件:

1. 同種または異種のチャンネルタイル（畝間水路 ⇔ 石組み導水路は相互接続する）
2. 水タイル（water / waterSource / flowedWater）
3. 水門タイルで、**水門の向きが方向Dの軸と一致している**
   - 横向き水門は左右のみ接続（上下には接続しない）
   - 縦向き水門は上下のみ接続（左右には接続しない）

#### 5.5.2 スプライト選択ロジック

接続の数とパターンからスプライトを決定する:

| 接続数 | 接続パターン | スプライト |
|---|---|---|
| 0 | — | プレイヤー指定の方向で直線（縦 or 横） |
| 1 | {上} | 端末（水路が上に続く → 下が行き止まり = 下向き端末） |
| 1 | {下} | 端末（水路が下に続く → 上向き端末） |
| 1 | {左} | 端末（水路が左に続く → 右向き端末） |
| 1 | {右} | 端末（水路が右に続く → 左向き端末） |
| 2 | {上, 下} | 直線・縦 |
| 2 | {左, 右} | 直線・横 |
| 2 | {上, 右} | 90度・左下（上辺と右辺が接続するL字） |
| 2 | {上, 左} | 90度・右下 |
| 2 | {下, 右} | 90度・左上 |
| 2 | {下, 左} | 90度・右上 |
| 3 | missing 下 | T字・上向き枝 |
| 3 | missing 上 | T字・下向き枝 |
| 3 | missing 右 | T字・左向き枝 |
| 3 | missing 左 | T字・右向き枝 |
| 4 | {上, 下, 左, 右} | 十字 |

※ 「端末の向き」は「行き止まり側の向き」で命名する（doc/09_RESOURCE.md の端末定義と一致）。

#### 5.5.3 再計算のトリガー

- 新しい畝間水路/導水路/水門が設置されたとき → **新タイル + 周囲4マス**を再計算
- 畝間水路/導水路/水門が撤去されたとき → **撤去タイルの周囲4マス**を再計算
- 水タイル（water/waterSource/flowedWater）が変化したとき → **周囲4マスの水路**を再計算
- 水門の**開閉状態変更時**は再計算不要（接続性は変わらず、水門自身のスプライトだけが切り替わる）

#### 5.5.4 計算量

- 1回の更新で最大5マス（配置タイル + 周囲4マス）の局所処理で完結
- 水路全体のグローバル再計算は不要 — 各タイルは純粋に**自身の4近傍**だけ見れば決まる
- スプライト選択と水の伝播計算は別レイヤ（スプライトは接続形状、水の伝播はBFSで別途計算）

### 5.6 水の伝播の計算量

- 畝間水路エンティティのBFS探索のみで計算が完結する
- 水門の開閉時に再計算が必要だが、畝間水路の数は全タイル数に比べて十分少ない
- 水が供給されている畝間水路の周囲nブロックのみが散水対象になる
- 散水判定時は各畝間水路のスプライト種別を参照し、L字・T字・十字は散水対象から除外する
- 現時点では、水のやりすぎによる悪影響は導入しない

## 6. リソース: 粘土と焼きレンガ

### 6.1 粘土の位置づけ

- 粘土は**汎用的な川辺リソース**として設計する
- 用途: 焼きレンガ（導水路）、防水層、その他の建材
- 川辺の土地にランダムで粘土が混在する

### 6.2 粘土の供給

- 耕していない川辺の土地に、時間経過で粘土が再生成される
- 土地を耕して畑にすると、そのタイルでは粘土は発生しない
- **川辺の土地の用途競合**:
  - 畑にする（農業用）
  - 粘土採取エリアとして残す（建材用）
  - 導水路の経路にする（水利用）
- この競合はプレイヤーの判断を生む良いリソース配分の問題

### 6.3 粘土→焼きレンガの加工

- 粘土を焼窯で焼いてレンガにする
- レンガを使って石組み導水路を設置する
- 焼窯自体は最初から作成可能（スキルツリーの制限はない、リソースの制約のみ）
- **レシピ: 炉 + 粘土 + 木材 → 焼きレンガ**（炭は不要。レンガの焼成温度900〜1100°Cは木材の燃焼で到達可能）

### 6.4 川辺の土地のゾーニング

実際の川辺集落の土地利用に近い体験が自然に生まれる:

```
  川川川川川川川川川川川  ← 川（水源）
  粘粘畑畑畑畑畑畑粘粘  ← 一部を粘土採取用に残す
  畑畑畑畑畑畑畑畑畑畑  ← 農地
  [導水路]===[水門]===  ← 導水路と水門
  畑畑畑畑畑畑畑畑畑畑  ← 農地（畝間水路から灌漑）
  畑畑畑畑畑畑畑畑畑畑
```
